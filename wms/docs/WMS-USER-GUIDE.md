# WMS LOGOFF — руководство пользователя

## 1. Назначение системы

WMS LOGOFF ведёт клиентов, товары, штрихкоды и КИЗы, короба и паллеты, приёмку, остатки, перемещения, заявки, инвентаризацию, FBS, биллинг, документы и клиентский кабинет. Каждое физическое действие должно оставлять цифровой след: кто, когда, с каким товаром и в каком коробе его выполнил.

## 2. Роли

| Роль | Основное назначение |
|---|---|
| OWNER | Закрытый контур владельца, системные настройки и аудит |
| ADMIN | Операционное администрирование WMS |
| MANAGER | Решения по заявкам, расхождениям и начислениям |
| OPERATOR | Приёмка, перемещения, сборка и проверка |
| TSD | Сценарии сканирования на терминале |
| CLIENT | Только разрешённые данные своего клиента |

Плитка в интерфейсе и право выполнить действие — разные уровни защиты. Скрытая плитка не выдаёт право, а показанная плитка не отменяет серверную проверку роли и клиента.

## 3. Начало работы

1. Войдите по адресу WMS.
2. После входа открывается «Обзор».
3. Проверьте имя пользователя и доступные роли справа вверху.
4. Выберите рабочую плитку.
5. Перед операцией с товаром всегда выберите правильного клиента.

Если вход не работает, не повторяйте пароль много раз. Запишите время ошибки и передайте администратору. При HTTP 502 используйте порядок из `WMS-TROUBLESHOOTING.md`.

## 4. Справочники

### Клиент

В карточке клиента хранятся юридические реквизиты, режим хранения, тарифы, менеджер, параметры FBS, подключение маркетплейса и видимость клиентских функций. Клиентский пользователь получает доступ только через назначенный scope.

### Товар и SKU

Карточка SKU содержит артикул, наименование, цвет, размер, штрихкоды, габариты и литраж. Основной штрихкод должен однозначно определять товар внутри клиента. Если литраж изменён вручную, импорт из API не должен перезаписывать ручное значение.

### Переклейка

Соответствие используется только если целевого товара нет в доступном остатке. Сборщику показывается исходный товар и короба, где он лежит. После переклейки сканируется целевой ШК.

## 5. Приёмка

### Приёмка в коробах

1. Выберите клиента и начните приёмку.
2. Отсканируйте уникальный номер короба.
3. Сканируйте только ШК товара в поле ШК.
4. Если товар маркируемый, следом сканируйте КИЗ.
5. Проверьте счётчики текущего короба.
6. Закройте короб и затем приёмку.

Повторный номер короба запрещён. КИЗ нельзя использовать повторно. При смене даты в номере короба система отделяет новую партию от предыдущей.

### Приёмка без коробов

Если у клиента включён режим «без коробов», после открытия приёмки сразу сканируется товар. Система принимает ШК без требования физического короба и создаёт корректный безкоробочный остаток.

### Онлайн-приёмка

Экран показывает только текущую партию, её короба, количество и КИЗы. КИЗы одной позиции сворачиваются, чтобы не раздувать страницу. После завершения партии сформируйте файл приёмки и проверьте, что в него вошли все короба нужной даты.

## 6. Остатки, короба и перемещения

Поиск короба открывает его состав, размещение, движения и историю. В рабочем списке показываются активные короба с положительным наполнением; пустые и удалённые ищутся в архиве.

При частичном перемещении:

1. Откройте короб.
2. Выберите товар и количество.
3. Укажите новый или существующий целевой короб.
4. Подтвердите перемещение.
5. Если исходный короб опустел, он переводится в архив.

Нельзя блокировать целый короб ради одной заявки: резервируются только требуемые единицы.

## 7. Зоны хранения и паллет-сорт

Зона — произвольно названная складская область. В зоне размещаются паллеты, на паллете — короба.

Сборка паллета на ТСД:

1. Откройте «Сборка паллетов».
2. Отсканируйте ШК паллета.
3. Сканируйте стоящие на нём короба.
4. Проверьте количество.
5. Нажмите «Следующий паллет» или завершите работу.

При поиске для FBS/FBO WMS сначала показывает короб, затем зону и паллет. Если на том же паллете есть другие требуемые короба, система сообщает об этом до перехода дальше.

## 8. Заявки

Заявки нумеруются. Основные статусы: новая, в работе, на сборке, сдана, отменена. Сданные и отменённые заявки уходят в архив.

Для ручной заявки:

1. Откройте подбор коробов.
2. Для каждой позиции выберите предложенный короб либо «Без короба».
3. Если WMS сообщает нехватку, укажите фактический короб или выберите доступный из подсказки.
4. Переведите заявку в работу и соберите.
5. Перед статусом «Сдано» проверьте фактическое количество.

Закрытие списывает только выбранные количества. Недостающие позиции можно перенести в новую заявку.

## 9. Инвентаризация

### Полная

На время полной инвентаризации блокируются движения товара. После завершения менеджер принимает решения по расхождениям и снимает блокировку.

### Частичная

Движения продолжаются. Сканируется короб, затем фактическое содержимое по ШК. Уже проверенный короб нельзя проверить повторно без разрешения администратора.

### Проверка содержимого

Система сравнивает ожидаемое и фактическое:

- недостача;
- излишек;
- неизвестный ШК;
- совпадение.

В результатах всегда видны номер короба, наименование, артикул, ШК и количество. Пустые сессии удаляются. Успешные проверки сворачиваются в одну строку, а расхождения располагаются выше.

### Актуализация

Менеджер видит все проверки, включая успешные. Возможные решения: актуализировать, удалить, принять как есть или оставить без изменения. Решение и автор сохраняются в истории.

## 10. FBS Wildberries

### Подготовка

1. В карточке клиента подключите API WB и выберите склад WB.
2. Запустите синхронизацию.
3. Проверьте активные и отменённые заказы.
4. Выберите направление сдачи: ПВЗ или СЦ.
5. Выберите нужное количество невыбранных заказов.
6. Создайте WMS-заявку.

Заказы, уже находящиеся в заявке, повторно массово не выбираются. В таблице виден номер WMS-заявки и короб, где лежит товар.

### Сборка на ТСД

1. Откройте «Сборка FBS».
2. Выберите конкретную заявку.
3. Отсканируйте предложенный или любой действительно нужный короб.
4. WMS показывает, сколько позиций нужно взять из короба.
5. Отсканируйте ШК товара.
6. Для маркируемого товара отсканируйте КИЗ.
7. После проверки над номером заявки появляется WB-стикер с крупными четырьмя цифрами.
8. Наклейте именно этот стикер.
9. Проверьте счётчик оставшихся товаров.

Если КИЗ физически верный, но ранее принимался без КИЗа, разрешённый сценарий привязывает его к фактической единице и сохраняет в заявке. Действие можно отменить до завершения.

### Упаковка

Для ПВЗ товары одной поставки распределяются по грузоместам по правилам WB. Для СЦ сначала сканируется физический короб, затем ШК упаковываемых товаров. WMS хранит связь:

`поставка → грузоместо → физический короб → заказ → товар → КИЗ → WB-стикер`.

Перед отправкой в WB система проверяет, все ли заказы собраны, нет ли отмен и незакрытых позиций.

### После отгрузки

Отгруженные заказы переходят из активных в отгруженные, затем участвуют в расчёте обработки FBS и архивируются после завершения. Группа одной поставки выделяется единым блоком.

## 11. FBS-остатки для продажи

В продажу отправляются только товары с положительным физическим остатком WMS. Можно задать количество для каждого SKU или общее ограничение для выбранных товаров. Нельзя опубликовать больше доступного остатка; строка подсвечивается красным.

Кнопка обновления резервов пересчитывает активные заказы и удаляет устаревшие резервы. Статус «продавать / не продавать» управляет публикацией, но не создаёт товарную карточку WB.

## 12. Биллинг

Биллинг строится из фактических операций, тарифов клиента и ручных начислений. Администратор может фильтровать счета по клиенту. Клиент видит только свои счета.

Для FBS применяются:

- фиксированная цена «FBS под ключ», если включена;
- иначе настроенный калькулятор обработки, логистики, коробов и дополнительных услуг.

Паллеты начисляются только если включены в настройках клиента. Сданная FBS-заявка формирует строку «Обработка заказов по FBS» с количеством и итоговой суммой. Оплаченные счета зелёные, доступно скачивание акта.

Аванс клиента уменьшает общий долг, но не изменяет сумму уже выставленных счетов.

## 13. Договоры

Администратор выбирает клиента и создаёт PDF по шаблону. В договор попадают реквизиты, адрес WMS, логин и пароль, подпись и печать исполнителя. Клиент может скачать договор, загрузить подписанный экземпляр и дополнительные соглашения.

Пароль в договоре хранится открыто по бизнес-требованию, поэтому доступ к файлам должен быть строго ограничен клиентским scope.

## 14. Клиентский кабинет и приложение WMS

Клиент видит только разрешённые плитки и собственные данные. В приложении работают светлая и тёмная темы, уведомления, карточки товара и короба, заявки, счета, FBS и аналитика. «Прочитать все» должно обновлять уведомления одной операцией без аварийного закрытия приложения.

Предварительное хранение показывает денежную сумму, а не литры. Оплаченные счета и сданные заявки отображаются зелёным.

## 15. Завершение смены

Перед выходом:

1. Закройте открытые короба приёмки.
2. Завершите или отложите активные задания ТСД.
3. Убедитесь, что FBS-упаковка сохранена.
4. Сообщите менеджеру о расхождениях.
5. Выйдите из учётной записи.
