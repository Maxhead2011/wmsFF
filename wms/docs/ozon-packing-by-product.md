# Упаковка Ozon по товару

Опубликовано в APK227: [отмена последней единицы и проверка ШК направления](fbo-packing-undo.md).

Статус: опубликовано 10.10.2026, PR549, LOGOFF APK226. Проданная WMS не изменяется.

В LOGOFF экран упаковки предлагает «По направлению» (прежний порядок) и «По товару».
Новый режим показывается только при marketplace=OZON и серверной capability packingByProductSupported.
Флаг WMS_OZON_PACK_BY_PRODUCT_ENABLED по умолчанию выключен; включать только в нашей WMS после выпуска API и APK.

## Последовательность

1. Отсканировать ШК уже отобранного товара.
2. Если товар маркирован — отсканировать КИЗ.
3. ТСД показывает направление и открытый короб. При отсутствии открытого короба предлагает новый пустой короб для этого направления.
4. Отсканировать указанный короб. Лишь теперь отправляется PACK_PRODUCT.
5. После подтверждения сервера можно сканировать следующий товар.

Приоритет: направления с недостающим товаром и открытым коробом, далее порядок направлений файла заявки. Из нескольких коробов одного направления выбирается первый по коду. Закрытые короба и полностью упакованные позиции исключены.

## Целостность

Подсказки приходят в обычном плане без отдельного запроса остатков при сканировании ШК. Это рекомендации, а не резерв направления.
PACK_PRODUCT использует существующую блокировку заявки и Serializable-транзакцию. Проверяются принадлежность короба, незакрытость, точная отобранная единица, КИЗ и квота направления. Создание нового короба и перемещение единицы атомарны. Ошибка откатывает оба действия.
При занятии последней квоты другим сборщиком сервер отклоняет команду; ТСД обновляет план, сохраняет товар и требует сканировать короб новой подсказки. Автоматического вложения в другое направление нет.
Неизвестный результат сохраняет исходную команду и operationId. Повтор и перезапуск не меняют её. Подтверждение очищает команду и сохранённый товар одним локальным commit.
Переключение режима разрешено только между товарами. «Отложить товар» не создаёт движений. При выключении capability сохранённый товар нельзя случайно отправить старой командой.

## Файлы

- FboTwoStageScreen.java: выбор режима, подсказка, сканирование, подтверждение и восстановление.
- FboScanState.java: checkpoint и неизменная повторная команда.
- TsdFboPlan.java: capability и рекомендации по SKU.
- ozon-packing-suggestion.ts: рекомендации и проверка нового/существующего короба.
- fbo-two-stage.service.ts и dto/fbo-action.dto.ts: дополнительная команда и поля плана.
- scripts/releases/ozon-packing-product-20261010/patch.cjs: только три модуля текущего runtime; старые обработчики сохраняются.

## Проверки и ограничения

API: тесты реально вызывают сервис; транзакции и данные в fixture имитируются с откатом и сериализацией. Проверяются конкурирующие команды последней квоты, повтор операции, неверный/повторный КИЗ, закрытый/чужой короб и выключенный флаг. Те же тесты запускаются с OZON_PRODUCT_RUNTIME на подготовленном runtime.
Android: реальные Robolectric-компоненты проверяют порядок ШК → КИЗ → короб, смену подсказки, запрет неверного короба, отсутствие ранних запросов и повтор после потери ответа/перезапуска. Другие flavor сохраняют старый экран.
Тест `scripts/tests/ozon-product-postgres.cjs` прошёл на отдельном локальном PostgreSQL: два конкурентных подключения к последней квоте, повтор операции и полный откат короба/остатка/движений при сбое аудита. Старый runtime этот тест не проходит. Проверка физическими ТСД остаётся после установки. Производственные данные при разработке не изменялись.

## Выпуск и откат

База до выпуска: 2026-10-10-ozon-direction-items, sourceParityVerified=false.
Перед выпуском повторно сверить API/web image IDs. Materialize в новый каталог, применить patch.cjs, проверить check-candidate: modules/tsd/fbo-two-stage.service.js, modules/tsd/dto/fbo-action.dto.js, modules/tsd/ozon-packing-suggestion.js.
Не заменять сервер полной сборкой исходников. Подготовлена отдельная версия LOGOFF APK226 `0.1.226-ozon-packing-product`. Выпуск: stage.py → PR → publish.py; точные хеши, подпись, прежние флаги и остальные контейнеры проверяются автоматически.
Для отката выключить новый флаг: новые вложения по товару запрещаются, прежний режим доступен. Незавершённые команды с неизвестным результатом сначала сверить/повторить с тем же operationId, не удалять их вручную. Данные упаковки используются общие, миграция БД не нужна.
