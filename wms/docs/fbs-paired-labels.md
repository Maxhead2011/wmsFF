# Парная печать FBS WB/Ozon для товаров без КИЗ

Обычная кнопка скачивания стикеров выбранных заказов раньше возвращала только
официальные этикетки маркетплейса. Теперь для немаркированного товара любого клиента
PDF содержит сначала этикетку товара
58×40 мм (ШК, заказ, название, артикул, количество), затем официальный стикер заказа.
Для четырёх однопозиционных заказов получается восемь страниц.

## Границы

- Новый режим включается только для нашей ВМС флагом
  `WMS_FBS_UNMARKED_PAIRED_LABELS_ENABLED=true`. Он не читает настройки ткани клиента.
  Бушкова, Хрупова, Баландин и другие клиенты получают пары для товаров без КИЗ.
  Подключение нужного маркетплейса и однозначная карточка товара по-прежнему обязательны.
- При выключенном новом флаге сохраняется поведение PR904: пары только при старом
  флаге ткани и существующем opt-in клиента. Это обеспечивает обратную совместимость
  и не меняет проданную ВМС, куда новый флаг/образ не публикуются.
- Решение принимается по каждой позиции, а не клиенту целиком. Требование КИЗ из
  карточки и требование маркировки WB/Ozon исключают дополнительную товарную этикетку.
  Смешанный заказ сохраняет официальный стикер и этикетки немаркированных позиций.
  Выбор только маркированных товаров остаётся на прежнем пути официальных стикеров.
- Авторизация клиента проверяется до нового обработчика. Кабинеты и SKU ограничены
  выбранным клиентом; одинаковые номера заказов разных кабинетов не объединяются.
- ШК берётся из пересечения данных заказа и каталога. ID товара не используется
  вместо ШК. При отсутствующей/неоднозначной привязке или недоступном официальном
  стикере выдаётся ошибка, а не неполная пара.
- Для карточки склада из WB, у которой нет идентификатора Ozon, читаются штрихкоды
  через `/v3/product/info/list` только выбранных SKU. Принимается лишь совпадение
  SKU и offer_id; затем требуется единственное совпадение ШК в каталоге клиента.
  Карточки и связи в БД не изменяются.
- WB: сохраняются официальные PNG/PDF, разделение cross-border и пакеты до 100 заказов.
- Ozon: отдельный запрос PDF для каждого отправления сохраняет соответствие страниц.
  Несколько товаров в отправлении дают несколько товарных этикеток перед официальной.
  Если Ozon ещё не разрешил этикетку, скачивание не переводит заказ в сборку/доставку.
- Печать не списывает метры, не создаёт приход, не меняет этап сборки и не передаёт
  заказы в доставку. Распознавание цвета рулона не определяет возможность печати.
- Учёт ткани, проданная ВМС, ТСД, Windows-агент и интерфейс не меняются.

## Расширение на немаркированные товары 08.11.2026

`fix/fbs-unmarked-paired-labels` → `feature/la_panthera`: изменён только helper
`fbs-paired-labels.ts`, существующий вызов в сервисе сохранён. Экспортное имя
`fabricPairedLabels` оставлено для совместимости с опубликованным runtime.
Скрипты `scripts/releases/fbs-unmarked-labels-20261108/` создают точный API1 overlay
от PR904; при публикации меняется только новый флаг, остальные переменные сверяются.

21 тест helper (10 новых): клиент без настройки ткани при выключенном учёте рулонов,
WB/Ozon с КИЗ и без, смешанные заказы и приоритет требований маркетплейса. Четыре
сценария независимости от ткани воспроизведены до исправления; отдельный тест
карточки WB без связи Ozon воспроизвёл ошибку до добавления точного поиска ШК.
Compiled runtime: старый код даёт четыре
страницы обычному клиенту, новый — восемь; проверены выключение нового флага,
сохранение старого режима ткани и запрет доступа до обращений к маркетплейсу.

Ответ HTTP429 при выдаче этикетки Ozon остаётся внешним препятствием: этот выпуск
меняет область парной печати и не обещает устранение ограничения API Ozon.

## Код и выпуск

`marketplace-connections/fbs-paired-labels.ts` вызывается из
`MarketplaceConnectionsService.getFbsOrderStickersPdf`. Публичный маршрут прежний:
`POST /api/v1/marketplace-connections/fbs/orders/stickers.pdf`.

Выпуск только в нашу ВМС через `fix/fbs-paired-download-2781` → `feature/la_panthera`.
Скрипты `scripts/releases/fbs-paired-labels-20261108/` добавляют точный двухфайловый
overlay к проверенному runtime PR902. Остальные байты сервиса и все остальные модули
сохраняются. Полная сборка исходников не является заменой production: source parity false.
Перед публикацией сверяются текущие образы, объединённый PR, точные хеши кандидата
и успешный запуск именно его образа на изолированной тестовой PostgreSQL.
При неудачном health/hash/environment-контроле возвращается предыдущий образ.
