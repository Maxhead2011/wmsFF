# Закрытие расчётного периода и исправления

Опубликовано в нашей WMS 04.10.2026 через [PR472](https://github.com/Maxhead2011/wmsFF/pull/472).
Merge `5ede9712e308f7d636d0ce807e4b0e7e9f4e08b0`; отдельный флаг включён только нашей WMS.

В нашей WMS включается `WMS_BILLING_PERIOD_CLOSE_ENABLED=true` вместе с
`WMS_BILLING_SETTLEMENTS_ENABLED=true`. Проданное окружение не включать.
Перед включением применить миграцию `20261003220000_billing_period_close`.

«Биллинг → Клиенты и расчёты»: выбрать клиента, даты услуг и активный филиал.
Предварительная проверка запрещает закрытие при черновиках, невыставленных услугах,
неоднозначных источниках, ошибках детализации и пересечении закрытых периодов.
Основание обязательно. Закрытие не означает оплату: фактические приходы доступны
после него, неоплаченные суммы остаются долгом.

Документ исправления имеет исходный счёт, сумму со знаком, причину, автора и дату.
Положительная сумма доначисляет, отрицательная уменьшает стоимость. Оригинальные
строки, сумма и приходы не переписываются. Итог не может быть отрицательным.
Уменьшение ниже уже внесённой оплаты показывает отдельную переплату; это не новый
приход, не аванс и не автоматический возврат.

Позднюю работу допускается сформировать отдельным черновиком. За закрытый период
он выставляется через вид исправления «Поздняя работа» с обязательной причиной.
Повтор запроса использует один operationKey; изменённые суммы требуют нового
предпросмотра. Проверки прав клиента, филиала и demo-окружения выполняются снова,
включая повтор сохранённой операции.

Защита БД фиксирует счета/строки, включённые в закрытие или исправление. Данные
закрытия и исправлений неизменяемы; обратное исправление — новый документ.
Платёжные суммы и статусы принимают прежние обработчики с учётом новой итоговой
стоимости. Финансовые записи выполняются под существующей общей блокировкой.

Проверки: unit suites API/web, browser fixture
`apps/web/test/billing-period-close.browser.cjs`, изолированный PostgreSQL
`scripts/test-billing-period-close-postgres.py`. PostgreSQL runner ожидает каталог
с `fixture.sql`, `migration.sql`, `assert.sql` (соответствующие файлы из api/test и
миграции); второй аргумент — закреплённый образ PostgreSQL. Новая БД без сети,
портов и томов; реальные бизнес-данные не используются.

Публикация выполнена по подтверждению Константина точечной сборкой из закреплённого
серверного runtime; соответствие всех исходников production не доказано.
Полный source build для выпуска запрещён. Отключение флага после
появления корректировок скрывает их влияние на долг, поэтому это не допустимый
откат после использования функции. Для такого случая нужен совместимый runtime,
который продолжает учитывать сохранённые документы исправления.
