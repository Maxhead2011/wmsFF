# Проверка дублей КИЗ у клиента

Изменение относится к нашей WMS. Серверный флаг `WMS_KIZ_CLIENT_GUARD_ENABLED=true`, веб-флаг `VITE_KIZ_CLIENT_GUARD_ENABLED=true`, интерфейс ТСД только LOGOFF с серверной capability. В проданную WMS флаги и артефакты не переносятся.

## Приёмка

Идентификатор — GTIN и серийный номер с сохранением регистра. Полный код, короткая идентичность и поддерживаемые обозначения GS проверяются как одна единица. Проверка охватывает всю историю одного клиента, включая другие филиалы. Подробности чужого филиала скрываются.

Дубль не увеличивает остаток. ТСД и онлайн-приёмка показывают красный экран «ОТЛОЖИТЕ ТОВАР», первоначальный короб, товар, дату доказанной приёмки и текущее состояние. При недостаточной истории дата не выдумывается. Оператор может передать обращение в «КИЗ → Проверки КИЗ» или явно перейти к другому товару.

Одинаковый подтверждённый запрос возвращает `ALREADY_APPLIED`. При позднем отказе синхронизации сохраняется структурированная причина. Повтор чужой операции не раскрывает её детали и не перезаписывает запись. «Принять с ошибкой», Excel и исправление строки приёмки проходят ту же проверку; администраторское принятие с ошибкой использует общую транзакцию.

## Повторная отгрузка

Ранее подтверждённая отгрузка требует решения администратора в существующем разделе проверок КИЗ. Разрешение привязано к клиенту, единице, заявке, заданию и исходному коробу. После отгрузки оно погашается. Старое разрешение без нового контекста не даёт автоматического допуска.

Проверяются сканирование FBS, SOS WB, восстановление/пересканирование, завершение FBS, FBO в коробах и без короба, ручная упаковка, ручное закрытие заявки и списание после печати. Первая обычная отгрузка тоже получает внутреннюю блокировку единицы, чтобы две заявки не забрали один КИЗ одновременно. Она не является решением администратора и не появляется как обращение на разбор.

`SHIPPING` сам по себе означает подготовку к отгрузке и не считается доказательством прошлого списания. Основания проверки — история отгрузок, завершённые FBO-единицы, использованное разрешение и подтверждённое внешнее свидетельство. Прежняя история сохраняется; изменение старой привязки после решения администратора записывается в аудит.

## Реализация и выпуск

- `common/kiz-client-registry.ts`: общая блокировка клиента/идентичности, история первоначальной регистрации, поиск и диагностика приёмки.
- `common/kiz-client-review.ts`: привязка единицы, контекстное разрешение, проверка и погашение, очередь администратора.
- `stock-operations`, `imports`, `warehouse`, `tsd-receipt/review/sync/operation-log`: все входы прихода и повтор запроса.
- `marketplace-connections`, `fbo-two-stage`, `fbo-unboxed-picking`, `wb-order-stock-lifecycle`: сборка и отгрузка.
- Android `ReceiptKizWarningView`, `ReceiptKizIdentity`, `MainActivity`, sync DTO; веб `ReceiptDuplicateNotice`, `OnlineReceiptPanel`, `KizReviewQueuePanel/Card`.

Добавляется только `KizClientRegistry` и пять поисковых индексов. Индексы создаются `CONCURRENTLY`. Backfill заполняет историю регистрации по доказательствам, не корректирует остатки и не объединяет старые ProductMark. Записи без доказанной даты имеют `LEGACY_UNKNOWN`.

Выпуск: `scripts/releases/kiz-client-guard-20261029/`. API — ограниченный overlay опубликованного `b99d8daf…`; веб — overlay PR761 плюс APK/озвучка PR763. `sourceParityVerified=false`; полная пересборка устаревших исходников для production запрещена. Изменяются только три функции основного веб-модуля; остальные байты сохраняются. Конфликт номера APK согласован с Катериной: LOGOFF244 сохраняет озвучку Софии из243.

Перед переключением: проверка актуальных image ID, PR, полного тестового набора, фактических runtime-модулей, отдельного PostgreSQL и полноценного запуска Nest. После переключения — флаг контейнера, health, публичные хеши и APK. Откат возвращает образы; добавочная история остаётся. Рабочие остатки при выпуске не переписываются.

## Проверки

Автотесты: `kiz-client-registry`, `kiz-client-receipt`, `kiz-client-review`, `kiz-receipt-conflict-transport`, `kiz-shipment-gates`; API transport веба и красный экран; Android identity/view/sync и все flavor suites. Runtime scripts проверяют реальные опубликованные модули; PostgreSQL — конкурентный приход, повтор, общий claim/receipt lock и повторный заказ той же заявки. `test-isolated.py` запускает целый API без доступа к внешним сервисам.

Исторический тест печати `kiz-duplicate.integration.spec.ts` запускается отдельно только с собственной БД `KIZ_DUPLICATE_TEST_DATABASE_URL`; его отсутствие не заменяет новые обязательные PostgreSQL-проверки.
