# Пауза WB при проверке поставок ФБО
Подготовлено, не опубликовано. WMS_WB_FBO_REQUEST_PAUSE включается только в нашей WMS; без него сохраняется прежний путь.

WbFboSupplyService.remote использует wbFboPausedFetch. Пауза и короткая аренда запроса записываются в SystemSetting, поэтому несколько заявок, ручные/фоновые проверки и экземпляры API разделяют ограничение. Ключ на клиента WMS консервативно объединяет его подключения WB. Между HTTP-запросами транзакция не удерживается.

HTTP429: максимальный срок Retry-After (секунды или HTTP-дата), X-Ratelimit-Retry и X-Ratelimit-Reset, минимум 60 секунд без корректного заголовка. Успешный ответ с нулевым остатком лимита также задаёт паузу. Остальные ответы имеют интервал 2 секунды, сетевая ошибка — 10 секунд. Во время паузы запрос в WB не отправляется, сообщение содержит время МСК и оставшиеся секунды. После паузы доступна обычная следующая проверка; автоматическая повторная отправка из этого ограничителя не выполняется.

Проверки: test/wb-fbo-request-pause.spec.ts — воспроизведение повторной отправки после 429 до исправления, перезапуск сервиса, несколько поставок, конкуренция, разные клиенты, даты и длительные паузы WB, истечение паузы, ошибка сети, выключенный флаг. Услуги, биллинг, состав и статусы заявок ограничитель не изменяет.

Проверено 05.11.2026: API 4314 passed / 3 skipped, web 594 / 2; интеграционные 53 passed / 106 skipped (нет настроенных отдельных тестовых БД для этих наборов). Новый сценарий PostgreSQL пройден на исходнике и скомпилированном модуле. TypeScript API проверен. Регрессия до исправления воспроизведена: второй вызов remote после HTTP429 ошибочно отправлял второй HTTP-запрос.
