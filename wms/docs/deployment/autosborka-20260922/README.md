# Автосборка FBS и плитки администрирования

Вход: Администрирование → Автосборка → клиент → кабинет. Для WB и Ozon отдельные расписания; новые настройки выключены. Время Москва (UTC+3), список запусков или заполнение интервала. Склады WB берутся из маршрутизации; Ozon использует склад исполнения кабинета. Неизвестные и исключённые направления пропускаются.

Проверки: только активные заказы с найденным товаром, без заявки, физического задания/резерва или поставки. Для WB создаётся заявка WMS, затем штатная поставка. При ошибке WB заявка сохраняется для ручного продолжения. Для Ozon создаётся только заявка, подтверждение собранного заказа остаётся ручным.

Флаг WMS_AUTO_ASSEMBLY_ENABLED по умолчанию выключен. Конфигурации и история сохраняются в SystemSetting; изменения расписания пишутся в аудит. Уникальный ключ временного слота предотвращает повторный запуск, сравнение версии предотвращает потерю параллельных изменений. PostgreSQL advisory lock клиента общий для ручного и автоматического создания/сборки, другие клиенты не блокируются. Повторная проверка связей перед созданием выполняется в транзакции. При незавершённом запуске после аварии история остаётся RUNNING: результат не подтверждён, повторной автоматической отправки того же слота нет. Просроченный слот выполняется один раз после восстановления, последующие прошлые интервалы не воспроизводятся.

Рабочая ветка не является точной копией сервера. По разрешению пользователя новые обёртки перенесены поверх текущего production, сохранены fast assembly/request creation, read-only operational fetch и прочие новые проверки. Точный production.patch приложен отдельно; для публикации запрещена замена всего серверного сервиса локальной старой копией.

Тесты: auto-assembly.spec.ts (расписание, конкуренция, исключения ручной сборки, Ozon, предпросмотр, ошибки WB и гонка таймеров), AdministrationNavigation.spec.tsx; полный набор API/web и TypeScript, сравнение production baseline/candidate перед выпуском.
