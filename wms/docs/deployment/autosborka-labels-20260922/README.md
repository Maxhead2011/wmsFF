# Автосборка: название склада и автор WMS

Для нашей ВМС. База: feature/administration-tiles-autosborka, PR в feature/billing-period-register-20260910.

- createFbsRequestUnlocked восстанавливает имя склада из маршрутизации по connectionId + warehouseId, когда быстрый ответ WB не содержит имени. Контекст автосборки передаёт имя из предварительной группировки.
- Автор автоматической заявки — отдельная заблокированная запись WMS без ролей и пригодного для входа пароля. Исполнение и проверка прав продолжаются от настоящего администратора. Автор события создания и связей заказов сохраняется; событие явно указывает автосборку WMS.
- Ручное создание не использует системного автора. Определение автора WMS и обращение к маршрутизации ограничены WMS_AUTO_ASSEMBLY_ENABLED.
- В production уже есть строка автора: production.patch сохраняет её и все более новые проверки быстрой сборки. Локальная ветка добавляет отсутствующую строку. Не заменять сервер целиком файлом из ветки.
- repair-request-labels.cjs по умолчанию строит read-only план. APPLY_REQUEST_LABELS=true исправляет только подписи и автора подтверждённых журналом автозаявок; CAS по updatedAt и AuditLog защищают от конкурентных изменений. Состав, статусы, остатки, права и настройки расписаний не меняются.

Проверки: API 2303 passed / 12 skipped, web 229 passed, обе проверки TypeScript успешны. Два интеграционных сценария воспроизводят ошибку на прежнем сервисе. Production baseline 1257 passed / 197 failed; candidate 1278 passed / те же 197 failed (новых падений нет). Целевые 21 тест и сборка интерфейса успешны. Существующие production-падения не относятся к этому исправлению.
