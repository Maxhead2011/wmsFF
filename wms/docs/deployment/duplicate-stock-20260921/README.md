# Доли дублей — интеграция с действующим сервером

Базовые образы нашей ВМС:
- API `sha256:f300f7fd06c25e7b41c6edb9d4c67cf90937becfb9c39891ed844ce30acfa176`.
- Web `sha256:a029e8302e28c688f260323ad4958ed103e0f860d5d8a8fdaa469a192ce035fc`.
- Web builder `logoff-web:restore-kiz-build`, index.html совпадает с работающим web.

`production.patch` — точный патч поверх этих исходников. Сервер уже содержит общий
резерв, единый учёт WB-заказов и подтверждение публикации, отсутствующие в старой
локальной интеграционной ветке. Их не заменять файлами старой ветки.

Новый runtime вызывается из существующего плана переклейки. Для активных групп
старые ручные соответствия не расходуют тот же пул повторно. Общий резерв удерживается
один раз; в возвращаемых SKU-правилах резерв рассчитанных групп устанавливается
в NONE только в памяти, без изменения общих настроек клиента в БД.
Готовый товар дубля остаётся на своей карточке. Точные исходные SKU используются
в списках заказов и выдаче ТСД; кэш выбора включает идентификатор источника.

Флаги `WMS_DUPLICATE_STOCK_GROUPS_ENABLED` и `WMS_DUPLICATE_STOCK_PUBLICATION_ENABLED`
по умолчанию выключены. Наличие редактора само по себе не включает публикацию.
Нужен отдельный список проверенных активных групп в SystemSetting.
Активация требует одного кабинета WB, общего склада, включённой переклейки,
действующего распределения по складам, подтверждения WB и единого учёта резервов.
Редактор не изменяет активную группу без контролируемого переключения администратором.
Пропущенная в ответе WB карточка блокирует увеличение всей связанной пары размера.

Пилот: ИП Лукин Илья Ильич, ФФ Москва. Пять пар, 23 соответствия размеров:
синий 50%, тёмный/светлый меланж по 25%, коричневый 100%, серый 50% на дубль.
«Графит → чёрный» исключена по указанию пользователя. Все пять связей уже существуют
в «Переклейке». Шесть исходных размеров худи без дубля не включаются в группы.
Общий резерв наследуется, включая правило малого остатка; число не копируется в группу.

Перед выпуском: полный локальный набор тестов; сборка кандидатов и сравнение полного
серверного API-набора с базой; расчёт кандидата на реальной БД без записи; проверка
совпадения preview/runtime и отсутствия повторного резерва. Переключение контейнеров
только под обеими release-блокировками с проверкой неизменности базовых образов.
Сохранить предыдущие теги и настройки групп для отката.

После активации: пересчёт существующей очередью WB, проверка исходной карточки 0
для всех размеров группы 100%, проверка каждого виртуального склада и суммы,
отдельная фиксация неподтверждённых строк. Факт выпуска и результаты записать после
выполнения проверок; наличие этого документа не означает, что код уже развёрнут.
