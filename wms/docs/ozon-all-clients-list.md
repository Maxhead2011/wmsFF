# FBO Ozon: общий список заявок

## Поведение

На нашей ВМС экран открывается с фильтром «Все клиенты», независимо от клиента,
сохранённого в других разделах. Это все клиенты, доступные текущему пользователю
в его складском контуре. Клиентский пользователь видит только свои заявки.
При выборе конкретного клиента список фильтруется, а создание по файлу/ссылке
сохраняет обязательный выбор клиента и филиала.

Заявки представлены строками: **Заявка / Состав / Срок и статус / Склад / Действия**.
Код и имя клиента находятся сверху в «Составе», как в FBO WB. Таймер редактирования
Ozon сохранён. Открытие сборки, поставки и грузомест использует ID выбранной заявки.
Удаление остаётся в существующем механизме с проверкой прав и подтверждением.
На телефоне строка складывается в вертикальные блоки; на промежуточной ширине
доступна горизонтальная прокрутка таблицы.

По 100 заявок загружается за один запрос. «Показать ещё» продолжает список по
уникальному номеру, поэтому старые заявки не скрыты ограничением первой страницы.
Ответ предыдущей страницы отбрасывается при смене фильтра, филиала или обновлении.
Исторические заявки остаются видимыми даже после отключения кабинета Ozon.

## Границы изменения

- `OzonFboImportService.list` и контроллер: только чтение, явный `allClients=true`
  под существующим `WMS_MARKETPLACE_WORKSPACES_ENABLED`, область клиентов и филиала,
  безопасный курсор `beforeNumber`, компактное описание состава.
- `OzonCustomerWorkspace`, `OzonAssemblyList`, `api.ts` и локальный CSS:
  общий фильтр, строки, пагинация и защита от запоздавших ответов.
- При отсутствии opt-in или выключенном флаге сохраняется прежний API-путь.
  Новый интерфейс включён только для нашей ВМС/локальной проверки. Проданная ВМС
  не публикуется. Схема БД, создание поставок, резервы, остатки и APK не меняются.

## Проверки

Регрессии общего списка и прав воспроизведены до исправления. Исходные тесты:
API — 3975 пройдено, 150 пропущено; web — 542 пройдено, 2 пропущено.
Два KIZ DB integration suite исключены из общего запуска, как в текущем выпуске.
API TypeScript, web TypeScript/Vite и 8 проверок baseline пройдены.
Фактический JS-кандидат: 34 assertions; scopes, query decorators, состав,
таймер и 205 заявок в трёх страницах. Браузер: 23 сценария, включая 6 ширин
в двух темах. Изолированный PostgreSQL: 9 сценариев и полный API health.
Проверочные данные синтетические; рабочие заявки не меняются.
