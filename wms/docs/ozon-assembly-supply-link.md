# Связь единой сборки с поставкой Ozon

FBO Ozon → единая сборка → «Поставка и грузоместа Ozon». Выберите кабинет и ID существующей заявки из адреса кабинета, затем сохраните соответствия направлений. Сверка показывает товары/количества по штрихкодам, место, слот и статус. Файл клиента остаётся источником потребности. Привязка не изменяет складские остатки.

Отбор и упаковка остаются общими FBO-сценариями на текущем APK. Передача разрешена только при точном совпадении распределения, закрытых/проверенных коробах и статусе DATA_FILLING в Ozon. Отправляются фактические FboAssemblyUnit по FboAssemblyBox. Существующие чужие грузоместа не заменяются. Подтверждение передачи обязательно.

Перед сетевым запросом под общей блокировкой ClientRequest сохраняются hash состава и SENDING. Каждый Supply ID имеет собственный результат. Повтор запроса не повторяет начатые отправки; можно продолжить ещё не начатые направления. UNKNOWN или оставшийся после сбоя SENDING требуют сверки в кабинете/поддержкой: автоматический повтор запрещён. FAILED также не повторяется автоматически. После начала передачи состав и привязка заблокированы; завершение уже проверенной сборки разрешено. Переупаковка после отправки пока требует отдельного разбора и не доступна обычной кнопкой редактирования.

По operation_id проверяется результат Ozon. После SUCCESS можно запросить PDF этикеток Ozon; если он готовится, повторное получение проверяет ту же операцию. Привязка не создаёт новую заявку Ozon, не меняет её количества и не бронирует слот. Передачу КИЗ/УПД этот модуль не выполняет.

Изоляция: WMS_OZON_FBO_IMPORT_ENABLED, client scope, активный филиал, кабинет того же клиента, уникальная пара sellerId/orderId. Прежние планы Ozon не перехватываются. Два nullable-поля OzonFboShipment; миграция аддитивная. Проданная WMS не меняется. API runtime — точечные изменения шести файлов от PR525; web сохраняет действующий граф и единственный React. Source parity false.

Проверки: policy/service tests; отдельная PostgreSQL — конкурентная отправка, unique binding и 40 FBO сценариев; browser готового графа — привязка, блокировка расхождений, mapping, подтверждение передачи, фиксация состава, ссылка PDF и прежний режим. Внешние записи в browser/DB тестах имитируются. Реальное API Ozon проверено только на чтение: №133455152, 8 направлений, 239 единиц против 11/393 в файле. Фактическая отправка и печать этикеток требуют согласованного состава и реальных проверенных коробов; до этого полный внешний цикл не подтверждён.
