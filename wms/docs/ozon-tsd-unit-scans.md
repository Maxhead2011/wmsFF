# Ozon FBS: этикетка и количество на ТСД

Для заказов с несколькими одинаковыми товарами без КИЗ ТСД показывает количество
и подтверждает каждую единицу отдельным сканированием ШК. Счётчик хранится на сервере.
Повтор запроса с прежним `scannedItemCount` не добавляет единицу. Обновление выполняется
через существующую проверку владельца задания и `updatedAt`.

В LOGOFF этикетка заменена текстом «Наклейте наклейку Ozon № [номер отправления]».
Подтверждение наклейки остаётся обязательным. Отправка в Ozon и ожидание готовности
этикетки сохраняются. После включения флага API не передаёт изображение на ТСД.

## Область изменения

- Только наша ВМС: `WMS_OZON_TSD_UNIT_SCANS=true`; по умолчанию выключено.
- Android: текстовая инструкция только для flavor `logoff`.
- WB и маркированная одиночная сборка сохраняют прежний порядок сканирования.
- Несколько разных артикулов не входят в исправление. Несколько КИЗов/переклейка
  блокируются до передачи заказа менеджеру: существующая запись хранит один КИЗ.
- Завершённые заказы не пересобираются. Активная старая запись с ШК считается
  одним сканированием, а не подтверждением всего количества.

## Порядок публикации после согласования PR

1. Применить миграцию `202609160001_ozon_tsd_unit_scans` до запуска нового API.
   Она добавляет счётчик и сбрасывает его при очистке ШК любым путём снятия задания.
2. Собрать актуальный выпуск LOGOFF ТСД с новым versionCode и доставить обновление
   сотрудникам. Перед выпуском совместить исправление с текущей версией нашей ВМС.
3. Установить API и включить флаг только в нашей конфигурации. Старое приложение
   получит просьбу обновиться при попытке поштучного сканирования.
4. Проверить на физическом ТСД новый заказ из двух одинаковых единиц: 0/2 → 1/2,
   обновление экрана сохраняет 1/2, затем 2/2 и текстовая инструкция с номером.
   До 2/2 завершение и передача в Ozon недоступны.

Для отключения нового серверного поведения убрать флаг; добавленное поле можно
оставить в базе. В проданной ВМС флаг не включать, APK LOGOFF туда не устанавливать.

## Проверки

- `pnpm test`: все тесты API и веба, включая `ozon-tsd-quantity.spec.ts`.
- `pnpm --filter @logoff/wms-api build`: проверка типов и сборка API.
- `gradle -p apps/android-tsd testLogoffDebugUnitTest testFfullhabDebugUnitTest testPlatformDebugUnitTest`.
- Локальная тестовая PostgreSQL: `psql -f apps/api/test/ozon-tsd-migration.sql`.
  SQL-тест использует отдельную схему внутри транзакции и полностью откатывается.
