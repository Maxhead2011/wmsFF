# Найденный после отгрузки КИЗ без короба

Только LOGOFF, флаги `WMS_KIZ_FOUND_REVIEW_ENABLED` и `VITE_KIZ_FOUND_REVIEW_ENABLED`.
Проданная ФФУЛЛХАБ не публикуется и не настраивается.

Проверка КИЗа остаётся чтением. Для единственной записи SHIPPING без короба
появляется явное действие «Товар физически у меня — отправить на разбор».
ADMIN/OWNER подтверждает наличие и причину; создаётся отдельный `FOUND:` случай
в существующей KizReviewCase, без заявки и складских движений. Повторное обращение
обновляет тот же случай. Очередь показывает обращения за семь дней.

Решения: разрешить использование КИЗа; разрешить переклейку; вернуть на склад;
отклонить ещё не обработанное обращение. Для возврата обязателен действующий короб
того же клиента и филиала. Подтверждённое погашение/продажа блокирует REUSE.
Само разрешение не добавляет запас. После отдельного возврата создаётся разрешение
UNIT для одного следующего отбора; существующий механизм claim/consume сохранён.

Историческая привязка освобождается только с отдельным подтверждением, после
возврата, с полным снимком прежней сборки в аудите. История отгрузки сохраняется.
Действующую сборку сначала нужно вернуть штатным механизмом: данный сценарий
не удаляет её КИЗ и не оставляет неснятый резерв. Отмена обращения не является
откатом уже учтённого возврата или выданного разрешения.

Блокировка ProductMark сериализует операции. RETURN, AVAILABLE, ProductMark,
разрешение и аудит записываются одной транзакцией; повторный RETURN идемпотентен.
Проверки клиента/филиала выполняются перед чтением и повторно внутри транзакции.

Файлы: `kiz-found-review.ts` (act/list/checkBindings), отдельный контроллер,
`kiz-location.service.ts` (lookup), `inventory.module.ts`, реестр API;
`KizFoundPanel.tsx`, KizCheckPanel/KizReviewQueuePanel и API-клиент;
KizLocationScreen/KizFoundPolicy/WmsApi/TsdKizLocationResponse, LOGOFF APK222.
Runtime delta: шесть файлов API. Старая очередь исключает FOUND, поскольку эти
обращения не привязаны к FbsTsdAssembly. Прочая логика старой очереди сохранена.

Тесты: воспроизведение отсутствующей кнопки до исправления; API unit;
PostgreSQL на отдельной локальной схеме (параллельные OPEN/RETURN, откат при
ошибке аудита); реальный JS-пакет в браузере; Android policy; runtime wiring.
Публикация кода не создаёт обращение и не возвращает реальные товары автоматически.
