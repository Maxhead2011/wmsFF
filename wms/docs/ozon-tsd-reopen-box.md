# Догруз закрытого короба Ozon в ТСД

Подготовлено в `fix/ozon-tsd-reopen-box`, не опубликовано.

В упаковке Ozon для закрытых коробов появляется «Добавить в закрытый короб».
Подтверждение повторно открывает существующий короб, сохраняя направление и содержимое.
Товар добавляется обычным PACK_UNIT с проверкой отбора, квоты направления и КИЗ.
После догруза короб снова закрывают и проверяют.

Серверная команда REOPEN_BOX проходит существующие проверки доступа, этапа,
состава заявки, занятости короба и идемпотентности. Сбрасываются только closedAt,
confirmedAt и confirmedByUserId. Команда записывается в журнал FBO_REOPEN_BOX.
Чужие короба, целые исходные короба и уже открытые короба отклоняются.
После фиксации состава в Ozon либо при незавершённой корректировке открытие запрещено.

Флаг WMS_OZON_REOPEN_BOX_ENABLED по умолчанию выключен. Capability
reopenPackingBoxSupported включает интерфейс только в LOGOFF APK и только для
изменяемой заявки Ozon. Нужны согласованные обновления API и APK.

Перед выпуском: заново снять актуальный runtime и image ID, точечно добавить
REOPEN_BOX в runtime DTO и Ozon allowlist, capability и ветку обработчика,
скомпилировать ozon-reopen-box.ts. Полной локальной сборкой runtime не заменять:
sourceParityVerified=false. Проверить именно runtime-кандидат, затем подписать
новую версию LOGOFF APK; обновить baseline после публикации. До этого на сервере
и устройствах сценарий не изменён.

Тесты: ozon-reopen-box.spec.ts — область действия, чужой короб/направление,
фиксация состава, feature flag, сохранение содержимого; FboTwoStageScreenTest —
кнопка по capability/flavor, отмена без записи, открытие и обычный PACK_UNIT.

Локальная проверка 15.10.2026: API 3446 passed / 155 skipped (отдельные DB suites
без настроенной тестовой БД); web 440 passed / 2 skipped; Android 263 на каждый
из трёх вариантов (789), LOGOFF release build и API TypeScript прошли.
Первый общий API прогон получил timeout PDF-теста; отдельный повтор и полный
повтор с четырьмя worker прошли. UI regression падал до добавления кнопки.
Тест реального серверного dispatcher подтверждает единственный аудит и изменение
при повторе того же operationId; смена направления при повторе отклоняется.
