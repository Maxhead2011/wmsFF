# Диагностика запросов и компактная квитанция ТСД

Первый самостоятельный выпуск аудита эффективности. Подготовлен к публикации;
очередь сверок и её миграция в этот выпуск не входят.

## Изменения

- `main.ts` подключает `timingMiddleware` до разбора тела запроса.
- `common/diagnostics/operation-timing.ts` измеряет время до завершения ответа
  или разрыва соединения. Контекст изолирован через AsyncLocalStorage. В журнал
  попадают шаблон маршрута, метод, статус, случайный trace ID и длительность.
  Тела запросов, параметры URL, SQL, токены и тексты исключений не записываются.
- Медленные ответы (от секунды) и серверные ошибки учитываются в первую
  очередь, быстрые — каждый сотый. Лимит 60 подробных записей в минуту на
  процесс плюс сводка подавленных записей. Эта выборка не подходит для
  вычисления среднего времени всех запросов. Суммы вложенных стадий могут
  пересекаться и не являются разложением общего времени.
- `TsdOperationLogService.findExisting` читает только статус и сообщения
  результата. Полный payload и скриншот при повторе сканирования не читаются.
  Ключи идемпотентности и история сохраняются, результат повтора не меняется.

Флаги `WMS_OPERATION_TIMING_ENABLED` и
`WMS_COMPACT_OPERATION_RECEIPTS_ENABLED` по умолчанию выключены; включаются
только в новом образе нашей ВМС. Проданная ВМС не получает этот образ.
БД, web, APK233, печатный агент и бизнес-данные не меняются.

## Проверки

- Регрессия компактной квитанции: падение до исправления, успех после.
- Проверены параллельные контексты, исходное исключение, сбой логирования,
  выключенные флаги, отсутствие утечки URL, однократное завершение и лимит журнала.
- API: 3462 passed / 150 skipped; два специализированных KIZ integration suite
  исключены, поскольку отдельная тестовая БД для них не настроена.
- Web: 443 passed / 2 skipped. API TypeScript — успешно.
- Actual-image smoke: 7 сценариев, без бизнес-записей. Синтетические 10 000
  вызовов middleware: около 5.9 микросекунды на вызов. Это не замер ТСД/сети.
- Runtime delta проверен: только `main.js`, `operation-timing.js`,
  `tsd-operation-log.service.js`. Класс журнала совпадает с опубликованным;
  заменяется только `findExisting`, текущие DI metadata сохранены. Для main
  проверено полное соответствие до изменения. Общий sourceParityVerified
  остаётся false.

База API: `997ba99e69cc980180b6efbe480b1fe5634e5096df5bffe733620b94de5d3090`.
Web сохраняется от PR614/615: `80a153ed4e09f7d6dc00310aac8bcc85910ca8d4974fd37239d62fa8d607c5ee`.
