# Фильтр статуса счетов

В разделе «Биллинг → Счета» поле «Статус счёта» доступно и в списке, и на экране
«Темы счетов»: Все статусы, Черновик, Выставлен, Оплачен, Отменён.
Выбор сохраняется при переходе между представлениями. Счётчики и суммы тем,
строки реестра и его итоговые суммы учитывают выбранный статус вместе с периодом,
клиентом и видом услуг. Фильтр не меняет документы и платежи.

Изменены только `BillingPanel` (контроль выбора статуса и `invoiceKindTiles`) и тесты.
Проданная WMS/FFULHAB не затрагиваются. Кнопка счёта по сданным заявкам сохраняется.

Проверки: регрессия отсутствующего фильтра на экране тем упала до исправления;
web 365 passed / 2 skipped, API 3033 passed / 132 skipped (отдельная KIZ suite,
требующая изолированной БД, исключена), TypeScript и Vite.
Browser test на действующем графе с фиктивными данными проверяет все четыре статуса,
сброс фильтра, счётчик тем, сохранение выбора и прежнюю кнопку создания счёта.
Запросов записи нет. Node/Python проверки публикации отклоняют посторонние изменения.

Публикация только нашей WMS: `scripts/billing-invoice-status-release.cjs` привязывает
точечную правку к SHA опубликованного billing chunk из PR463, создаёт новый граф
из 29 JS-файлов и сохраняет старые assets. `deploy-billing-invoice-status.py`
под блокировкой сверяет все контейнеры и web-хеши со свежим эталоном, проверяет
кандидат и публичные файлы, пересоздаёт только web и автоматически откатывает при ошибке.
API, compose и данные не изменяются. Полная сборка исходников не публикуется:
source parity false. Целевая ветка PR — `feature/wb-print-check`, remote `publish`.
