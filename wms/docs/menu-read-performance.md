# Приёмки и онлайн-выполнение: ограниченное чтение

Изменение нашей WMS, 09.10.2026. Рабочая ветка `fix/receipt-online-read-performance`,
целевой PR — `feature/wb-print-check`. Исходный baseline —
`2026-10-08-fbo-compact-packing`; `sourceParityVerified=false`.

## Причины и изменения

- ФБС: документ подбора загружал полный JSON карточек маркетплейса в каталоге
  и повторно в остатках. Остаются те же товары, соответствия артикулов, штрихкоды,
  разрешённые остатки и порядок выбора. Из остатков исключён неиспользуемый JSON;
  каталог получает все ключи, которые читает `buildShkCatalogFromSkus`.
  Сокращение набора кандидатов по SKU намеренно не применяется: это могло изменить
  подбор замен и распределение целых коробов.
- ФБО: браузерный GET получает непосредственно специализированный план.
  Проверки клиента, филиала и ожидающего согласования баланса сохранены.
  Внутренний `getRequestPlan` для операций и прежний ответ при выключенном флаге сохранены.
- Приёмки: только отчётный путь агрегирует движения в PostgreSQL по коробу,
  документу и году и читает последнее значимое открытие короба. Количества,
  ручная принадлежность и старые годы сохраняются. Операционные проверки
  согласования, блокировки и транзакционные записи не меняются.
- Список запрашивает `summary=1`: число коробов без их содержимого. Раскрытие
  загружает `receiptId`. Старые клиенты без параметров получают прежний ответ.
- Одновременные браузерные GET одного плана объединяются только в пределах
  одного токена, заявки и вида плана. Завершённый ответ не кэшируется;
  ошибки удаляются из очереди. Интервал опроса и проверки актуальности операций прежние.

Это не материализованная таблица приёмок: запрос ещё агрегирует историю в БД,
но не выгружает её целиком в Node. Отдельная постоянная сводка потребовала бы
новых транзакционных обновлений и миграции; текущий выпуск их не вводит.
Полная история КИЗов ФБО пока остаётся в специализированном плане.
Условные ответы «не изменилось» не вводятся без полного списка источников версии:
неполная версия скрывала бы новые сканирования. Здесь устранены дублирующие запросы.

## Изоляция и выпуск

API: `WMS_MENU_READS_ENABLED=true` только нашей WMS; по умолчанию выключен.
Source-web: `VITE_MENU_READS_ENABLED=true` включает объединение запросов.
Точечный web overlay для нашей WMS включает его явно. Sold WMS не пересобирать.
Подтверждение приёмки, складские движения, КИЗы, биллинг, APK219 и агент печати
не изменяются. Новых таблиц нет.

API overlay: `scripts/build-menu-read-performance.cjs`, шесть модулей. Web overlay:
`scripts/menu-read-web-runtime.cjs`, сохраняет единственный React и остальные
функции опубликованного графа. Проверять `release_baseline.py check-candidate`.
Перед переключением контейнеров повторно сверять image ID и сохранять rollback-теги.
Откат API — прежний image и значение флага; web — прежний image.

## Проверки

Автотесты помечены `// TEST`, исправления — `// FIX`:

- `apps/api/test/menu-read-performance.spec.ts`: прямой web FBO, запрет при
  согласовании, FBS/выключенная установка, прежний набор остатков без тяжёлого JSON.
- `apps/api/test/receipt-report-evidence.spec.ts`: агрегирование только отчётов,
  сохранение года/количеств и прежнего операционного пути.
- `apps/web/test/shared-read.spec.ts`: объединение только незавершённых чтений,
  изоляция сессий, повтор после ошибки.
- `scripts/tests/menu-read-browser.cjs`: реальный JS-граф, ленивое раскрытие
  коробов и одновременные запросы. На старом графе проверка компактного списка падает.
- `scripts/tests/menu-read-runtime.cjs`: собранные API-методы и Nest query metadata.
- `scripts/tests/menu-read-live-compare.cjs`: сравнение в одном RepeatableRead
  снимке с обязательным откатом и запретом ORM-записей. Только чтение рабочей БД;
  не запускать как нагрузочный тест. Поля времени формирования исключены из сравнения.

Локально: 3163 API прошли / 141 пропущен; отдельно исключён
`kiz-duplicate.integration.spec.ts`, которому нужна выделенная тестовая БД.
Первый общий запуск подтвердил именно отсутствие её URL, а не регрессию.
400 web прошли / 2 пропущены; API/web TypeScript прошёл.
Браузерный тест управления окном ФБО также прошёл на готовом графе.
