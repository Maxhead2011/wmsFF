# Отмена последней единицы упаковки

Подготовлено в `feature/fbo-undo-last-packed`, ещё не опубликовано.

В LOGOFF на экране упаковки добавлена кнопка «Отменить последнюю единицу».
Если отсканирован только ШК/КИЗ, сбрасывается незавершённый скан без запроса изменения остатков.
Если вложение уже подтверждено, сборщик подтверждает физическое извлечение одной штуки из указанного короба.
Единица и её КИЗ возвращаются в накопитель отобранного товара; счётчик упаковки и потребность направления обновляются.
Сам отбор сохраняется. Пустой короб остаётся открытым.

Отмена относится к последней подтверждённой поштучной упаковке этого сотрудника в этой заявке.
Следующая успешная операция, закрытие короба, завершение или фиксация состава для Ozon запрещают отмену.
Целые короба и ручные добавления этой кнопкой не отменяются. Старые вложения до включения функции не получают искусственных квитанций.

## Надёжность и изоляция

`WMS_FBO_PACK_UNDO_ENABLED` выключен по умолчанию. Включение предназначено только для нашей WMS;
кнопка дополнительно ограничена LOGOFF flavor и серверной capability `packingUndoSupported`.
Для каждой новой обычной упаковки сохраняется точная квитанция единицы в существующем AuditLog.
Поиск квитанции использует первичный ключ; проверка более поздних операций — индекс requestId/createdAt.
Отмена использует прежнюю блокировку заявки, Serializable-транзакцию и operationId.
Запись истории с `undoOperationId`, обратное движение остатка/КИЗа и изменение единицы атомарны.
Потерянный ответ повторяется с прежним operationId, включая перезапуск приложения.
Неизвестный результат нельзя заменить новым сканом или отменой.

Изменены сервис FBO, DTO и новый `fbo-packing-undo.ts`; экран, состояние и модель плана Android.
Проданная WMS, маршрутизация и схема БД не изменяются. Для публикации нужны отдельный API delta и новая версия LOGOFF APK после 226.
`scripts/releases/fbo-undo-last-20261010/patch.cjs` сохраняет все оптимизации действующего runtime.

## Проверка направления на ШК

В упаковке Ozon «По направлению» проверяется состав направления текущего короба.
ШК чужого направления или уже полностью упакованной позиции отклоняется до запроса КИЗа и отправки команды.
Проверка использует полученный план без дополнительных сетевых запросов. Сервер по-прежнему проверяет актуальную квоту при вложении.

- `fbo-packing-undo.spec.ts`: точная единица, чужой сотрудник, изменённая упаковка, закрытый короб и выключенный флаг.
- `scripts/tests/ozon-product-postgres.cjs <candidate> --undo`: реальный PostgreSQL, конкурентные отмены, повтор запроса, откат при сбое аудита/КИЗа, запрет старой квитанции, физическое обратное движение КИЗа.
- `OzonProductStateTest`: сохранение исходного вложения и команды отмены после перезапуска.
- `FboTwoStageScreenTest`: подтверждение извлечения, сброс незавершённого скана, потеря ответа/перезапуск, проверка направления до запроса КИЗа.

Физическое сканирование ТСД проверяется после установки нового выпуска.
