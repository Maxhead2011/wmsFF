# Резервы и мониторинг WB: CL-000014

Подготовлено 28.10.2026 в `fix/kubrin-stock-reservations`. **Не опубликовано**.
PR предлагается в `feature/wb-print-check`; открытие PR требует подтверждения
по инструкции пользователя. Рабочие данные этой проверкой не изменялись.

## Причины

В проверке CL-000014 найдены 12 старых нетронутых AUTO-заданий от 8–9 октября.
Свежий ответ WB: `complete/sold`. Заказы вышли из обычного окна загрузки,
но задания `WAITING_STOCK` продолжали участвовать в резерве. У них нет связей
с заявками, сканов, печати, точных складских проводок и истории отгрузки.
Это не основание создавать отгрузку задним числом: нужно закрыть только
устаревшее виртуальное требование.

31 событие мониторинга с 27 октября не имело chrtId: общий SKU содержал
идентификатор Ozon, тогда как корректная связь WB была сохранена отдельно.
Мониторинг должен использовать связь точного клиента, кабинета и SKU.
Подлинные резервы FBO и работающие FBS-задания сохраняются.

## Изменения и изоляция

- `fbs-monitor-product-identity.ts`: `monitorProductIdentities` использует
  единственную LINKED-связь WB при действующем клиентском флаге product links.
  Нет связи или есть неоднозначность — нет запасного перехода на чужой ID.
- `fbs-stock-monitoring.service.ts`: `ingestOrders` и `runChecks` используют
  связь кабинета; старое событие получает правильный ID при повторной проверке.
  При смене ID прежняя база сравнения сбрасывается. Большие chrtId поддержаны.
- `wb-terminal-auto-reservations.ts`: `reconcileTerminalAutoReservations`
  отдельно читает статусы до 1000 старых AUTO-заданий. Только подтверждённое
  терминальное состояние и отсутствие следов работы разрешают RELEASED.
  Serializable-транзакция, блокировка строки, повторная проверка updatedAt,
  запросы связей/проводок/печати/отгрузки/КИЗ, атомарная запись AuditLog.
- `marketplace-connections.service.ts`: сверка вызывается перед расчётом
  автоматически публикуемого остатка; в runtime — до снимка stock plan.
  Обычный просмотр остатков эту процедуру не вызывает.

Новый флаг `WMS_WB_TERMINAL_AUTO_RESERVATIONS_ENABLED` по умолчанию выключен.
Дополнительно обязателен список `WMS_WB_TERMINAL_AUTO_RESERVATION_CLIENTS`.
Кандидат нашей WMS включает только UUID клиента CL-000014.
Общие модули затронуты; проданная WMS не получает образ или флаги.
При выключенных флагах сохраняется прежнее поведение. Web, APK238, schema,
физические остатки, движения, правила страхового резерва не меняются.
