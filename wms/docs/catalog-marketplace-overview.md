# Связи WB/Ozon в каталоге

Подготовлено 24.10.2026, не опубликовано. Ветка `feature/catalog-marketplace-overview`, целевая интеграционная ветка `feature/wb-print-check`.

Таблица каталога выбранного клиента показывает подтверждённые связи каждого SKU с кабинетами WB/Ozon, артикул, ID и собственные штрихкоды маркетплейса. Складской штрихкод остаётся отдельной колонкой. Наличие связи не обозначает включённую продажу или положительный остаток на маркетплейсе.

Кнопка «Проверить соответствия WB и Ozon» перечитывает сохранённые связи всех кабинетов выбранного клиента. Проверяет статус, наличие данных, размер/цвет, пересечение ШК со складской карточкой и один ШК у разных SKU. Замечания требуют ручной проверки; изменений связей, объединения SKU, движений или публикации остатков нет. Это проверка последней сохранённой информации, не синхронизация внешних каталогов; для свежих внешних данных используются существующие кнопки выгрузки из API.

Старые ответы API без полей ШК не считаются успешной сверкой. Ошибка одного кабинета не выдаётся за успешную частичную проверку. Ответы предыдущего клиента отбрасываются; подключения фильтруются по clientId. Неподтверждённые связи не отображаются как подтверждённое присутствие товара на маркетплейсе.

## Файлы и границы

- `CatalogPanel.tsx`: подключение обзора, кнопка и результаты, ячейки таблицы.
- `CatalogMarketplaceOverview.tsx`: чтение существующих API, состояния загрузки/ошибки, отображение кабинетов и ШК.
- `marketplaceOverview.ts`: чистая проверка сохранённых связей.
- `lib/api.ts`: дополнительные необязательные поля ответа, совместимость со старым API.
- `MarketplaceConnectionsService.productLinks`: дополнительные поля `barcodes`, `size`, `color` из той же записи связи; прежние проверки доступа и feature/client gate сохранены.

Общие исходники затронуты. Проданная WMS не входит в выпуск; её образы/настройки не меняются. Для клиента без включённого механизма связей показывается явное ограничение, не ложное отсутствие товара.

## Включение сверки из каталога

Рядом с выгрузкой WB/Ozon находится «Включить сверку WB/Ozon», затем «Проверить соответствия WB и Ozon». POST `marketplace-connections/:id/catalog-reconciliation/enable` требует прав записи, владения филиалом клиента и роли ADMIN/OWNER. Общий флаг установки `WMS_MARKETPLACE_PRODUCT_LINKS_ENABLED` должен быть включён. В SystemSetting сохраняется `catalog.reconciliation.enabled.v1:<clientId>`, отдельно от operational allowlist. Запись и аудит атомарны, повторное включение идемпотентно.

Это включение именно просмотра и проверки, не перевод обработки заказов/остатков на другие идентификаторы. Для legacy-клиентов исходные сохранённые SKU показываются как SAVED_CARD и не выдаются за подтверждённую общую связь. При нескольких кабинетах одного маркетплейса legacy-атрибуция не выполняется, поскольку владелец карточки неоднозначен. Сопоставление по ШК выдаёт кандидата/замечание без объединения SKU. Полный переход клиента на общий operational-каталог остаётся отдельной процедурой подготовки связей.
