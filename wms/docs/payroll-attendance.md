# ФОТ: учёт времени и погрузок

Рабочая ветка: `feature/payroll-attendance`. Реализация подготовлена локально;
публикация и перенос реальных записей ещё не выполнены. Планшетное приложение
не входит в этот этап.

## Доступ и включение

Раздел расположен в «Управление расходами → ФОТ». Новый API доступен только
при `WMS_PAYROLL_ATTENDANCE_ENABLED=true`. До включения сохраняется старый экран.
ADMIN ограничен warehouseIds / writableWarehouseIds; OWNER видит все филиалы
своего демо/реального контура. Рабочие не получают доступ к реквизитам.

Схема: миграция `20260926150000_payroll_attendance`. Новые таблицы Payroll*
не изменяют остатки, сборку, печать или существующий журнал расходов.
Проданная WMS не включается в публикацию. Перед выпуском обязательны PR,
свежая сверка runtime и проверка кандидата по release-workflow.md.
Обновление Prisma-клиента также требует проверки на текущем runtime.

## Расчёт

- Реальные начало/конец с часовым поясом, дата учёта — дата начала по Москве.
- Несколько интервалов суммируются по дню. Пересечения запрещены под блокировкой сотрудника.
- Больше шести часов: один час обеда, распределённый пропорционально по ставкам.
  Ровно шесть часов: обеда нет. Денежный итог округляется до копеек после расчёта.
- Базовые ставки сохраняют историю; следующая ставка закрывает предыдущую.
  Временные условия имеют конец действия и приоритет над базой; пересечения запрещены.
- Сдельные начисления используют завершённые физические задания и историю попыток;
  одинаковые идентификаторы не дублируются. Задания с неизвестным филиалом требуют проверки.
  Смена типа оплаты внутри смены блокирует оплату до проверки.
- Погрузка/разгрузка: ставка каждого участника на начало работы, умноженная на
  паллеты и делённая на число участников. Общая запись подтверждается администратором.
  16 коробок или 5 мешков = паллета. Тарифы задаются явно; текущий согласованный — 500 ₽.
- Состояния начисления: UNPAID, REVIEW, PAID. При оплате сохраняется снимок расчёта,
  дата и автор. Повторная отметка PAID не создаёт выплату. Изменение оплаченных
  смен запрещено до пересмотра статуса; пересмотр записывается в аудит.

## Реквизиты и отчёты

Способ выплаты: CASH / TRANSFER. Для перевода обязательны телефон и банк.
Сотрудник может существовать без логина WMS; для сдельного расчёта требуется
привязка пользователя сборки. В настройках можно скрыть сотрудника, сохранив историю.
Excel содержит исходные колонки табеля, детализацию ставок и начисления.
PDF содержит личный отчёт за выбранный период. Общий экран позволяет выбрать всех
доступных сотрудников; изменения статуса и личные выгрузки выполняются по сотруднику.

## Исторический импорт

Загрузка XLSX сначала формирует предпросмотр и требует явного соответствия имён
сотрудникам WMS. Старые часы, суммы и статусы сохраняются, новый обед не применяется.
Неизвестный статус — REVIEW. Некорректные числовые результаты блокируют импорт.
Повторный файл пропускает уже внесённые строки; изменение ранее внесённого результата
требует ручной сверки. Нельзя одновременно импортировать и заводить смены за один день.
Телефон и банк исходных строк сохраняются в истории; текущие реквизиты сотрудника
задаются в карточке и не перезаписываются автоматически.

Проверка предоставленного файла: 1263 корректные строки, 31 вариант имени;
Август_2026, строка 48 содержит отрицательное итоговое время и сумму 0.
Реальный импорт не выполнялся; решение по спорной строке ожидает пользователя.

## Проверки

- payroll-calculation.spec.ts: ночные/раздельные смены, порог обеда, временные ставки, копейки при делении.
- payroll-access.spec.ts: флаг, роли, филиалы, телефон и банк для перевода.
- payroll-workflow.spec.ts: оплаченные дни, пересечения, аудит, повторная оплата.
- payroll-import.spec.ts: сохранение истории, идентичность повторного импорта, неизвестный статус.
- payroll.integration.spec.ts: отдельная локальная PostgreSQL, конкурентная запись и снимок оплаты.
- PayrollManagement.spec.tsx: сохранение прежнего экрана до включения флага.

Локальная проверка 26.09.2026: API 2838 passed / 94 skipped; web 239 passed;
дополнительно PostgreSQL 3 passed и экспорт Excel/PDF 2 passed.
TypeScript API и web проходит. Интеграционный тест KIZ duplicate исключён из
общего прогона: он создаёт PrismaClient с undefined URL даже при skipIf;
в исходном полном прогоне это единственный оставшийся инфраструктурный сбой.
Тестовую БД ФОТ после проверки остановили. Секреты и реальные данные в тесты не копировались.

Перед включением на сервере нужна визуальная приёмка форм, выборочное сравнение
расчётов с реальными днями и проверка совместимости Prisma-клиента с текущей базой.
