# Массовое изменение литража по артикулу / баркоду

Подготовлено 17.11.2026; на сервер не опубликовано.

В блоке «Массовое изменение литража» можно выбрать клиента, ввести артикул
или баркод, оставить отмеченными нужные позиции и задать новый литраж.
Диапазон текущего литража необязателен; если заполнена хотя бы одна граница,
нужно заполнить обе. Поиск по части артикула / SKU клиента не учитывает регистр;
баркоды проверяются среди всех баркодов карточки с сохранением ведущих нулей.
Карточки без литража также доступны. Лимит выдачи остаётся прежним: 5000 товаров.

При смене клиента, запроса или диапазона старый выбор недоступен для сохранения.
Запоздавшие ответы игнорируются. Enter сканера в поле поиска не отправляет форму.
Перед сохранением показано подтверждение, во время записи элементы заблокированы.
Сервер повторно проверяет клиентский доступ, выбранные ID и условия поиска;
несовпадение количества обновлённых товаров прерывает транзакцию нового режима.
Запись изменяет только volumeLiters и volumeSource=MANUAL, с журналом аудита.
Габариты не изменяются. Новый литраж, как и прежде, используется для хранения.

## Изоляция проданной ВМС

Общие модули: SkusService.listBulkVolume/updateBulkVolume, SkusController.listBulkVolume,
BulkUpdateSkuVolumeDto, веб-контракт fetchBulkSkuVolume/updateBulkSkuVolume и BulkVolumeEditor.
Для нашей ВМС включаются два флага:

- API: `WMS_BULK_VOLUME_SEARCH_ENABLED=true`.
- При сборке web: `VITE_BULK_VOLUME_SEARCH_ENABLED=true`.

По умолчанию флаги выключены. API отклоняет непустой поиск, если флаг выключен;
web скрывает поле. Прежний сценарий по диапазону сохраняется.
Не включать флаги и не переносить выпуск в проданную ВМС. Миграций нет.
Для публикации сначала сверить текущий runtime согласно release-workflow.md:
sourceParityVerified=false, поэтому полная локальная сборка не является готовым
образом для замены production. Этот PR содержит исходники и тесты.
