# Публикация «Проблемы FBO» на нашей ВМС

Согласованное совмещение с работающим сервером: production.patch применяется к исходникам образов live-before.json, не заменяет их файлами старой рабочей ветки. Сохраняются автосборка, плитки администрирования, печать, параллельная упаковка, быстрые подтверждения, перенос недобора и существующее отключение старого режима FBO. Политика FBO, DTO, складские операции и основной экран FBO остаются серверными. Новых миграций нет.

Новые возможности выключены без WMS_FBO_PROBLEMS_ENABLED=true; включение только на нашей ВМС. Проданную ВМС не обновлять этим выпуском.

Проверки кандидата: TypeScript API/web и сборки прошли; 62 API-проверки FBO на изолированной PostgreSQL, 256 web, отдельная проверка плиток — успешно. Полный набор старых тестов серверного образа имеет 205 падений, воспроизводимых на исходном образе. Первоначальные два дополнительных падения — устаревшие ожидания legacy fallback в перенесённых тестах; исправлены на проверку действующего серверного запрета. Производственный код этого запрета не изменён. Проверки полного серверного набора не являются зелёными; новых регрессий сравнение не выявило.

server-test-compatibility.patch применяется к интеграционному тесту рабочей ветки; AdministrationFboNavigation.spec.tsx запускается рядом с серверным AdministrationPanel. В сценарии повторного восстановления включены быстрые ответы и параллельная упаковка. Рабочая БД для изменений в тестах не используется.

Перед переключением контейнеров проверяются исходные image ID, неизменность окружения, сохранность остальных исходников и файлов сайта, включая Android и print-agent. После обновления проверяются запуск API, доступность интерфейса, список и состав FBO, отчёт и Excel в READ ONLY транзакции. При сбое проверки выполняется откат образов и нового флага.
