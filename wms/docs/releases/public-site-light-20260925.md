# Светлый внешний сайт LOGOFF

Только публичный экран до входа: светлые поверхности, контрастный текст,
крупные подписи, адаптивная навигация, актуальные сценарии и изображение
интерфейса в теме «Современная». AuthPanel, API, БД и ТСД не изменяются.
Проданная WMS не входит в выпуск.

Ветка: `feature/public-site-light-release-20260925`, база PR312.
`public-site-release.cjs` собирает только MarketingLanding с существующим React.
В опубликованном bundle заменяется ровно одна функция; остальной код сохраняется.
Ссылки ESM получают согласованные новые имена, чтобы ленивые разделы использовали
один React/entry module. Тела остальных модулей не меняются.
Старые assets не удаляются, уже открытые сеансы продолжают использовать их.

Проверки: 234/234 web, TypeScript, 3 проверки замены компонента,
4 проверки состава выпуска; сохранённый baseline проверен.
Готовый runtime проверен в браузере при 1440, 768 и 390 px: без горизонтального
переполнения, меню и выбор этапа работают; переход ко входу работает без
авторизации реальными учётными данными. Заголовки #172c37, основной текст #425864
на белых/светлых поверхностях. Изображение темы «Современная» загружается.
API/Android тесты не запускались: эти компоненты и их артефакты не изменяются.
Сравнения с эталонным скриншотом и измерений Core Web Vitals нет.

Выкладка: `deploy-public-site.py prepare` проверяет все старые публичные файлы
в дочернем образе. `publish` повторно сверяет production image/config и файлы,
пересоздаёт только web, проверяет публичный index и неизменность API container.
При ошибке автоматически возвращает предыдущий web image.
Откат: тег `logoff-web:before-public-light-20260925` → `infra-web`,
затем существующий compose `up -d --no-deps --no-build --pull never --force-recreate web`.
База API остаётся `2026-09-25-fbs-display`; после выпуска web требует
наложения сохранённого `proof.json` и нового внешнего bundle поверх этой базы.
