# Ozon: импорт по ссылке для клиента с несколькими кабинетами

14.10.2026. Подготовлено, не опубликовано.

У пользователя Королев Максим есть canRead/canWrite к обоим клиентам,
активные подключения Ozon и активная связь обоих клиентов с ФФ Москва.
activeWarehouseId отсутствует, что допустимо для клиентского кабинета.
Импорт по ссылке ошибочно требовал внутренний активный филиал; импорт файла
уже использовал корректный выбор филиала клиента.

Изменения:
- OzonLinkImportService.access использует OzonFboImportService.resolveWarehouse.
- connections проверяет права записи и наличие доступных филиалов, затем
  возвращает только активные кабинеты выбранного клиента без секретов.
- warehouseId передаётся из интерфейса через preview/commit в импорт файла.
  Выбранный филиал входит в хеш предпросмотра; изменение требует нового preview.
- Ошибка загрузки кабинетов отображается отдельно от пустого списка.
- Смена клиента/филиала сбрасывает форму и предыдущий предпросмотр.

Проверки авторизации сохранены: другой клиент, клиент только для чтения,
чужой кабинет и недоступный филиал запрещены. Сотрудник с ограничением по
филиалу по-прежнему обязан выбрать свой доступный активный филиал.
Если у клиента несколько филиалов, автоматического произвольного выбора нет.

Четыре новые регрессии воспроизведены до исправления, затем прошли.
API3437 passed /150 skipped; dedicated kiz*.integration.spec.ts исключены.
Web431 passed /2 skipped; API/web TypeScript noEmit прошли.
На рабочих данных в read-only транзакции сравнили текущий обработчик и
скомпилированный исправленный модуль: старый отказывает для обоих клиентов,
новый возвращает соответствующий Ozon-кабинет и определяет ФФ Москва.
Это проверка чтения, а не создание реальной заявки или публикация runtime.

Общие модули импорта затронуты. Расширения прав, изменения связей пользователей,
секретов API, схемы, остатков и реальных заявок нет. Проданную WMS не обновлять.
Будущий выпуск — точечный runtime delta от актуального production baseline,
сохранить остальные изменения Ozon. sourceParityVerified остаётся false.

Ветка fix/ozon-client-cabinet-access; PR в feature/wb-print-check. Публикация разрешена пользователем.

Добавлены подписи владельца из выбранного клиента: имя клиента, дополнительное
название кабинета (если есть), sellerId. Два теста подписей и браузерная проверка
обоих runtime entry points, переключения клиентов и передачи филиала прошли.
Веб-сборка сохраняет текущую точку входа cabinet-keys-20261014 и её экспортируемые
возможности; ссылки старого React entry перенаправлены на текущий через
существующий single-react-graph, чтобы не загрузить второй экземпляр React.
Runtime API — один модуль после проверки соответствия исходной версии;
resolveWarehouse уже существует в опубликованном JS (private действует только в TS).
