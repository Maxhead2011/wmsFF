# Отбор остатка короба целиком в частичном режиме

Подготовлен LOGOFF247, пока не опубликован. PR в feature/wb-print-check.

Ранее FboTwoStageScreen скрывал целый отбор в частичном режиме, даже если после выбора короба сервер присылал wholeBox=true. Теперь появляется «Забрать остаток короба целиком». Сотрудник вводит фактическое оставшееся количество, без уже отобранных единиц. Незавершённый скан ШК/КИЗ и требование актуализации блокируют действие. Поштучный отбор сохранён. После перезапуска неподтверждённый PICK_BOX сохраняет операцию и частичный режим.

Серверный код не меняется: опубликованный runtime проверяет количество, оставшуюся потребность, резервы, паллет, КИЗ и повтор операции. Уже отобранные поштучно единицы остаются wholeBox=false в FBO-PICK, оставшиеся — wholeBox=true в исходном коробе. Упаковка исходного короба учитывает только остаток; ранние отдельные единицы упаковываются отдельно. Смешанный состав сохраняет SKU и КИЗ каждой единицы. Исторические отборы не переклассифицируются.

Файлы: FboTwoStageScreen (showWholePicking, wholePickingTitle, confirmation and retry recovery), FboPickingModeTest, build.gradle.kts LOGOFF-only version; scripts/releases/fbo-partial-whole-20261030 tests/release; README, map, index. Проданные flavors сохраняют прежний UI и версии. На production меняются только три APK download-файла в точном overlay текущего web image; API, схема и складские данные не изменяются.

Проверки: воспроизводящий Android-тест RED/GREEN; количество остатка вместо исходного, незавершённый скан, разрешение/запрет wholeBox, восстановление pending операции. На фактическом runtime в отдельном PostgreSQL: 1 поштучно + 4 смешанных целиком, отклонение старого количества и FBS резерва, идемпотентный повтор, упаковка 4+1 и итоговый баланс 5; полный запуск Nest health. Полные API4096/web563, пропущены156/2, отдельный не настроенный KIZ DB suite исключён.

Финальная проверка: Android305 на каждый flavor (915), LOGOFF release/lintVital, API4096/web563, PostgreSQL9/full Nest health и baseline8 прошли. Исходный тест отсутствующей кнопки падал до изменения и проходит после. Неподтверждённый PICK_BOX сохраняет PARTIAL после пересоздания экрана. API baseline verify/materialize/check-candidate: изменений нет.
