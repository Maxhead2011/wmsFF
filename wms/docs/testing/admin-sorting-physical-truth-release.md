# Административная сортировка: объединение перед публикацией

Только наша WMS; prod/sold и FFULHAB не обновлять. Ветка `fix/admin-sorting-physical-truth-20260909`, PR в фактическую release-ветку `fix/sorting-recorded-source-20260908` (сверена по PR 81–84).

## Область и риск

- `inventory/pallet-sorting.service.ts`: start/includeScannedSource/openTarget/move/previewInTx/archiveSources/resetAffectedRoutes/assertMovementAllowed — административное подтверждение физического положения. Высокий риск учёта; одна Serializable-транзакция, точная идентичность КИЗ, явное подтверждение недостачи, аудит, переопределение только в этом меню.
- `inventory/pallet-sorting-policy.ts`, `pallet-sorting.controller.ts`, web `lib/workspaces.ts`: доступ ADMIN без дополнительного stock:write; demo/скрытые клиенты/feature flag остаются. Средний риск доступа.
- `stock/stock-operations.service.ts`: только адаптер `reconcileAdminSortingUnit`; обычные перемещения/FBS не изменяются.
- `stock/sorting-admin-unit-reconciliation.ts`: источник, целевой короб, перенос единственной единицы, дедупликация, идемпотентность, audit. Высокий риск остатков.
- `inventory/inventory.service.ts`: decideLine не применяет старый пересчёт поверх административного перемещения после начала пересчёта. Средний риск, изолировано флагом WMS_PALLET_SORTING_ENABLED.
- `stock/sorting-admin-sku-receipt.ts`: дополняет физическое перемещение подтверждением приёмки исходной SKU_COLLECTION. Сам остатков не создаёт. Средний риск счётчиков, атомарность вместе с движением.

## Разрешение конфликтов (подтверждено Константином)

Сохранены свежие функции PR 81–84: повторное открытие закрытого назначения, пополнение непустого назначения с его текущим количеством, отдельная обработка некорректного отрицательного остатка при завершении, вывод удержанных расхождений, исходный API приёмки SKU_COLLECTION. Новая административная операция использует свой общий учёт и дополнительно закрывает исходный PICKED scan, чтобы нормальная приёмка не смогла повторно принять тот же товар.

Убраны прежние тестовые ожидания, запрещавшие ADMIN восстанавливать архивный/перемещённый целевой короб: это прямо изменённое пользователем правило. Проверки конкурирующих сессий, исходного короба как назначения, исчезнувшего закрытого назначения, отрицательного остатка сохраняются. Тесты неопубликованного `pallet-sorting-postgres.cjs` не включаются.
