# Клиентский доступ к повторной отгрузке WB

Дата: 2026-09-11. Ветка `fix/wb-reshipment-client-access`, исходный HEAD `82285e870249f206f6a429bec83af27bf1f06da4`.
Константин подтвердил Gate 1: клиенту доступны SAME_ITEM и NEW_ITEM после явного подтверждения. Gate 2 и публикация через PR подтверждены сообщением «публикуй».

## Контракт и влияние

- Новый `fbs-reshipment-access.ts`: CLIENT требует `client-requests:write`, явное пересечение читаемых/записываемых client IDs, отсутствие скрытого клиента. CLIENT+ADMIN, ALL и system:admin не расширяют область клиента. ADMIN/OWNER сохранены; demo запрещён.
- `fbs-reshipment.controller.ts`: допускает одно из `clients:write` / `client-requests:write`, затем сервис применяет отдельную политику.
- `fbs-reshipment.service.ts`: capabilities/authorize используют политику; активный доступный для записи филиал, ownership операции и проверки перед WB-записью сохранены. Комментарий новой заявки корректно говорит «подтверждён пользователем».
- `marketplace-connections.service.ts`: отдельный `readReshipmentWbStatuses`, минимальное выделение общего HTTP-чтения. Старый `readRepeatAssemblyWbStatuses` сохраняет административный emergency guard.
- `FbsReshipmentPanel.tsx`: CLIENT видит инструмент для явно своего записываемого клиента; изменения прав и областей сбрасывают старую проверку/подтверждение.
- Тесты: четыре API spec, web spec, существующие браузерный сценарий и синтетический fixture.
- Права на API-ключи, общие роли, миграции, остатки, КИЗы и APK не менялись. Наше окружение отдельно; проданное/FFULHAB не затрагиваются. Сохранён default-off `WMS_FBS_RESHIPMENT_ENABLED`; shared API/web исходники должны попадать только в выпуск нашей WMS.
