# Подтверждение печати без ожидания начислений

После подтверждения этикетки SOS WB обработчик `finishFbsPrintJob` сохранял
печать и отгрузку, затем ожидал пересчёт начислений по всей истории клиента.
Windows-агент не запрашивал следующую этикетку до завершения этого запроса.

Теперь отгрузка и задание `FbsPrintBillingOutbox` сохраняются в одной транзакции.
Ответ агенту по-прежнему требует успешной фиксации отгрузки. Фоновый обработчик
вызывает прежний `ensureFbsProcessingCharges`, сохраняя его блокировку БД,
правила расчёта и защиту от повторных начислений.

Очередь объединяет задания по клиенту. Счётчик revision защищает новую печать,
поступившую во время расчёта. Обработчик забирает задание условным обновлением
и получает уникальную аренду на 5 минут. При аварии аренда истекает; устаревший
обработчик не может удалить задание нового. Ошибки повторяются с паузой от
5 секунд до 5 минут, без ограничения числа попыток; текст последней ошибки
остаётся в записи, а предупреждение — в журнале API. После рестарта очередь
читается из БД, без зависимости от памяти процесса.

## Область применения и выпуск

- Ветка исправления: `fix/print-ack-billing-outbox`.
- База PR: `fix/fbs-transfer-started-at`, действующая ветка серверных исправлений
  нашей ВМС; исходное состояние `2dba511` совпадает по файлам с её merge `71bab4a`.
- Новая логика работает только при `WMS_WB_ORDER_STOCK_LIFECYCLE_ENABLED=true`.
  При выключенном флаге проданная ВМС не запускает обработчик и не обращается
  к новой таблице. Схема меняется только добавлением таблицы.
- Перед запуском новой API-сборки применить миграцию
  `20260916170000_fbs_print_billing_outbox` и сгенерировать Prisma Client.
  При подготовке образа сохранить актуальные параллельные серверные исправления.
- Windows-агент и ТСД для этой правки переустанавливать не нужно.
- При откате API таблицу не удалять: незавершённые задания должны остаться для
  повторного выполнения после восстановления обработчика. Не отключать учёт
  отгрузок ради отката ускорения печати.
- После публикации проверить успешные ответы `/fbs/print-jobs/:id/result`,
  получение следующего задания, завершение записей очереди и отсутствие повторных
  начислений. `printedAt` подтверждает результат агента, а не физический выход бумаги.

## Проверки

Новый регрессионный тест до правки падал: обработчик вызывал начисления напрямую
и не сохранял задание. После правки проверяется независимость ответа от начислений,
обязательное сохранение задания и отсутствие новой логики при выключенном флаге.

Тесты PostgreSQL проверяют откат транзакции, восстановление обработчика, объединение
заданий, новую печать во время расчёта, ошибку с повтором, конкурентный захват,
истёкшую аренду и защиту от устаревшего обработчика. Отдельный тест вызывает
настоящий расчёт начислений, имитирует сбой после его коммита и подтверждает,
что повтор не меняет счета, не дублирует начисления и не списывает товар снова.

Команды из `wms/` после подключения `work/dev-env.ps1`:

```powershell
$env:WB_LIFECYCLE_TEST_DATABASE_URL='postgresql://codex_tests@127.0.0.1:55469/wb_lifecycle_tests'
$env:KIZ_DUPLICATE_TEST_DATABASE_URL='postgresql://codex_tests@127.0.0.1:55469/kiz_duplicate_tests'
pnpm --filter @logoff/wms-api exec vitest run --maxWorkers=4 --minWorkers=1 --testTimeout=15000
pnpm --filter @logoff/wms-api build
pnpm --filter @logoff/wms-web test
```

Используются только выделенные локальные тестовые БД. Миграция новой таблицы
проверена локально. Измерение задержки на рабочем принтере выполняется после
публикации; локальные тесты не гарантируют время физической печати.
