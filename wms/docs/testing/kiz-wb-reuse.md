# Проверка прежнего использования КИЗа

Изменения включаются только флагами `WMS_KIZ_REUSE_EVIDENCE_ENABLED=true` на API и
`VITE_KIZ_REUSE_EVIDENCE_ENABLED=true` при сборке нашей ВМС. Для проверки администратора
также нужен существующий `WMS_KIZ_LOCATION_CHECK_ENABLED`. По умолчанию новая логика выключена.

## Решения

- `ALLOW`: нет истории либо все исторические заказы подтверждённо отменены продавцом,
  WB сообщает отмену, текущая маркировка заказа не содержит этот КИЗ, поставка не имеет
  подтверждения приёмки, True API отвечает `INTRODUCED`, локальная привязка к прежней сборке снята.
- `RELABEL`: True API подтверждает `RETIRED`/`WRITTEN_OFF`, либо актуальные метаданные WB содержат
  именно этот серийный КИЗ и WB подтверждает продажу или отмену после приёмки поставки.
- `REVIEW`: остальные случаи, включая сбой/неполный ответ внешних API, отсутствие подключения
  Честного знака, сохранившуюся привязку к сборке, исходную единицу в повторном заказе с другим КИЗом.

Одной локальной записи SHIPPING, печати этикетки или принятия КИЗа через API недостаточно.
Продажа повторного заказа с другим серийным кодом не доказывает продажу исходной единицы.
Нет изменений в восстановлении остатков, списании, блокировках качества и аренде задания.
Плановая переклейка при замене размера сохраняет существующий механизм.
Старое сохранённое предложение переклейки перепроверяется перед применением.

## Отображение и журнал

Отдельная плитка «Проверка КИЗов» доступна администраторам в меню КИЗ нашей ВМС.
Экран ТСД использует тот же авторизованный поиск. История показывает первую известную запись,
заявку ВМС, заказ и поставку WB, сотрудника, вид события и дату/время (МСК).
Время завершения сборки и время локальной отгрузки подписаны отдельно и не выдаются за
неизвестное точное время отправки метаданных WB. Номера заявок других филиалов не раскрываются.
Результат проверки при сборке записывается в `AuditLog` (`KIZ_REUSE_CHECK`).

## Проверки

Регрессии: `kiz-wb-reuse.spec.ts`, `kiz-wb-reuse-guard.spec.ts`,
`KizCheckPanel.spec.tsx`, `KizLocationPolicyTest`.
Проверяются разрешение только при полном подтверждении, отказ при неопределённости,
несовпадение КИЗа повторной сборки, журнал решения, первая заявка, дата МСК и изоляция проданных версий.
Полные результаты локального запуска: `work/kiz-history-validation/`.

Итог: API — 2733 прошли, 60 предусмотренных условиями окружения пропусков; веб — 208 прошли;
ТСД — 930 прошли в шести вариантах. TypeScript API и веб проверены без ошибок.
API проверялся с Prisma-клиентом, отдельно сгенерированным из схемы этой ветки, и отдельной
локальной PostgreSQL (`127.0.0.1:55469/kiz_duplicate_tests`). Рабочая БД не использовалась.
PR предлагается из `feature/kiz-wb-history` в `fix/historical-packing-client-free-stock`.

Публикация и включение флагов выполняются отдельно после проверки PR и интеграции
с актуальными опубликованными исходниками API, веб-приложения и ТСД.
