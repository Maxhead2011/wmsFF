# WB: перенос из доставки через расширение

Ветка: `fix/wb-delivery-transfer`, база `de088f3`, PR в `feature/billing-period-register-20260910`.

## Воспроизведение

Публичное добавление заказа в новую поставку возвращало 409 для заказа `complete/waiting`
из поставки в доставке. Кабинет WB успешно выполняет другой запрос — `orders/transfer`
к исходной поставке — с перевыпуском стикера.

До исправления 4 новых теста сервиса завершались ошибкой: публичный PATCH продолжал
вызываться, состояния ожидания браузера и одноразовой выдачи команды не существовало.
Отдельный тест кэша падал: `complete/waiting` оставался в кэше после подтверждённого возврата.

## Покрытые ограничения

Точный состав и источник, новый стикер, доступ к клиенту/филиалу, запрет после физического
сканирования, запрет WB/isTransferable=false, выключенная функция, неверный кабинет,
смена кабинета во время запроса, повторный клик, restart worker, другой документ/вкладка,
истёкшая команда, изменившийся runtime WB, 409/неполный ответ, автоматический SDK retry.
Кэши посторонних заказов и кабинетов сохраняются. Складские движения не создаются.

## Тайм-аут биллинга при подготовке переноса

Для заказа 5675266516 / заявки 686 сервер возвращал HTTP 500 ещё до создания
журнала переноса: loadFbsOrdersUncached вызывал пересчёт начислений и счетов,
который завершался P2028 / истечением 60-секундной транзакции.

При WMS_FBS_NO_STOCK_TRANSFER_ENABLED=true подготовка, перенос, восстановление
и завершение используют загрузку без пересчёта счетов. Актуальные проверки WB,
прав доступа, остатков и физической обработки сохраняются. Сохранённые суммы
используются только для отображения; такой ответ не заменяет общий финансовый
кэш и не ожидает уже запущенный пересчёт. При выключенном флаге путь прежний.

До правки: 2 новых теста упали, 1 прошёл. После правки добавлена также проверка
точки входа prepareFbsStockTransfer с включённым/выключенным флагом.
Полный прогон: API 2194 passed / 10 skipped, Web 183 passed, расширение 8 passed.
API build и git diff --check успешны. Web/расширение в этой правке не менялись.

Повторная попытка оператора создала операцию c3ce5e9a-49d6-40bb-a0b9-b3e9db7f20f0
и пустую целевую поставку WB-GI-277351827, но обычный API WB вернул 409.
На 12 сентября 2026, 13:50 UTC серверный код PORTAL_READY отсутствует,
WMS_WB_PORTAL_TRANSFER_ENABLED не задан. Чтением WB подтверждено: заказ всё ещё
в WB-GI-274299916 (5 заказов), целевая поставка пуста. Установка расширения
подтверждена пользователем, но управление открытым Яндексом недоступно в этой
сессии; сквозная проверка в пользовательском браузере не выполнена.
