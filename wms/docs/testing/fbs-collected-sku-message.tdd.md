# FBS: сообщение о полностью собранном SKU

Задача Константина: при сканировании короба, товар из которого больше не нужен заявке, объяснять выполненную потребность, а не требовать короб следующего заказа. Исходный пример — заявка 728.

## Изменения и риск

- `apps/api/src/modules/marketplace-connections/fbs-collected-box-message.ts`: новый read-only модуль. Сверяет точные SKU положительного AVAILABLE в коробе с текущими строками заявки и COMPLETED-заданиями с completedAt. Сопоставление по requestItemId и skuId, не по артикулу. Остатки/заказы не изменяются.
- `apps/api/src/modules/marketplace-connections/marketplace-connections.service.ts`, `scanFbsTsdBox`: после безуспешного переключения на другие заказы и только при отсутствии текущего SKU заменяет текст ошибки. API-код FBS_WRONG_BOX сохраняется для совместимости ТСД.
- `apps/api/test/fbs-collected-box-message.spec.ts`: 20 проверок через реальную точку сканирования с подменёнными внешними зависимостями.
- `apps/api/test/fbs-collected-box-message.coverage.cjs`: native Node coverage собранного read-only модуля.

Изоляция: `WMS_FBS_COLLECTED_SKU_MESSAGE_ENABLED=true`, по умолчанию выключен. Проданная WMS без флага сохраняет старое поведение. Не меняются отбор, перераспределение резервов, маршрутизация, операции КИЗ, APK и остатки.

## Правило сообщения

> Нужное количество этого товара уже собрано по заявке (2 из 2 шт.). Больше брать из этого короба не нужно. Можно отсканировать другой короб или паллетсорт с ещё нужным товаром.

Для нескольких полностью собранных SKU используется «этих товаров». Сообщение НЕ выдаётся при оставшейся потребности, несовпадении размера/SKU, отсутствующих строках заявки, неподтверждённой сборке, превышении количества, пустом коробе или неоднозначной переклейке. Если переключение на нужный заказ успешно, новая проверка вообще не вызывается.

## Перед публикацией

Ветка `fix/fbs-collected-sku-message` создана от `fix/noginsk-receipt-client-history`; для узкого stacked PR использовать эту базу. При подготовке production-релиза брать только коммит этой задачи, не включать неутверждённые изменения приёмки заодно.

В текущем production API есть дополнительные изменения, отсутствующие в локальном монолитном сервисе. Нельзя заменять весь service.ts локальной копией: переносить только импорт и локальный блок сообщения поверх актуального live-исходника, плюс новый модуль. Не перестраивать API из устаревшего серверного Git checkout. Включить флаг исключительно в WMSFF2207 после согласованной публикации.
