# ФБО: привязка КИЗа при поштучном отборе

Настройка `WMS_FBO_PICK_BIND_KIZ=true` включает поведение только для выбранного развёртывания. По умолчанию выключена; проданную ВМС не обновлять. Требуется существующее включение двухэтапной сборки ФБО. Миграций и обновления ТСД нет.

`FboTwoStageService.act(PICK_UNIT)` вызывает `bindPickedMark` внутри той же Serializable-транзакции, что и списание одной единицы AVAILABLE → PACKING. Скан должен содержать корректный КИЗ и соответствовать ШК нужной позиции заявки.

- Отсутствующий КИЗ регистрируется к товару клиента и фактическому коробу. Без доступного остатка и без прежнего подтверждения единицы операция откатывается.
- Существующая привязка к другому коробу исправляется. Если остаток сохранился по прежнему адресу/статусу, сначала перемещается именно он: повторного списания двух единиц нет.
- Ранее отобранный или отгруженный КИЗ восстанавливается по физическому скану. Если учётного остатка больше нет, восстановление отражается отдельной INVENTORY_ADJUSTMENT перед отбором.
- Незавершённая прежняя единица ФБО помечается RETURNED; предыдущая сборка возвращается к PICKING, подтверждение её затронутого упаковочного короба снимается. Завершённая история ФБО не переписывается.
- Прежнее незавершённое задание FBS переводится в RELEASED с объяснением причины. КИЗ и ссылка на прежний заказ сохраняются. Завершённые задания и история отгрузок остаются прежними.
- Повторное сканирование уже отобранного КИЗа в той же заявке запрещено. Повтор запроса с прежним operationId идемпотентен.
- Другой клиент, товар, филиал, дубли КИЗа и активная инвентаризация требуют отдельного разбора.

Журнал `FBO_PICK_KIZ_BOUND` содержит КИЗ, прежнюю привязку, предыдущие задания FBS/единицы ФБО и признак восстановления. Журнал и все изменения откатываются при неудачном списании.

Проверки: `apps/api/test/fbo-two-stage.integration.spec.ts` на изолированной локальной PostgreSQL. `FBO_TEST_DATABASE_URL` допускает только `codex_tests@127.0.0.1:55469` либо `55485`, базу `kiz_duplicate_tests`. Второй порт нужен, когда первый зарезервирован Windows.
