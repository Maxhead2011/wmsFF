# Замена размера WB в Сервисе

Новый инструмент доступен только ADMIN/OWNER с правом записи клиента и выбранного филиала.
Выбор клиента — существующий переключатель Сервиса. По номеру находится ровно одна
текущая попытка WB в этом филиале. Уже физически отобранные, упакованные, отменённые и закрытые
заказы не преобразуются в новую физическую сборку.

Соседние размеры того же артикула и цвета предлагаются первыми. Более отдалённые
показываются только при отсутствии свободных соседних. Учитываются явные
ClientArticleMapping при включённой переклейке клиента. Диапазоны вроде M–L и
неизвестные размеры не угадываются. Учитывается AVAILABLE в активных коробах на
паллетах, за вычетом текущих резервов FBS. Предварительный результат не резервирует товар.

Создание повторно читает WB (new/confirm/complete + waiting), затем заказ, привязку, SKU,
остатки и резервы в Serializable-транзакции. Изменившийся результат требует нового
подбора. Создаётся одна IN_WORK заявка с заданием переклейки; существующая
неотсканированная попытка переносится в неё. Исходная заявка теряет одну единицу
и получает событие переноса. В журнале сохраняются прежние task/link и согласовавший.
Повторная отправка возвращает ту же заявку. Остатки, марки и WB при создании не меняются.

sourceSkuId/sourceBarcodes и relabelRequired включают существующий путь отбора и
переклейки. Таблица FbsSizeSubstitution сохраняет согласование для конкретной попытки,
заявки, филиала и пары SKU. Фоновая отмена WB продолжает освобождать резерв;
фоновое перепланирование не подменяет согласованный источник. Списание происходит
при физическом сканировании штатным механизмом, не в данном инструменте.

## Установка

Применить миграцию 20260920090000_fbs_size_substitution перед включением
WMS_FBS_SIZE_SUBSTITUTION_ENABLED=true только на нашей ВМС. Значение по умолчанию false:
меню скрыто, создание запрещено, дополнительное чтение согласований не выполняется.
Не отключать обработку согласований до завершения активных заявок с заменами.
Существующие исключения 1049/1099 при публикации сохранить из текущей серверной версии.
Не перезаписывать сервер целиком из этой ветки: другие опубликованные изменения могут
отсутствовать в базовой ветке. Нужна проверка совместимости серверного патча.

## Проверки

- test/fbs-size-substitution.spec.ts: правила размеров/прав, настоящая PostgreSQL,
  сохранение источника в TSD, отсутствие списания, повторный запрос,
  конкуренция за последнюю единицу, отмена/начало сборки, изменение остатков.
- test/administration-internal-api.service.spec.ts: регистрация трёх API-методов.
- apps/web/test/size-substitution-browser.mjs: настоящий компонент в браузере с
  изолированным API; подтверждение переклейки, создание, сброс при смене заказа.
- Полные API/web Vitest и обе TypeScript-проверки перед коммитом.

Для интеграционных тестов SIZE_SUBSTITUTION_TEST_DATABASE_URL допускает только
postgresql://codex_tests@127.0.0.1:55481/done_packing_tests. Миграция применяется
заранее. Никаких производственных учётных данных в тестах нет.
