# FBO: голосовые подсказки и ручное добавление

Ветка feature/fbo-manual-packing создана от feature/fbo-packing-voice (основание feature/fbo-packing-mode-choice).

Наш Android flavor logoff озвучивает шаги новых коробов и ручного добавления офлайн женским голосом: «Отсканируйте короб», «Отсканируйте ШК», «Отсканируйте КИЗ», «Положите в короб». Последняя фраза звучит только после успешного ответа API. Повторные перерисовки не повторяют фразы, ошибки и неподтверждённые запросы не подтверждают упаковку.

Для ручного режима требуется WMS_FBO_MANUAL_PACKING_ENABLED=true совместно с существующим WMS_FBO_TWO_STAGE_ENABLED=true. По умолчанию новая возможность выключена; plan возвращает manualPackingEnabled. В проданной ВМС не включать. Общие модули API/Android затронуты, старое поведение изолировано флагом API и flavor logoff.

В меню упаковки появляется «Добавить товар вручную». MANUAL_OPEN_BOX открывает пустой или уже открытый упаковочный короб данной заявки. Закрытые короба и целые отобранные короба не дополняются. Далее сканируются ШК и КИЗ; MANUAL_PACK_UNIT определяет исходный короб по точному физическому КИЗу.

Если единица уже отобрана в эту заявку, перемещается из FBO-PICK в короб упаковки без второго списания из AVAILABLE. Если единица ещё AVAILABLE, отбор и упаковка выполняются одной serializable-транзакцией: расход из фактического исходного короба, приход PACKING в целевой, перенос конкретного ProductMark и FboAssemblyUnit. При отсутствии спроса количество строки увеличивается на 1; отсутствующий товар добавляется новой строкой. Состав и его контрольная сумма обновляются атомарно. История FBO_MANUAL_PICK_RECOVERED содержит сотрудника, КИЗ, источник, назначение и увеличение количества.

Повтор operationId идемпотентен. Повторный КИЗ, чужой клиент/филиал, несовпадение ШК, неизвестный/отгруженный КИЗ, недостаток остатка или занятый короб отклоняются без частичных изменений. Общие блокировки актуализации и правила физических резервов сохраняются.

Ручное добавление требует физического сканирования: товар, вообще не просканированный сотрудником, автоматически обнаружить невозможно. Дополнительная пересканировка всего содержимого перед закрытием этим изменением не вводится.

Проверки: FboPackingVoiceTest, FboScanFeedbackTest, FboTwoStageScreenTest; fbo-two-stage.integration.spec.ts на отдельной локальной БД kiz_duplicate_tests (127.0.0.1:55485); полный API/Android прогон и TypeScript. Без миграции БД. Публиковать APK только поверх актуального Android-релиза; версия старого checkout не является новой версией выпуска.

Итог проверки 19.09.2026: API 2693 passed, 38 skipped; Android 852 passed (6 вариантов); TypeScript --noEmit и assembleLogoffDebug успешно. Локальная БД 55485 доступна тестам через временный loopback-прокси 55469, после прогона он остановлен. Новый тест на исходном серверном коде падает с «Неизвестное действие», на исправленном проходит. Аналогично проверено отсутствие голосовых подсказок на исходном Android-коде.
