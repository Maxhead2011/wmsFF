# FBS: зависание «Собрать / Передаю…» — 2026-09-18

## Причина и границы

`assembleFbsOrders` и `moveFbsOrdersToSupply` повторно загружали общий каталог,
после записи поставки ожидали ещё одну полную синхронизацию. Предыдущее
ускорение `createFbsRequest` этот маршрут не меняло.

Изменены только сервис маркетплейсов, обработчик подтверждения сборки в
`FbsPanel`, тип ответа и регрессионные тесты. Миграций и исправлений данных нет.
Проданное окружение / FFULHAB не изменяются.

## FIX

- Новый флаг `WMS_FBS_FAST_ASSEMBLY_ENABLED=true`, по умолчанию выключен.
- Выбранные заказы проверяются один раз; общий биллинг и история не входят
  в ожидание WB-сборки. Актуальные статусы, права клиента, проверка точного
  состава поставки, сохранение плана и грузомест остаются обязательными.
- Ответ WB-сборки содержит `ordersPartial: true`; интерфейс объединяет строки
  по кабинету и ID, не удаляя остальные заказы, запускает обновление отдельно.
- Частичный ответ не перезаписывает общий серверный каталог. Метаданные
  выбранных заказов сохраняются для следующей проверки после исчезновения
  из `/orders/new`, без продления срока свежести полной истории.
- Повторная отгрузка сохраняет старый путь. Для Ozon сохраняется существующая
  отправка; при включённом флаге первоначальная загрузка также ограничена выборкой.
