# Администрирование: проблемы FBO

Изолированный инструмент для OWNER и ADMIN. ADMIN получает доступ только к единственному закреплённому в UserWarehouse филиалу с canRead/canWrite; переключатель филиала в шапке не расширяет права. Проверка ролей, статуса пользователя и филиала выполняется в БД при каждом запросе. Клиентам, сотрудникам и демо-пользователям инструмент недоступен.

## Включение

По умолчанию выключен. Только на нашей ВМС устанавливаются `WMS_FBO_PROBLEMS_ENABLED=true` и существующий `WMS_FBO_TWO_STAGE_ENABLED=true`. Для завершения неполного отбора требуется `WMS_FBO_CLOSE_PICK_ENABLED=true`. На проданной ВМС новый флаг не устанавливать: сервер отклоняет операции, интерфейс скрывает плитку по capabilities.

Ветка сохраняет обе согласованные логики: ручная/повторная упаковка и завершение отбора с недобором. Перед выпуском проверить историю миграций: включена существующая миграция `20260919020000_fbo_pick_closure`. Если колонка уже была добавлена прежним выпуском, не выполнять ALTER повторно; сверить применённую миграцию штатным процессом выпуска. Схема новых таблиц для раздела не требуется.

## Действия

- Завершить отбор по факту: сохранить исходный заказ, зафиксировать количество к упаковке.
- Добавить выбранные целые короба.
- Восстановить упаковку выбранных отобранных единиц в существующий короб поштучной упаковки. Перенос только PACKING → PACKING, без второго списания AVAILABLE; прежнее подтверждение целевого короба снимается.
- Разобрать выбранные целые короба в поштучную упаковку.
- Подтвердить выбранные короба, проверив остатки и КИЗ каждого. Ошибка одного короба откатывает пакет целиком.
- Завершить упаковку через штатный сервис; проверить построение файлов товаров и распределения WB до фиксации транзакции. Файлы доступны для повторного скачивания.
- Отменить одно доказанное ошибочное списание из контроля фантомных остатков. Требуются движение −1 PACKING, одна упакованная единица с заблокированным КИЗ, связь с предыдущим движением данной сборки, отсутствие последующих движений и расхождение ровно 1. Создаётся компенсация +1 PACKING; исходное списание и прошлые отгрузки сохраняются. Другие случаи требуют индивидуальной сверки.

Причина и подтверждение физического факта обязательны. Сервер хранит предпросмотр 10 минут, сравнивает ревизию состава/остатков/КИЗ, блокирует заявку, выполняет операцию в SERIALIZABLE-транзакции и записывает результат до/после в AuditLog и комментарий заявки. Повтор того же токена возвращает сохранённый результат. Новая попытка с конфликтом сериализации повторяется только после отката.

## Отчёт

Отдельный экран и Excel: короб, паллет при отборе, сотрудник, время МСК, способ отбора, количество, состояние упаковки и целевой короб. Одинаковые фильтры сотрудника, паллета, дат и состояния действуют на экран и Excel. Новые отборы фиксируют паллет в той же транзакции. Старые события используются только при однозначном совпадении сотрудника, источника и времени транзакции; отсутствующее местоположение — «Не зафиксирован». Текущее расположение не подставляется в историю.
