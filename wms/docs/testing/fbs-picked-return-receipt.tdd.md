# Повторная приёмка изъятых товаров FBS — 2026-09-06

## Задача и границы

Константин подтвердил: после физического отбора отменённый товар нужно заново
принимать в бокс, а не автоматически восстанавливать в исходном месте.
Продолжение `permanent-storage-box-lifecycle.tdd.md`, исходный коммит `1151be8`.
Рабочая ветка: `fix/fbs-picked-return-receipt`.

Поведение включается только при `WMS_PERMANENT_STORAGE_BOXES_ENABLED=true`.
Значение по умолчанию остаётся false. FFULHAB/проданную WMS не менять и флаг
там не включать. Production и реальные остатки в этой задаче не изменялись.

Реализован путь **поштучного WB-возврата до закрытия отгрузки** через существующий
раздел проблемных заказов онлайн-заявки: «Принять возврат в бокс».
Сканируются бокс назначения, ШК и, для маркированного товара, тот же полный КИЗ.
Новый endpoint, статус БД, миграция и Android APK не требуются.

**Не реализовано:** приёмка через обычный экран новой приёмки ТСД, многотоварные
заказы, Ozon и возвраты после DONE. При включённом флаге такие физически
отобранные заказы не разрешается молча возвращать старым действием менеджера;
API сообщает об отдельной проверке/поштучном учёте, остатки не меняет.
Это ограничение нужно учитывать до включения флага, не выдавать за готовую
универсальную приёмку всех возвратов.
