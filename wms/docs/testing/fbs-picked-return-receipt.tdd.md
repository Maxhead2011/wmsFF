# Повторная приёмка изъятых товаров FBS — 2026-09-06

## Задача и границы

Константин подтвердил: после физического отбора отменённый товар нужно заново
принимать в бокс, а не автоматически восстанавливать в исходном месте.
Продолжение `permanent-storage-box-lifecycle.tdd.md`, исходный коммит `1151be8`.
Рабочая ветка: `fix/fbs-picked-return-receipt`.

Поведение включается только при `WMS_PERMANENT_STORAGE_BOXES_ENABLED=true`.
Значение по умолчанию остаётся false. FFULHAB/проданную WMS не менять и флаг
там не включать. Production и реальные остатки в этой задаче не изменялись.

Реализован путь **поштучного WB-возврата до закрытия отгрузки** через существующий
раздел проблемных заказов онлайн-заявки: «Принять возврат в бокс».
Сканируются бокс назначения, ШК и, для маркированного товара, тот же полный КИЗ.
Новый endpoint, статус БД, миграция и Android APK не требуются.

**Не реализовано:** приёмка через обычный экран новой приёмки ТСД, многотоварные
заказы, Ozon и возвраты после DONE. При включённом флаге такие физически
отобранные заказы не разрешается молча возвращать старым действием менеджера;
API сообщает об отдельной проверке/поштучном учёте, остатки не меняет.
Это ограничение нужно учитывать до включения флага, не выдавать за готовую
универсальную приёмку всех возвратов.

### Уточнение: бокс — постоянная перезаполняемая ячейка (06.09.2026)

Константин подтвердил: нулевое количество не означает конец жизненного цикла
бокса. Он сохраняет идентификатор, активность, паллет-сорт и зону до ручного
удаления; приёмка может повторно наполнить ту же ячейку. Отменённый изъятый товар
попадает в неё только по новой приёмке. Автоматического восстановления старых
остатков/архивированных боксов не выполняем.

В `reserveCompletedWildberriesStock` под opt-in флагом воспроизведены live-защита
`sourceBoxPending` и boxless PACKING. Live-очистка одноразового исходного короба
сохранена, но постоянная ячейка исключена до попытки архивирования/отвязки.
В `returnCompletedWildberriesStockReservation` приёмка распознаёт и старый
box-linked резерв, и текущий boxless резерв. История сначала неттируется по
местоположению; погашенные прошлые попытки не выбирают неправильный источник,
противоречивые активные резервы отклоняются до изменения остатков. Без сканов
изъятая отмена остаётся RETURN_REQUIRED. Неизъятый rollback при включённом флаге
сохраняет live-поведение «без короба», а не восстанавливает историческую ячейку.

Точки изменения: один production-модуль (две функции), три существующих файла
тестов и этот документ. Sold/default-off поведение оставлено прежним. Миграций,
новых зависимостей и массовых операций нет. Новые комментарии `// FIX`, `// TEST`.
