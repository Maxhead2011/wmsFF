# Очередь проверки КИЗов и решения администратора

Ветка `feature/kiz-review-queue`, основана на проверке истории КИЗов (PR 242).
Цель PR: `fix/historical-packing-client-free-stock`.

## Работа

При остановке FBS из-за спорной истории КИЗа создаётся `KizReviewCase`.
Повторные сканы одной единицы в одном задании обновляют обращение, сохраняя счётчик.
Ошибка сканирования не откатывает обращение. Очередь автоматически обновляется в
«КИЗы → Проверка КИЗов → Обращения сборщиков».

Администратор/собственник может принять решение как в ВМС, так и после сканирования
этого КИЗа в «Проверке КИЗ» на ТСД:

- «Разрешить использовать»: обязательное основание и подтверждение ручной проверки,
  что физическая единица находится на складе, КИЗ не погашен и пригоден для использования.
  Подтверждённая продажа/погашение запрещает это действие. Занятая чужая привязка,
  неподходящий короб, отсутствие остатка или закрытая заявка также запрещают разрешение.
- «Разрешить переклейку»: только при свежем подтверждении необходимости переклейки.
  Сборщик повторяет скан старого КИЗа, затем сканирует свободный новый КИЗ в существующем
  сценарии ТСД. Полная актуализация короба не требуется. Остаток по количеству неизменен,
  старая маркировка блокируется с сохранением истории, новая записывается к этой единице.

В решении сохраняются сотрудник, время, основание, подтверждение и данные проверки.
Разрешение связано с контекстом конкретного задания (заказ, клиент, товар, короб,
сборщик, начало попытки), автоматически теряет силу при изменении этого контекста.
Принятие КИЗа или замена использует разрешение. Повторная отправка решения идемпотентна.
Разрешение само по себе не отправляет КИЗ в WB и не гарантирует приём API WB: действующие
проверки сборки, ответов WB, количества и активных привязок сохраняются.

Чужие филиалы и клиенты исключены из выдачи, в том числе из вложенной истории.

## Изоляция и установка

Только наша ВМС: `WMS_KIZ_REUSE_EVIDENCE_ENABLED=true`,
`WMS_KIZ_REVIEW_QUEUE_ENABLED=true`, `WMS_KIZ_LOCATION_CHECK_ENABLED=true`.
Веб: прежний `VITE_KIZ_REUSE_EVIDENCE_ENABLED=true` и новый
`VITE_KIZ_REVIEW_QUEUE_ENABLED=true`. Переклейка требует прежнего флага
`WMS_FBS_KIZ_RELABEL_ENABLED=true`. По умолчанию новая очередь выключена.
ТСД показывает решения только в варианте logoff для ADMIN/OWNER/SUPER_ADMIN;
API повторно проверяет роли и права записи по клиенту и филиалу.

Перед включением нужна миграция `20260921170000_kiz_review_queue` и генерация Prisma.
Миграция создаёт только новую таблицу и индексы, без изменения остатков.
Для уже зарегистрированных ошибок предусмотрен скрипт
`apps/api/scripts/backfill-kiz-review-queue.cjs --since <ISO>` (сначала dry run),
затем тот же вызов с `--apply`. Он перечитывает текущую историю, создаёт обращения,
не разрешает использование автоматически и не меняет складские движения.
Новые ошибки поступают автоматически без этого скрипта.

При публикации наложить изменения на актуальные опубликованные источники:
сохранить защиты чужого короба, учёт филиалов, действующие функции и голоса ТСД.
Не заменять опубликованный проект целиком этой рабочей веткой.

## Проверки

- `kiz-review-queue.spec.ts`: права, контекст, два решения, защита нового серийного КИЗа.
- `kiz-review-queue.postgres.spec.ts`: отдельная локальная PostgreSQL, одновременные
  сканы/решения, отсутствие дублей, клиентский/филиальный доступ, запрет использования
  погашенного КИЗа, смена попытки, замена одной единицы при расхождении общего числа
  КИЗов в коробе, откат изменения и разрешения при ошибке.
- `KizReviewQueuePanel.spec.tsx`, `KizReviewPolicyTest`: обе кнопки, допустимое решение,
  права администраторов и изоляция проданных вариантов.
- Полные наборы API, веба и шести вариантов Android; проверка TypeScript API/веба.

Результат локального запуска: API — 2739 прошли, 60 предусмотренных окружением
пропусков; веб — 209 прошли; Android — 936 прошли (156 в каждом из шести вариантов).
TypeScript API и веба без ошибок. SQL-миграция применена в отдельной локальной БД.
Логи: `work/kiz-history-validation/review-api-tests-final.log`,
`review-web-tests.log`, `review-android-tests.log`.

Изменения не опубликованы: отдельно нужны проверенная интеграция с текущим сервером,
PR, миграция, выпуск APK и включение флагов.
