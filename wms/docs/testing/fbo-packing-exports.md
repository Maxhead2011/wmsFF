# FBO: проверка коробов и два файла WB

Изменение: `feature/fbo-packing-mode-choice`, исходная ветка `feature/fbo-fbs-location-voice`.

В Android LOGOFF после выбора заявки доступны «Собрать новые короба», «Отсканировать целые короба» и «Сканировать все короба поставки». Последнее действие доступно после упаковки всех единиц и закрытия коробов. Завершение формирования новых коробов возвращает в меню без завершения заявки. Итоговый контроль использует существующие SORTED, CONFIRM_BOX, FINISH. Чужой или повторный скан отклоняется сервером; неподтверждённые короба показываются списком. После FINISH доступны обе выгрузки в ТСД и web-заявке.

API: GET /tsd/requests/:id/fbo/wb-products.xlsx и wb-packages.xlsx. Существующие скачивания /client-requests/:id/marketplace/wb-products.xlsx и wb-packages.xlsx используют те же данные. Доступ проверяется по клиенту и филиалу.

При включённом WMS_FBO_TWO_STAGE_ENABLED и наличии FboAssembly экспорт читает фактически упакованные FboAssemblyUnit и подтверждённые FboAssemblyBox. Фаза должна быть COMPLETED, число единиц должно совпасть с упаковочными местами заявки. Неполные или противоречивые данные отклоняются.

Первый файл, Sheet1: Баркод, Количество. Сумма по всем коробам.
Второй файл, Sheet1: Баркод товара, Кол-во товаров, ШК короба, Срок годности, ШК короба для печати в стороннем сервисе. Одна строка на пару баркод–короб, последние два поля пустые. Структура соответствует предоставленным WB-шаблонам. Баркоды и коды коробов — текст, количества — числа.

Модули: FboTwoStageScreen, FboTwoStagePanel, FboTwoStageController/Service, ClientRequestMarketplaceFilesService и новый fbo-wb-export.ts. Реестр API админки дополнен маршрутом состава поставки.

Изоляция: новое меню — только Android flavor logoff; новый экспорт — только включённая двухэтапная FBO-сборка. Shared-модули затронуты; для проданных вариантов сохранены старые меню и legacy-экспорт. Изменений схемы БД нет. Прямая передача данных в WB отложена, в этом изменении отсутствует.

Тесты: FboPackingModeTest, FboTwoStageScreenTest; fbo-wb-exports.spec.ts; fbo-two-stage.integration.spec.ts; FboTwoStagePanel.spec.tsx; полный Android/API/web прогон. Локальная интеграционная проверка использует отдельную БД kiz_duplicate_tests, порт 55485 (копия теста с заменой только локального порта; исходный guard 55469 сохранён). Тесты не подключаются к производственной БД. Релизные образы дополнительно проверяются в изолированных контейнерах без сети.
