# Автоматические статусы заявок FBS

Флаг `WMS_FBS_REQUEST_AUTO_STATUS_ENABLED=true` включает автоматические переходы только в нашей ВМС. По умолчанию флаг выключен; проданная ВМС сохраняет прежнее поведение. Миграция базы не требуется.

## Правила

- **В работе**: сотруднику назначено реальное задание FBS с временем начала. Автоматическая резервация `AUTO:*` не считается началом работы.
- **Упаковано**: все текущие заказы имеют завершённые задания, и количество полностью совпадает с каждой строкой состава. Отсутствующая строка, перенос, возврат или другая неразрешённая связь блокируют переход.
- **Сдано**: для всех текущих заданий WB есть подтверждённая печать со станции `SOS-WB:*` и отдельный факт складской отгрузки с соответствующим количеством. Создание задания печати, ошибка печати, обычная печать ТСД или только внешний статус WB недостаточны. Порядок прихода подтверждений печати и завершения сборки не влияет на результат.

Операции завершения отбора и подтверждения SOS выполняют изменение статуса в той же транзакции, что и основной результат. Блокировка заявки сериализует последние одновременные завершения. Повторы не создают дополнительный переход. История заявки содержит основание автоматического изменения и сотрудника.

Автоматика не понижает статус и не открывает заново DONE/CANCELLED/REJECTED. Ручная смена через существующий API не изменена. Событие сканирования/печати, произошедшее раньше ручного изменения статуса, не отменяет это решение при повторе или возобновлении. Новое действие сотрудника после ручного изменения может запустить следующий автоматический переход.

Для Ozon работают первые два перехода; автоматическое «Сдано» через SOS WB 2 относится только к WB. Заявки Excel/FBO без связей FBS не затрагиваются. Исторические заявки не обновляются массово при включении флага: обработка идёт по действиям/возобновлению заданий и подтверждениям печати.

## Изменённые модули

- `common/stock/fbs-request-auto-status.ts`: проверка состава, текущих заказов, подтверждений печати и отгрузки, ручных изменений; запись статуса и истории.
- `marketplace-connections.service.ts`: назначение/возобновление задачи ТСД и SOS, завершение отбора, успешное подтверждение печати и восстановление незавершённого подтверждения. После изменения сбрасывается кеш заказов клиента.
- `.env.example`: выключенный по умолчанию флаг.

## Проверки

`test/fbs-request-auto-status.integration.spec.ts`: 19 сценариев на отдельной PostgreSQL `fbs_auto_status_tests`; включая реальные точки входа завершения ТСД и подтверждения печати, конкурентные подтверждения, все три перехода, неполный состав, отсутствие задач, ошибку печати, отсутствие складского списания, обычную печать, порядок событий, ручное управление, Ozon, выключенный флаг и откат транзакции.

Регрессия воспроизведена на исходном `MarketplaceConnectionsService`: последнее завершённое задание оставляет заявку SUBMITTED вместо PACKED. С исправлением сценарий проходит. Дополнительно 48 сценариев FBO проходят на чистой отдельной тестовой базе. Рабочая база не менялась.

Проверено 24.09.2026: общий прогон API — 233 файла, 2746 успешных тестов, 60 пропущенных (2 файла целиком). Проверки с отдельными базами выполнены дополнительно: складской цикл WB и начисления печати — 38, закрытие упаковки и замены размеров — 29, идентичность КИЗ — 5; все успешны. Проверка TypeScript API и `git diff --check` пройдены. Общий прогон использовал отдельный Prisma-клиент и чистую локальную базу `kiz_duplicate_tests_fbs_auto`; общий Prisma-клиент других рабочих копий не изменялся.
