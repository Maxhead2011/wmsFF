# Перенос неотобранного остатка FBO

В двухэтапной сборке FBO кнопка **«Перенести неотобранное»** доступна после частичного отбора. Подтверждение показывает количество для переноса и количество, которое останется в основной заявке. После переноса основная заявка переходит к упаковке; дочерняя появляется в общем списке со статусом «Подана».

Дочерние номера образуют серию основной заявки: `1220_01`, затем `1220_02`. Перенос из `1220_01` также продолжает серию `1220`, а прямая связь с `1220_01` сохраняется. Отдельный номер серии виден в списке, заголовке карточки и связях экрана FBO. Внутренние числовые номера и UUID остаются неизменными.

## Гарантии

- Количество дочерней строки равно количеству основной строки минус фактически отобранные единицы. Полностью неотобранные строки удаляются из основного состава и появляются в дочернем.
- Отобранные единицы, КИЗы, физические движения и исходные короба остаются в основной заявке.
- Создание дочерней заявки, изменение состава, обновление контрольной суммы сборки, смена этапа и события истории выполняются одной транзакцией.
- Суммарный резерв сохраняется: неотобранная потребность переносится, а не копируется.
- Повтор запроса с тем же operationId возвращает текущий результат. Конкурирующие переносы защищены блокировкой заявки и Serializable-транзакцией; корневой счётчик блокируется отдельно.
- Нельзя перенести остаток до первого отбора, при полном отборе, после перехода к упаковке либо при изменённом составе заявки.
- Дочерняя заявка наследует клиента, филиал, приоритет, дату и адрес поставки, контактные данные и комментарии товарных строк. Оригинальный Excel остаётся в исходной заявке: он содержит полный исходный заказ, а не состав дочерней.

## Включение

1. Применить миграцию `20260921170000_fbo_remainder_requests`, сгенерировать Prisma Client и собрать API/web.
2. Для нашей ВМС включить `WMS_FBO_REMAINDER_TRANSFER_ENABLED=true` при включённом `WMS_FBO_TWO_STAGE_ENABLED`.
3. Для проданной ВМС оставить флаг `false`: кнопка скрыта, API отклоняет действие. Миграция добавляет nullable-поля связи/номера и счётчик с нулевым значением; существующий состав заявок не меняется.

Миграция и новая функция не разделяют существующие заявки автоматически. №1220 и №1221 будут разделены только по нажатию кнопки сотрудником.

`FboTwoStagePanel.spec.tsx`: видимость кнопки только после частичного отбора и включения флага, отображение связи и номера дочерней заявки.
