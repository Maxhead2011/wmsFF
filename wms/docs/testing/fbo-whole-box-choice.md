# ФБО: целый короб, поштучный отбор и перемещение остатка

В заявке 1029 оставалось 19 единиц `Дэнс_светлмеланж`, S / 44.
В `FFL_LKBS1509_31` находились все 19 с соответствующими КИЗами, но маршрут
выделял одну единицу из более раннего смешанного `FFL_LKBS1509_27`.
Для целого короба оставалось только 18, поэтому кнопка была недоступна.

## Изменения

`prioritizeFboWholeBoxes` отдаёт приоритет целым сверенным однородным коробам:
сначала точное совпадение с потребностью, затем большее подходящее количество.
После каждого выбора потребность пересчитывается. Занятые короба исключаются
прежней проверкой, отрицательные остатки и расхождения КИЗов не обходятся.
Оставшиеся единицы распределяются по прежнему порядку паллетов и коробов.
Количество по нескольким строкам одного SKU суммируется.

В ТСД можно выбрать поштучный отбор ШК + КИЗ либо открыть существующий экран
перемещений для ненужного остатка. Переход не создаёт движения товара и не
отмечает отбор. После завершения перемещения кнопка возврата заново загружает
заявку и её маршрут. При незавершённом перемещении возврат блокируется.

Кнопка целого короба открывает пустое поле фактического количества единиц.
ТСД сверяет ввод с показанным количеством; API повторно проверяет актуальные
остатки и КИЗы внутри транзакции. Несовпадение ничего не списывает. Количество
сохраняется вместе с идентификатором операции на ТСД и участвует в серверной
проверке повторов. Старые уже принятые операции без количества по-прежнему
распознаются как повторы; новые требуют явного количества.

## Изоляция и выпуск

- Ветка: `fix/fbo-whole-box-choice`; база PR: `fix/fbo-transaction-retry`.
- Серверный режим ограничен `WMS_FBO_TWO_STAGE_ENABLED`; вход в экран ФБО
  остаётся доступен только в Android-варианте `logoff`.
- Затронуты общие файлы API ФБО и Android, включая `MainActivity.java`.
  Проданная ВМС с выключенным режимом сохраняет прежние операции и навигацию;
  её номер версии не меняется. Проверяется также Android-вариант `ffullhab`.
- Новая версия LOGOFF ТСД: 181 / `0.1.182-fbo-box-choice`.
- Миграции БД и ручная корректировка остатков не нужны.
- Сначала обновляется API, затем публикуется и устанавливается подписанный APK.
  До обновления старый ТСД может собирать поштучно; новый отбор целого короба
  получает объяснение о необходимости ввода количества и обновления ТСД.
- При публикации сохранять параллельные изменения веб-прогресса ФБО из другой
  рабочей папки. Они не включены в эту ветку и не должны быть перезаписаны.

## Проверки

Три новых регрессии до исправления падали на настоящей локальной PostgreSQL:
выбор смешанного короба перед целым, принятие отсутствующего количества,
принятие несовпадающего количества. После исправления они проходят.

Проверяются также повтор транзакции без двойного списания, конкурирующие ТСД,
весь цикл отбора/упаковки, сверка КИЗов и резервов, ввод количества в
Robolectric, отсутствие мутаций при открытии перемещений и сохранение количества
после потери ответа и перезапуска приложения.

Команды из `wms/`, после `work/dev-env.ps1`:

```powershell
$env:KIZ_DUPLICATE_TEST_DATABASE_URL='postgresql://codex_tests@127.0.0.1:55469/kiz_duplicate_tests'
pnpm --filter @logoff/wms-api exec vitest run --maxWorkers=4 --minWorkers=1 --testTimeout=15000
pnpm --filter @logoff/wms-api build
pnpm --filter @logoff/wms-web test
```

Из `wms/apps/android-tsd/`:

```powershell

```
