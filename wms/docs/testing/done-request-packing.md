# Сданная заявка: закрытие остатка PACKING

## Поведение

При `WMS_DONE_PACKING_RECONCILIATION_ENABLED=true` переход товарной заявки в `DONE` сверяет её остаток `PACKING`. Повторное закрытие уже сданной заявки выполняет ту же сверку. Сама заявка сохраняет `DONE`; складская история не удаляется.

Ранний выход по существующему факту `WbOrderShipment` больше не мешает фоновой сверке **сданных** заявок: отдельный проход обрабатывает их положительное сальдо PACKING. Активные заявки, включая напечатанные, этот проход не закрывает. Действующий механизм подтверждения SOS/WB остаётся без изменений.

Списание — отрицательное движение `SHIP/PACKING` с ключом `done-packing:<requestId>:<balanceId>`. AVAILABLE, SHIPPING, КИЗы, факты отгрузок, оплаченные счета и упаковочные документы не переписываются. История КИЗов продолжает формироваться существующим workflow отгрузки.

## Проверки

- Блокировки в порядке заявка → задания отбора → остатки. Общие остатки блокируются в стабильном порядке, проверяются все строки до первого изменения.
- Вычисляется сальдо конкретной заявки по клиенту, филиалу, SKU, коробу и паллету. Учитываются отрицательные движения целой заявкой, а не только по ID заказа.
- Сумма истории ячейки должна совпасть с текущим остатком; отрицательное сальдо другой заявки запрещает автоматическое распределение списания. Неоднозначные старые данные требуют ручной сверки.
- Перенос отбора в другую заявку, отсутствующий/неоднозначный остаток и несовпадение филиала запрещают исправление. Исключение откатывает транзакцию целиком.
- Повторная операция видит погашенное сальдо и не создаёт второе списание.
- Проданная ВМС: флаг по умолчанию выключен; изменений схемы БД нет.

## Исторические заявки

Из каталога API после сборки:

```text
node dist/scripts/reconcile-done-request-packing.js --dry-run
```

По умолчанию выполняется только предпросмотр, в транзакциях PostgreSQL READ ONLY. Вывод JSONL содержит номер заявки, клиента, количество или причину отказа. Код завершения 2 означает наличие записей для сверки, а не успешное исправление всех заявок.

После проверки отчёта и включения флага на нашей ВМС:

```text
node dist/scripts/reconcile-done-request-packing.js --apply
```

Каждая заявка проверяется заново в своей транзакции. Ошибочная заявка откатывается целиком; остальные обрабатываются независимо. Старые даты отгрузки не меняются; корректирующее движение отражается датой выполнения. Отключение флага прекращает новые исправления и не возвращает уже списанные остатки.

Предпросмотр рабочей БД 19.09.2026 17:07 МСК: 320 сданных заявок с положительным суммарным сальдо; 27 заявок / 57 единиц однозначно проходят проверку, 293 требуют сверки. Это снимок для оценки, не разрешение без повторной проверки. Данные рабочей БД не изменены; персональные данные и полный отчёт не включены в Git.
