## Правила учёта

1. Учитывается сохранённая завершённая работа начиная с **01.09.2026 00:00 МСК**:
   дата завершения, ШК, короб, исполнитель/ТСД, положительное целое количество.
   Один статус WB не является достаточным подтверждением. Читается также история
   успешных попыток до сброса/повторной сборки. Повторные попытки одного заказа не
   получают повторный тариф автоматически: ключ — клиент/маркетплейс/кабинет/заказ/услуга.
2. Проверка уже начисленных услуг охватывает все даты, оплаченные/выставленные счета,
   перенесённые в объединённые счета строки и другие поставки. Отсутствие строки в
   выбранном периоде само по себе не разрешает выставить услугу повторно.
3. Недостающие услуги создаются отдельными черновиками по филиалу/заявке/дню МСК.
   Тариф обработки берётся из настройки (сейчас **37,10**, налог повторно не начисляется).
   При включённой первичной обработке: **10,64 + 4,26**. Перемаркировка — только по
   `relabelConfirmedAt`, по настроенному тарифу. Новая логистика не начисляется.
4. Сохранённое начисление без единого прикрепления к счёту можно прикрепить как есть:
   сумма, дата, количество и состав не переписываются. Филиал определяется по
   клиентским заявкам/полным связям заказов. Отменённые вручную счета не воскрешаются.
5. Пустая/неполная выдача WB не уменьшает старый начисленный состав. Новые услуги
   не пересчитываются по текущему хвосту WB. Появление того же заказа в новой поставке
   не начисляет обработку второй раз. Сохранённый счёт не приписывается чужому заказу.
6. Чтения и запись выполняются под общей финансовой PostgreSQL advisory-блокировкой,
   в одной транзакции; вставки пакетами по 500. Уникальные sourceKey дополнительно
   защищают от дублей. Журнал: `billing.completed-fbs-work-recovered`.

Неоднозначные связи, отсутствующие доказательства/тарифы и ранее отменённые восстановления
выдаются в `blocked`/`unresolvedWork`, а не превращаются в выдуманные начисления.
