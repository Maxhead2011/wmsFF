# Проверка КИЗ без подтверждённой печати

Сервис → «Поиск неотгруженных КИЗ»: выбранные клиент и рабочий филиал, период сканирования (1–31 день, календарные даты МСК). Отчёт использует события `FBS_KIZ_SCAN_ACCEPTED` и `FBS_WB_KIZ_REPLACED_AFTER_PRODUCT_PICK`, включая сохранённые попытки сборки. Короб и сотрудник берутся из события сканирования. Один КИЗ в одной попытке представлен последним успешным сканированием.

Отсутствие печати не доказывает физическое наличие товара. Подтверждением печати служат `FbsPrintJob` со статусом PRINTED и временем печати либо успешный аудит `FBS_TWO_LABELS_PRINTED`, совпадающие по сборке, заявке, заказу и физическому КИЗ. Проверка не ограничивает дату последующей печати выбранным периодом. Скачивание этикетки, очередь и ошибка печати не являются подтверждением.

Отчёт не меняет склад. Записи с отгрузкой WMS, изменённой привязкой, неизвестным исходным коробом или уже созданным поиском видны, но заблокированы для создания заявки. Перед созданием выбранные строки заново проверяются. Запрос с тем же ключом операции возвращает прежнюю заявку; параллельные создания сериализованы по клиенту/филиалу. Максимум 500 строк на заявку; при более 5000 событий требуется сократить период.

Создаётся обычная заявка OTHER и маркер `KIZ_SEARCH_CREATED` с `targets`, совместимый с существующим `KizSearchService` на ТСД (формат заявки №1054). Исполнитель должен иметь доступ к клиенту и филиалу, а также права склада. Остатки, маркировки, задания FBS и маркетплейсы не изменяются.

Изоляция: серверный `WMS_UNPRINTED_KIZ_SEARCH=true`, веб-сборка `VITE_UNPRINTED_KIZ_SEARCH=true`; оба выключены по умолчанию. Для создания нужен уже установленный и включённый `WMS_TSD_KIZ_SEARCH=true`. Миграций нет. При переносе на production сохранять существующий модуль поиска КИЗ и вкладку проверки печати WB; текущая интеграционная ветка не включает все ранее опубликованные модули.

Тесты: `apps/api/test/unprinted-kiz.spec.ts`, `apps/api/test/unprinted-kiz.service.spec.ts`, `apps/web/src/lib/unprintedKiz.spec.ts`. Браузерная проверка должна включать переключение клиента/периода, строки с блокировкой, выделение и повтор создания с тем же ключом после сетевой ошибки.
