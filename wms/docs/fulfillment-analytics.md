# Аналитика отгрузок и запасов ФФ

## Детализация моделей (опубликовано 25.11.2026, PR1078)

По умолчанию таблица показывает модели с раскрытием до цвета/рисунка, размера и исходной SKU. Переключатель также предлагает виды товаров, модель + цвет, модель + цвет + размер и исходные карточки без группировки. У товаров без размера этот уровень раскрытия пропускается. Поиск по артикулу находит родительскую модель, страницы ограничивают число родительских строк; раскрытые строки не добавляются повторно к сводке.

`fulfillment-groups.ts` выводит группы только внутри уже проверенного клиента и склада. Виды из числового marketplace category ID не угадываются. Поддержаны явные структуры артикулов одежды (тип/модель/цвет/размер), семейство Ностальжи, цветовые суффиксы с сохранением кодов моделей, FMS-X с отдельным Pro, артикулы отрезов gab/satin/sat. Числовые артикулы без правила остаются самостоятельными моделями с названием товара; карточки без артикула не склеиваются по похожему названию. Данные каталогов не исправляются. Противоречие цвета названия и поля карточки отмечается; размеры, извлечённые из артикула, отмечаются отдельно. Неизвестный цвет/размер не превращается в общий взаимозаменяемый вариант.

Каждый уровень получает собственные ABC и XYZ из исходных дневных отгрузок. ID заявок объединяются перед подсчётом частоты, даты отгрузок не суммируются между SKU. Доли относятся ко всем отгрузкам выбранного канала, клиента и склада, независимо от поиска. Средний возраст взвешивается по единицам с известной датой. Рекомендации, дефицит и избыток суммируются из отдельных SKU; показывается число SKU с известной рекомендацией. Избыток другого цвета/размера не уменьшает дефицит. Дни покрытия/нулевого остатка для группы не показываются, поскольку варианты не взаимозаменяемы.

Для тканей рядом со штуками показаны метры в отрезах с известной длиной. Это не свободный остаток рулонов и не объединение разных материалов. ABC остаётся по штукам, как указано в методике; метры — дополнительная мера.

Проверки: `test/fulfillment-groups.spec.ts`, дополнение PostgreSQL в `test/fulfillment-postgres.spec.ts`, браузер `fulfillment-groups.browser-test.cjs`. Сборка точечного обновления: `scripts/releases/fulfillment-groups/build.cjs <release-dir>`. Проверка скомпилированного кандидата `runtime-test.cjs` выполняет только чтение реальных отчётов Лукина, Елецкой, Кубрина, Королёва и тканей; сверяет итоги всех уровней и неизменность сумм рекомендаций. Доступ регулируется прежним флагом нашей установки, миграций и записи складских данных нет. Проданная ВМС не публикуется.

## Доступ и компоненты

`WMS_FULFILLMENT_ANALYTICS_ENABLED=true` включает только на нашей установке два read-only маршрута `/analytics/fulfillment/clients` и `/analytics/fulfillment/dashboard` и признак сессии `fulfillmentAnalyticsEnabled`. При выключенном флаге API отвечает 404, меню сохраняет прежнее поведение WB. Новый сеанс/обновление авторизации получает актуальный признак. Существующий `analyticsEnabled` продолжает управлять только аналитикой Wildberries.

Пользователь выбирает клиента и один склад ФФ. Сервер независимо проверяет client scope, скрытых клиентов, demo isolation, связь клиента со складом и warehouse scope сотрудника. Обычный клиент получает склады только своих клиентов. Явное скрытие меню через `workspaceVisibility` сохраняется.

`AnalyticsPanel.tsx` содержит три вкладки; прежний WB-компонент сохранён. `FulfillmentPanel.tsx` — фильтры, сводка, матрица ABC/XYZ, поиск, сортировка, страницы по 25 товаров, подробности и предупреждения. Сервер: `fulfillment.controller.ts`, `fulfillment.service.ts`, `fulfillment-math.ts`. Регистрация в `analytics.module.ts`, перечень маршрутов в `administration-internal-api.service.ts`; признак доступа в auth service/guard/types, web API types и `workspaces.ts`.

## Источники и определения

- Период: 1–366 завершённых дней МСК; по умолчанию 90. Будущие даты и сегодняшний незавершённый день запрещены.
- Отгрузки: текущие DONE/OUTBOUND заявки, дата **первого** DONE за всю историю. Повторный DONE не добавляет отгрузку. Это дата отражения в ВМС, не гарантированная дата физической сдачи маркетплейсу.
- ФБС: явная связь `FbsOrderRequestLink`. ФБО: явная связь сборки WB, Ozon, Yandex или Lamoda. Остальные OUTBOUND, включая B2B, не приписываются ФБО. Число исключённых заявок и количество без SKU показываются отдельно.
- Объём — итоговые количества `ClientRequestItem`, сгруппированные по заявке и SKU. Частота — число заявок ВМС и дней с отгрузками, **не число покупательских заказов**.
- Приход — положительные RECEIPT movements за период, возвраты отдельно. INITIAL_IMPORT не считается приёмкой. Приход и остаток общие для ФБС/ФБО; складывать вкладки нельзя.
- Текущий остаток: StockBalance кроме IN_TRANSIT. Расчётно свободно = max(0, AVAILABLE − max(0, количества открытых OUTBOUND − RESERVED/PACKING/SHIPPING)). Это оценка распределения обязательств, а не новая физическая резервация.
- Возраст товара: средневзвешенная дата приёмки короба из ReceiptStockIdentity или первого положительного RECEIPT этого короба. Возраст отгруженного товара — по отрицательным SHIP с `sourceDocument=requestId`. Если SHIP больше количества заявки, такая трасса не используется. Неизвестные даты дают null, рядом показывается покрытие. Это не индивидуальное FIFO-прослеживание каждой единицы.

## ABC/XYZ и рекомендация

ABC по доле отгруженных единиц: границы 80%/95%; класс определяется накопленной долей до группы одинакового объёма. Равные объёмы остаются вместе; граница может быть превышена. N — нет отгрузок. Поиск и пагинация не меняют знаменатель.

XYZ по коэффициенту вариации недельного объёма: X ≤10%, Y ≤25%, Z >25%. Нужны 8 полных недель понедельник–воскресенье; нулевые недели включены. Нет спроса по неделям — N, мало недель — «?». Дневное среднее включает нулевые дни с начала периода или первой приёмки, если она позже.

Рекомендованный остаток **ФБС** требует известной первой приёмки и 28 дней наблюдений. Пользователь задаёт доставку на ФФ, интервал пополнения и минимальный запас в днях, каждый 0–90 (первые два в сумме ≥1).

`горизонт = доставка + интервал`; `страховой запас = max(среднее × запас дней, 1.65 × sqrt(дисперсия дневных отгрузок × горизонт))`; `целевой остаток = ceil(среднее × горизонт + страховой запас)`.

Довезти = max(0, цель − расчётно свободно). Избыток = max(0, свободно − цель). Дни покрытия = свободно / среднее; при нулевом спросе null. Для ФБО прогноз null: партии требуют отдельного плана поставок.

Дни без товара восстанавливаются по дневным движениям от текущего остатка только при совпадении полного ledger с балансами. Отрицательная реконструкция делает историю недостоверной. Дефицит мог ограничить наблюдаемый спрос: поправки на потерянные продажи нет. Нулевые отгрузки сами по себе не доказывают отсутствие будущего спроса. При отрицательных или противоречивых остатках прогноз и некорректное покрытие возраста не показываются.
