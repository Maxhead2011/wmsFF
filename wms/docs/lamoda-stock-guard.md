# Проверка остатка при создании Lamoda

Подготовлено 28.10.2026, ветка `fix/lamoda-stock-guard`. Не опубликовано.
База — PR718/719, `2026-10-28-lamoda-mapping`, API
`sha256:c508378d6c5ae11cdf18e918ef36fd8ea8bc59c0fc91c8f7cfd47ce5e51e4f08`.
Сверена с работающим контейнером перед подготовкой кандидата.

`LamodaService.createAssembly` проверяет остаток после разрешения соответствий
и до создания `ClientRequest`, в существующей Serializable-транзакции. Ранее
импортированный план мог создать резерв на отсутствующий или занятый товар.
Предыдущий предварительный расчёт в UI не заменяет эту проверку.

`lamoda-stock-guard.ts` суммирует спрос по SKU, читает AVAILABLE выбранного клиента
и филиала из активных коробов (либо без коробов согласно настройке клиента),
исключает несогласованные и запрещённые для ФБО приёмки через `receiptRules`.
Подтверждённая приёмка без палет-сорта допускается. Оставшиеся резервы берутся из
общего `wbReservationQuantities`, включая заявки ФБО и задания ФБС; уже отобранные
единицы повторно не вычитаются. Расчёт консервативен: общие резервы вычитаются из
доступного для ФБО пула даже при наличии отдельного остатка только для ФБС.

При нехватке возвращается HTTP409 с ШК, требуемым, доступным количеством и дефицитом.
Складская заявка и связь сборки не создаются. Повтор ранее успешного создания
возвращает прежнюю заявку до проверки — дополнительный резерв не возникает.
Сохранены права клиента/филиала, сопоставление SKU, проверка удалённой поставки
и защита ФБС при фактическом отборе. Общие модули WB/Ozon не изменены.
Изменение действует внутри существующих флагов Lamoda, проданная WMS не затронута.

- 28 целевых тестов: 22 сервиса и 6 расчёта (суммирование SKU, точная граница,
  неподтверждённая приёмка, короб без паллеты, хранение без коробов, исключение своей заявки).
- Общий API-прогон: 3852 passed /155 skipped; дополнительные 6 тестов helper passed.
  Выделенная `kiz-duplicate.integration.spec.ts` исключена: нет её отдельной тестовой БД.
  Web: 519 passed /2 skipped.

  исходный локальный generated-клиент был старее моделей Yandex FBY и Lamoda.
- `scripts/releases/lamoda-stock-20261028/postgres.cjs`: 6 проверок настоящих
  транзакций на изолированной PostgreSQL. ФБС-задача и её заявка не удваивают резерв;
