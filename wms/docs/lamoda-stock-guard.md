## Поведение

Перед созданием показываются товар, артикул, размер, складской ШК, исходный план,
резервы, свободное количество, дефицит и редактируемое количество к сборке.
Пока оно превышает свободный остаток, создание заблокировано. Кнопка
«Скорректировать по доступному остатку» предлагает уменьшенные количества;
она не создаёт заявку и не резервирует товар. Нулевые позиции исключаются.
Пользователь может уменьшить количества вручную, восстановить исходные и
отдельно создать сборку. Пустая сборка и увеличение исходного плана запрещены.
При нескольких направлениях уменьшение распределяется в исходном порядке;
сумма directions всегда соответствует составу заявки. Исходный LamodaPlan/Excel
остаётся неизменным; переданный состав фиксируется в аудите.

`LamodaService.availability` и `createAssembly` используют один расчёт:
AVAILABLE клиента/филиала в активных коробах (либо без коробов по настройке),
только подтверждённые приёмки с разрешением ФБО. Палет-сорт не обязателен.
`wbReservationQuantities` вычитает оставшиеся резервы ФБС/ФБО, не удваивая
резерв связанной ФБС-задачи и не вычитая повторно уже отобранный товар.
Расчёт консервативен: общие резервы вычитаются из разрешённого для ФБО пула
даже при наличии отдельного остатка только для ФБС.

В Serializable-транзакции количество проверяется повторно до записи заявки.
При новом резерве ФБС возвращается HTTP409, заявка не создаётся; UI обновляет
таблицу остатков и требует заново проверить состав. Повтор успешного создания
возвращает существующую заявку. Для связанной поставки Lamoda выбранный состав
должен совпадать с текущим удалённым составом; пользователь корректирует кабинет
Lamoda отдельно. Автоматических изменений поставки на маркетплейсе нет.

## Затронутые файлы и влияние

- `apps/api/src/modules/lamoda/lamoda-stock-guard.ts`: общий расчёт, ограниченные
  корректировки состава, проверка перед резервированием.
- `lamoda.service.ts`: `availability`, `createAssembly`; `lamoda.controller.ts`
  и `lamoda.dto.ts`: приём и проверка выбранных количеств.
- `apps/web/src/components/lamoda/LamodaStockReview.tsx`: таблица и корректировка;
  `LamodaPanel.tsx`: создание и обновление дефицита; `lamoda.css`: адаптивный экран;
  `apps/web/src/lib/api.ts`: только типы и вызов Lamoda.
- API service/guard/manual-mapping тесты, web StockReview тесты и
  `scripts/releases/lamoda-stock-20261028/`: проверки/сборка точного кандидата.

Общие механизмы WB/Ozon не меняются. Схема, APK и проданная WMS не затронуты;
создание по-прежнему ограничено флагами Lamoda и правами клиента/филиала.
Полная локальная сборка не заменяет production (`sourceParityVerified=false`).
