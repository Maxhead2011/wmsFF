# WMS LOGOFF — карта алгоритмов

## 1. Приёмка

```text
клиент
  → режим с коробами / без коробов
  → уникальный короб (если нужен)
  → ШК товара
  → SKU
  → КИЗ (если нужен)
  → StockBalance
  → StockMovement(RECEIPT)
  → история партии
```

Контроль: клиент, уникальность короба, тип скана, SKU, уникальность КИЗа, idempotency.

## 2. Перемещение

```text
исходный короб
  → SKU + статус + доступное количество
  → целевой короб
  → decrement source
  → increment target
  → OUT movement + IN movement
  → перенос КИЗов
  → архив пустого исходного короба
```

Обе стороны выполняются в одной транзакции.

## 3. Заявка

```text
строки заявки
  → предложения коробов
  → выбор фактических источников
  → резерв единиц
  → сборка
  → проверка незавершённых
  → списание
  → начисления
  → СДАНО
  → архив
```

## 4. FBS

```text
WB API
  → локальные заказы
  → группировка по клиенту/поставке/направлению
  → WMS-заявка
  → поиск коробов и паллет
  → ШК
  → КИЗ
  → WB sticker
  → физическая упаковка
  → грузоместа WB
  → проверка полноты
  → передача
  → обработка FBS
  → архив
```

Любая отмена или перенос запускает reconciliation заказа, резерва и заявки.

## 5. Инвентаризация

```text
сессия
  → expected snapshot
  → скан короба
  → counted by barcode
  → сравнение SKU quantities
  → OK / shortage / surplus / unknown
  → решение менеджера
  → корректирующие движения
  → завершение
```

Повторная проверка требует разрешения, а исходный результат не удаляется.

## 6. Биллинг

```text
операционное событие
  → клиент
  → специальный тариф
  → общий тариф
  → количество/единица измерения
  → налог
  → BillingCharge
  → счёт
  → акт
  → оплата / аванс / долг
```

## 7. Права

```text
JWT
  → active user
  → role permissions
  → feature flags
  → workspace visibility
  → client scope
  → business rule
  → действие
```

Для режима владельца после permissions выполняется отдельная проверка owner allowlist.

## 8. Изменение через ИИ

```text
текст владельца
  → классификация
  → структурированный план
  → risk + checks + rollback
  → preview
  → ПРИМЕНИТЬ
  → allowlisted tool
  → server validation
  → действие
  → audit
```

Программное изменение заканчивается change request и не проходит в production автоматически.
