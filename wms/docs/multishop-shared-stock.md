# Общий остаток и автоматическая отправка WB/Ozon

Реализовано в feature/multishop-shared-stock, PR в feature/wb-print-check.
Статус публикации и точные образы фиксируются в current-production.md.

## Настройка

ФБС → управление распределением → «Между магазинами». Создать группы,
выбрать кабинеты и физический склад, назначить каждому каноническому товару
одну группу. Разные товары могут принадлежать разным парам WB/Ozon или группе
всех магазинов. ID склада маркетплейса можно указать для каждого участника;
пустое поле использует склад подключения.

- «По долям» (ALLOCATED): сумма долей 100%, общий бюджет не размножается.
- «Общий остаток» (SHARED): каждый магазин получает одинаковый свободный
  остаток. Это синхронизация независимых площадок, не атомарная общая корзина.
- Страховой запас вычитается один раз из общего бюджета.
- При достижении порога последние единицы остаются у приоритетного магазина.

Сохранение редактирует только черновик. «Предпросмотр отправки» проверяет
подключения, соответствия товаров, склады и читаемые остатки площадок.
«Применить и включить» отдельно активирует сохранённую версию. Первые две
минуты отведены на завершение прежних запросов. Проверка очереди — каждые 30 с;
фактическое время сходимости зависит от количества товаров и ответов площадок.
«Остановить» обнуляет назначения и ждёт подтверждения чтением. Старый отправитель
не получает управление автоматически даже после завершения остановки.

## Учёт и безопасность

multishop-stock-reader.ts читает повторяемый снимок физического AVAILABLE,
доступности приёмок/ФБС, активных заявок и фактических движений. Остаток содержит
только товар нужного клиента и склада. Заявка ФБО также уменьшает свободное
количество. Заказ маркетплейса и связанная заявка дедуплицируются; физический
отбор вычитается один раз. Сам отправитель не создаёт складских движений.

Пример: AVAILABLE=20, заказ=1 → свободно=19. После физического отбора
AVAILABLE=19, неотобранная потребность=0 → свободно по-прежнему 19.

Ozon читается целиком через /v4/posting/fbs/unfulfilled/list, с курсором и
широким окном сроков отгрузки; учитываются все строки отправления. Неполный
ответ, неизвестное соответствие или неоднозначный склад блокируют отправку.
Чтение /v2/product/info/stocks-by-warehouse/fbs использует free_stock,
проверяет present-reserved, товар и склад. Эти read-only контракты проверены
на действующем API 26.10.2026. Запись /v2/products/stocks проверяется по ACK
и затем независимым чтением; реальная запись клиентских остатков при выпуске
не выполняется. WB использует существующее полное чтение заказов и API v3 stocks.

multishop-stock-queue.ts: постоянная очередь в SystemSetting, одна строка
на клиента/физический склад/SKU, транзакционная блокировка, версия и аренда
исполнителя. Старые назначения сохраняются при смене состава группы. Снижения
отправляются раньше увеличений; неизвестный результат сначала перечитывается.
Повтор учитывает задержку и не создаёт параллельную отправку одного товара.
Снимок внешних заказов старше 120 секунд не разрешает запись увеличения.

multishop-stock-ownership.ts защищает общий сетевой путь прежних WB-записей,
включая повторы. Смешанный прежний пакет с управляемым товаром отклоняется
целиком: он не выдаётся за успешно отправленный. Прежнее распределение по
нескольким складам WB следует отключить до активации новой группы.

## Предусловия и изоляция

Нужны действующие подключения, подтверждённые MarketplaceProductLink, уже
включённый рабочий режим связей для клиента и однозначный склад исполнения.
Каталог только для просмотра не равен рабочим соответствиям. Автоматическое
включение связей или групп для конкретного клиента не выполняется при релизе.
Многоскладская маршрутизация одного кабинета и сторонние маркетплейсы в общем
пуле отклоняются явно. Незавершённая переклейка между SKU требует завершения.

Оба флага WMS_MULTISHOP_STOCK_ENABLED и WMS_MULTISHOP_PUBLICATION_ENABLED
по умолчанию выключены. Выпуск включает возможность только в образе нашей ВМС.
Проданная ВМС, её настройки и APK не изменяются. Общие исходные модули:
marketplace-connections service/module/controller и реестр внутренних API;
изменённые рабочие пути защищены флагом. Новых таблиц и миграций нет.

Нельзя просто выключить флаг и вернуть старый образ при активных группах:
сначала остановить их, дождаться подтверждённых нулей и проверить прежние
автоматические задания. До активации клиентов допустим откат обоих образов
к тегам before-multishop-auto-20261026.
