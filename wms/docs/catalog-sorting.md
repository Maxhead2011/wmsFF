# Сортировка и фильтры каталога — подготовлено, не опубликовано

Ветка `feature/catalog-sorting`, целевая ветка PR `feature/wb-print-check`.

Каталог использует новый GET `/skus/catalog` только при `VITE_CATALOG_SORT_ENABLED=true`. На сервере требуется `WMS_CATALOG_SORT_ENABLED=true`. Флаги включаются только в нашей установке. Старый GET `/skus` и его потребители не изменены.

Сортировка по артикулу, цвету и физическому количеству работает по всему доступному списку перед разбиением на страницы. Артикулы сортируются с учётом чисел, пустой цвет/артикул остаётся внизу в обоих направлениях. По умолчанию сохранён порядок обновления. Поиск включает название, внутренний SKU, артикул, цвет и ШК.

«Только в наличии» означает положительную сумму StockBalance в доступном пользователю складском контуре. Товар IN_TRANSIT исключён, резерв и другие физические состояния включены. Это не свободный остаток для публикации на маркетплейсе. Количество не зависит от наличия связей WB/Ozon.

Фильтр соответствий:

- Есть подтверждённые WB и Ozon: один складской SKU имеет LINKED-связи обоих маркетплейсов в активных кабинетах этого клиента.
- Нет подтверждённой пары: сверка включена, но такой пары нет. Кандидат по одинаковому ШК ещё не является подтверждённой парой.
- Не проверено: сверка клиента не включена.

Никаких автоматических объединений SKU, списаний, изменений резервов или публикации остатков. При ошибке чтения показывается ошибка, прежние строки очищаются. Данные клиентов и складов ограничиваются существующими проверками ClientScopeService и scopedWarehouseId. Общие исходники изменены, но проданная WMS сохраняет старый режим без обоих флагов.

Файлы: `skus.controller.ts` (catalog), `skus.service.ts` (catalog), `catalog-list.ts` (проверка параметров, глобальная сортировка, остатки и статус пары), реестр API (+1 маршрут), `lib/api.ts`, `CatalogPanel.tsx`, `CatalogSortControls.tsx`, `catalog.css`, тесты и документация.

Перед публикацией: свежая сверка образов, точечный runtime-кандидат от текущей базы по release-workflow; полную локальную сборку не публиковать. Миграции БД не требуются.
