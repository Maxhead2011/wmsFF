# Отбор из текущего короба: FBO и Android FBS

## Изменение поведения

FBO: после скана паллет-сорта и короба маршрут сначала выделяет требуемое количество из этого короба, затем из других коробов того же паллет-сорта. Выбор целого короба в другом месте больше не вытесняет текущий источник после каждой принятой единицы. Без выбранного места сохраняется прежний приоритет целых коробов.

Android FBS: после физического подтверждения короба следующие заказы той же заявки продолжаются из него без повторного сканирования паллет-сорта и короба. Для каждого заказа выполняется штатная серверная проверка источника, свободного остатка, владения заданием и КИЗа. Требуемые этапы передачи в маркетплейс и подтверждения наклейки сохраняются. В окне ШК / КИЗ видны принятые единицы из этого короба и оставшаяся потребность. Принятое количество восстанавливается из завершённых заданий этого сотрудника, заявки и короба.

## Изоляция и безопасность

- `WMS_FBO_LOCAL_ROUTE_ENABLED=true` включает приоритет текущего места в нашей API.
- `WMS_FBS_SEQUENTIAL_PICK_ENABLED=true` включает предпочтение предыдущего источника и серверный счётчик.
- По умолчанию обе возможности выключены. Автоматическое продолжение в Android дополнительно ограничено вариантом `logoff`.
- Подсказки местоположения FBO не создают резервов и не расширяют доступ к клиенту или филиалу. Заблокированные и недоступные короба отфильтровываются до расчёта маршрута.
- Выбранный источник FBS хранится только в текущем сеансе; смена пользователя/заявки, сброс или потеря владения прекращают продолжение. Каждый следующий короб проходит обычный серверный `scan-box`. Неуспешная попытка не повторяется бесконечно.
- Никаких миграций БД и изменений остатков этой доработкой не выполняется.

## Затронутые модули

API: `FboTwoStageService.plan/snapshot/act`, GET-контроллер и DTO контекста маршрута, новый `prioritizeFboLocation`; `MarketplaceConnectionsService.getNextFbsTsdAssemblyUnlocked/formatFbsTsdAssembly/fbsTsdSourceBoxUsage`, модуль предпочтения источника FBS.

Android: `FboTwoStageScreen` и `WmsApi` передают выбранное место при обновлении; `MainActivity` и `FbsSequentialPick` продолжают отбор и показывают счётчик; модели ответов получают совместимые необязательные поля.

Регрессии: сценарий FBO «нужно 4, два короба по 3, после первого скана маршрут меняется», скан на PostgreSQL, исчезновение остатка, границы текущего паллета, отключённые флаги, выбор источника другого сотрудника, недостаточный свободный остаток, повторный ответ, смена заявки, восстановление счётчика после потери ответа.

## Публикация

Рабочая ветка: `fix/fbo-sticky-route-fbs-sequential`. Предлагаемая база PR нашей ВМС: `fix/historical-packing-client-free-stock`.

Это локальные изменения, не публикация. Перед выпуском нужно совместить только эти изменения с актуальными исходниками сервера и Android: локальная база ветки не содержит всех последних серверных доработок fast acknowledgement / parallel packing. Нельзя заменять рабочие файлы целиком старой локальной копией. Сохраняются существующие голоса, режимы упаковки и подтверждение операций. При фактических конфликтах применяется правило согласования из AGENTS.

Проданная ВМС не публикуется и новые флаги на ней не включаются. В PR необходимо указать общие модули FBO/FBS и Android, поскольку они используются обеими версиями.
