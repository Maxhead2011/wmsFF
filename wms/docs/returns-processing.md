# Обработка возвратов

Опубликовано 22.11.2026 через PR1057 в `feature/la_panthera` из `feature/returns-processing`. [Проверка публикации](releases/returns-1057.json). Оба канала ТСД — 268.

В WMS и LOGOFF ТСД 268: клиент → код возврата WB/Ozon → ШК фактического товара → состояние → действующий короб клиента/филиала. Состояния: нормальное, разнопарка/некомплект, испачкан/повреждён, неверное вложение. В одном коробе одна партия и одно состояние. Неоднозначный товар требует исправления карточки; чужие короба и уже принятый остаток не допускаются.

Завершение сортировки атомарно создаёт RETURN/QUARANTINE, остаток и одно начисление RETURN_PROCESSING. КИЗ для хранения не требуется; AVAILABLE не создаётся. Повтор завершения и повтор запроса скана не увеличивают количество или стоимость. Один код возврата + ШК у клиента защищён от повторного приёма. Несколько одинаковых вещей под общим возвратным кодом требуют отдельного согласования сценария.

Хранение следует существующей политике клиента (включённый учёт, объём SKU и тариф). По принятой дневной модели считается остаток на начало дня: первый оплачиваемый день — следующий после приёма, независимо от получения КИЗ. Возврат не создаёт новый старт хранения при последующем MOVE. Если тариф обработки не задан, строка остаётся черновиком с PRICE_REVIEW и явным пояснением; тариф задаётся в биллинге.

Excel содержит короб, фактический ШК, наименование, артикул, размер, состояние, количество и код возврата; отдельный лист нормальных единиц, ожидающих КИЗ. История показывает последние 200 партий с фильтром по датам.

Этот выпуск охватывает первичную обработку и карантинное хранение. Привязка полученных от клиента КИЗ и выпуск из карантина не выполняются кнопкой завершения и не должны оформляться повторной обычной приёмкой. Отдельного экрана маркировки возвратов в этом выпуске нет.

## Маркировка и закрытие короба — ТСД 269

В WMS и ТСД два пункта: «Первичная обработка» и «Маркировка».
Маркировка: клиент → скан короба → повторяемые пары ШК товара и полный КИЗ → «Закрыть короб».
Скан КИЗ создаёт привязку в QUARANTINE к первоначальному приходу RETURN. Закрытие доступно только после маркировки всех нормальных единиц короба; выполняется одной транзакцией, переводит остаток и марки в AVAILABLE через MOVE. Количество, receivedAt и начисление RETURN_PROCESSING не изменяются. Повторные запросы используют сохранённую единицу и тот же код, повторное закрытие не создаёт движений. Повреждённые, неполные и неверные вложения остаются в карантине.

Проверяется формат полного КИЗ, прежнее использование и известное соответствие GTIN товару/размеру. Внешняя проверка статуса Честного знака не выполняется этим действием.

Новые маршруты: GET /returns/box, POST /returns/:id/mark, POST /returns/:id/close-box. Схема БД не меняется. Точный overlay API4/web3 от PR1057; sold ВМС не затронута, существующий флаг сохранён.

Проверки: API4878 passed/183 skipped; отдельный kiz-duplicate.integration исключён из общего запуска из-за отсутствующей специализированной БД. PostgreSQL возвратов8, включая сбой audit с полным откатом закрытия и конкурентные повторы. Web656/2 skipped, tsc и браузерный сценарий; оба подписанных APK проверены на Android9 emulator с синтетическим API. Установка обычного269 поверх опубликованного268 успешна. Серверный кандидат запущен на отдельной PostgreSQL, mark/close/retry проверены на скомпилированных модулях. В полном API tsc остаются 12 прежних ошибок вне модуля возвратов. Физический ТСД не проверен.
