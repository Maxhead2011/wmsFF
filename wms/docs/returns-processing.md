# Обработка возвратов

Подготовлено 22.11.2026 для нашей ВМС, ветка `feature/returns-processing`.

В WMS и LOGOFF ТСД 268: клиент → код возврата WB/Ozon → ШК фактического товара → состояние → действующий короб клиента/филиала. Состояния: нормальное, разнопарка/некомплект, испачкан/повреждён, неверное вложение. В одном коробе одна партия и одно состояние. Неоднозначный товар требует исправления карточки; чужие короба и уже принятый остаток не допускаются.

Завершение сортировки атомарно создаёт RETURN/QUARANTINE, остаток и одно начисление RETURN_PROCESSING. КИЗ для хранения не требуется; AVAILABLE не создаётся. Повтор завершения и повтор запроса скана не увеличивают количество или стоимость. Один код возврата + ШК у клиента защищён от повторного приёма. Несколько одинаковых вещей под общим возвратным кодом требуют отдельного согласования сценария.

Хранение следует существующей политике клиента (включённый учёт, объём SKU и тариф). По принятой дневной модели считается остаток на начало дня: первый оплачиваемый день — следующий после приёма, независимо от получения КИЗ. Возврат не создаёт новый старт хранения при последующем MOVE. Если тариф обработки не задан, строка остаётся черновиком с PRICE_REVIEW и явным пояснением; тариф задаётся в биллинге.

Excel содержит короб, фактический ШК, наименование, артикул, размер, состояние, количество и код возврата; отдельный лист нормальных единиц, ожидающих КИЗ. История показывает последние 200 партий с фильтром по датам.

Этот выпуск охватывает первичную обработку и карантинное хранение. Привязка полученных от клиента КИЗ и выпуск из карантина не выполняются кнопкой завершения и не должны оформляться повторной обычной приёмкой. Отдельного экрана маркировки возвратов в этом выпуске нет.

## Файлы и изоляция

- API: `src/modules/returns/*`, `app.module.ts`, схема и миграция `20261122_returns_processing`.
- Хранение: `storage-overview.service.ts`, карантин только зарегистрированных возвратов.
- Реестр внутренних API: `administration-internal-api.service.ts`, пять маршрутов.
- Web: `ReturnsPanel.tsx`, CSS, меню `App.tsx`, workspaces/groups/spaceNavigation.
- Android: `ReturnsActivity`, один пункт MainActivity, четыре метода WmsApi, manifest/version. Старые операции не заменяются.

API выключен без `WMS_RETURNS_PROCESSING_ENABLED=true`; исходный web выключен без `VITE_RETURNS_PROCESSING_ENABLED=true`. Runtime overlay устанавливается только в нашей ВМС. Sold ВМС и её APK не публикуются. Source parity остаётся false: точный overlay API8/web3, не полная сборка.
