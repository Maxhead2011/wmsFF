# Архив FBS после перезапуска

Архив запрашивается отдельно от активного экрана. По умолчанию — последние три календарных дня, включая сегодня, по Москве. Поля «С даты» и «По дату» ограничивают запрос к БД. «Последние 3 дня» возвращает исходный период.

Сохранённые связи заказов восстанавливают отгруженные и полученные заказы даже при пустом кэше и завершённой заявке. Текущий ответ маркетплейса приоритетнее сохранённого статуса, включая отмену. Сохраняются проверки клиента, кабинета, филиала и магазина. Нет повторного списания или пересчёта биллинга. Если карточка SKU удалена, история не удаляется.

Дата: сохранённая передача в доставку; при её отсутствии — сохранённая дата заказа, о чём сообщает интерфейс. Дата импорта не подставляется вместо даты отгрузки. Исторические записи без обеих дат не включаются в датированный запрос. Старый статус не объявляется свежим ответом МП.

Контур: `WMS_FBS_SAVED_ARCHIVE_ENABLED=true` только в нашей WMS. Флаг выключен по умолчанию; проданный контур не меняется. Runtime накладывается точечно: API3/web2, исходники не объявлены полной копией сервера.

Проверки: 16 тестов архива/дат; API 4748 passed / 9 skipped (выделенные DB integration suites отдельно); web 624 passed / 2 skipped; web typecheck; runtime RED/GREEN, browser5; полный запуск с изолированным PostgreSQL; чтение диапазона у 12 клиентов без записей в БД. Startup/reload и 24 проверки оформления прошли. Скрипты: `scripts/releases/fbs-archive-20261110/`.
