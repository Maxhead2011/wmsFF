# WB: идентичность по штрихкоду

При единственном точном совпадении ШК в полном каталоге WB и каталоге клиента
изменение артикула или размера не блокирует существующую связь. Описательные
поля синхронизируются на прежнем SKU; складские остатки, резервы и КИЗ не переносятся.
Дубликаты, конфликтующие ШК и действительно отсутствующие карточки остаются заблокированы.
Сопоставление по названию и автоматическая смена nmID/chrtID не добавляются.

`wb-barcode-identity.ts` индексирует ШК и выдаёт проверенный контекст только для
конкретного SKU и объекта карточки. `build-wb-barcode-identity.cjs` накладывает
изменение на проверенный runtime: `wb-catalog-sync.js`, `wb-barcode-identity.js`,
`marketplace-connections.service.js`. За пределами контекста прежний запрет
неподтверждённого изменения идентичности сохраняется. Изменения описаний записываются
в существующий аудит синхронизации с прежними и новыми значениями.

Источник: baseline `2026-10-10-marketplace-links`, sourceParityVerified=false.
Полная сборка исходников не предназначена для публикации. Этот API-выпуск не
публикует подготовленный отдельно интерфейс страхового резерва из родительского коммита.
Общие модули marketplace затрагиваются только в образе нашей WMS.

Проверки: 8 unit-сценариев, фактический classifier до/после, полный runtime sync
и настоящий SKU upsert на изолированных фикстурах; дубликаты и повторный вызов
вне проверенного контекста. API: 3303 passed / 150 skipped; web: 416 / 2;
14 обязательных FBS runtime проверок; изолированная проверка TypeScript.
Отдельная не настроенная KIZ DB integration suite исключена.

Предварительная сверка Лукина: 53 блокировки изменения описаний снимаются;
37 отсутствующих карточек не имеют совпадений ШК в текущем полном каталоге WB.
После публикации требуется повторная синхронизация и проверка остатков только
на складах нашей маршрутизации с учётом активных и страховых резервов.
