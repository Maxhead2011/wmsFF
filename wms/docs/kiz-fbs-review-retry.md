# Повторная проверка КИЗ при отборе FBS

Исправление от 30.10.2026. База: PR769, API e96334e56c84, sourceParityVerified=false.

Регресс: после принятия КИЗ reserveCompletedWildberriesStock переводит ProductMark в PACKING, при постоянных коробах очищая boxId, но не заменяет stockMovementId. Проверка ownExpectedMovement принимала это за постороннее изменение и открывала разбор; следующий вызов мог заменить OPEN новым FIRST_USE.

Изменён только common/kiz-client-review.ts. Повтор распознаётся по текущему заданию, клиенту, КИЗ, SKU, филиалу, коробу назначения и положительному нетто движений fbs-sticker-pick точного задания. Возвращённые резервы не дают разрешение. OPEN/REJECTED/USED не превращаются в первое использование. Сохранённая история открытого разбора не удаляется при пустом повторном чтении.

Предупреждение показывает подтверждённую дату (Москва) и предыдущий заказ либо заявку FBO. Если доказательств отгрузки нет, сообщение говорит о проверке привязки, а не о якобы прежней отгрузке. Подробности другого филиала скрыты.

Проверки: 3 новых RED/GREEN теста; API4042, web555, TypeScript; 30 проверок фактического runtime (4 новых + 26 сохранённых). Пропуски API155/web2; отдельная старая kiz-duplicate.integration.spec.ts требует собственной БД и исключена, как в предыдущем выпуске. Изменён 1 из 688 API-модулей; web, APK245, схема, складские записи и проданная WMS не меняются. Действует существующий WMS_KIZ_CLIENT_GUARD_ENABLED.

Артефакты выпуска: scripts/releases/kiz-fbs-retry/runtime.cjs и release.py. Ветка fix/kiz-fbs-review-retry, PR в feature/wb-print-check.
