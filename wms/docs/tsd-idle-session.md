# ТСД: вход до 15 минут бездействия

Подготовлено 06.11.2026 в `fix/tsd-idle-session` для PR в
`feature/la_panthera`. **Не опубликовано, production-флаг не включён.**

## Поведение

LOGOFF ТСД 257 запрашивает вход с `idleSession: true`. Сервер с
`WMS_TSD_IDLE_SESSION_ENABLED=true` сохраняет отдельную UserSession с дедлайном
15 минут. Нажатия, сканы и действия в диалогах продлевают вход; опрос состояния,
обновление экрана и подтверждения фоновых операций сами по себе его не продлевают.
При постоянной работе фиксированный срок JWT восемь часов больше не прерывает
такую сессию. Обычный JWT и старые приложения сохраняют прежние правила.

После 15 минут приложение блокирует запросы и предлагает войти снова. Закрытие
авторизации не удаляет журналы неподтверждённых операций и их идентификаторы.
Нужно войти тем же сотрудником и открыть прежнее задание. Уже принятая сервером
операция не становится новым сканированием. Работа офлайн не позволяет продлить
уже истёкшую серверную сессию. Перезапуск приложения не начинает новый таймер.

## Изменения и изоляция

- API: AccessTokenService, AuthGuard, TsdDeviceService/login, DTO и новый
  POST `/tsd/session/activity`; TsdIdleSessionService хранит дедлайн в существующей
  таблице UserSession. Миграция схемы не требуется. Проверяются пользователь,
  активность и принадлежность устройства; атомарное продление не оживляет отозванную
  сессию и не сокращает дедлайн из-за позднего запроса.
- Android: MainActivity, StorageBoxTransferActivity, окна TsdUi,
  WmsApiFactory и модели login; новые TsdIdleSession/TsdIdleWindow.
  Продление передаёт возраст реального действия, обычная частота — до одного раза
  в минуту, с исключением перед окончанием серверного дедлайна.
- Registry API увеличен на один. Исходный registry 111→112, runtime 108→109:
  существующее расхождение не исправлялось в этой задаче.
- Проданная WMS не развёртывается; флаг по умолчанию выключен. Ffullhab/platform
  не включают новый механизм авторизации и не отправляют opt-in.

## Публикация и откат

Перед публикацией повторно сверить актуальный сервер/APK, выполнить staging HTTP
проверку login/activity/expiry и сохранить предыдущий образ. Сначала API с флагом
только нашей WMS, затем метаданные обоих каналов. После установки на контрольном
ТСД проверить реальный скан, 15 минут простоя, повторный вход и восстановление
неподтверждённой операции. Публикация APK не означает его установку на устройства.

APK257 требует ответ login с idleTimeoutSeconds=900. Отключение серверного флага
или откат API самостоятельно лишит новые APK возможности входить. Поэтому откат
должен быть согласованным: сохранить совместимый сервер либо выпустить совместимое
Android-исправление с большей версией. Обычное обновление Android на меньшую версию
невозможно. Не представлять выключение флага как безболезненный откат.
