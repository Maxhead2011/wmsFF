# Ozon FBS: стикеры перед физической сборкой

Опубликовано 25.11.2026 через [PR1072](https://github.com/Maxhead2011/wmsFF/pull/1072) в `feature/la_panthera`. [Доказательства выпуска](releases/ozon-pre-pick-1072.json).

Регрессия №003290/003299: «Печать всех ШК» вызывала обычный `assembleFbsOrders`, который требует завершённого отбора ТСД. Рабочий порядок склада — сначала официальные стикеры, затем сборка.

Кнопка использует отдельный `POST /marketplace-connections/fbs/orders/prepare-labels`. После существующего подтверждения пользовательского действия сервер читает актуальный состав выбранных отправлений и подготавливает этикетки через Ozon. Внешний статус становится `awaiting_deliver`; фактический отбор, списание ткани, завершение ТСД и закрытие заявки в WMS при этом не выполняются. Маркируемые и многоместные отправления сохраняют отдельную проверку.

Проверяются клиент, действующий кабинет, открытая заявка и активный филиал. Все выбранные отправления проходят предварительную проверку до первой отправки. PostgreSQL advisory-lock использует опубликованные идентификаторы блокировок сборки. Повторная печать не повторяет `ship` для `awaiting_deliver`. Намерение сохраняется до сетевого запроса для восстановления после неизвестного результата.

Запись `ozon.print-preparation.v1:` содержит заявку и точный состав. Она позволяет продолжить настоящий отбор после печати, включая быструю локальную очередь и рулоны. Отменённые и доставленные отправления не возвращаются в сборку. Изменившийся состав требует проверки. Обычное подтверждение сборки сохраняет проверки фактического отбора и КИЗ.

Изоляция — существующий `WMS_FBS_UNMARKED_PAIRED_LABELS_ENABLED`. При отключённом флаге новый путь недоступен. Проданная WMS и её настройки не меняются.

Проверки: реальный прежний обработчик воспроизводит блокировку; 6 новых сценариев обработчика проходят после исправления. API 4893 passed / 199 skipped; отдельно исключён `kiz-duplicate.integration.spec.ts`, падающий при сборе и на базе без выделенной БД. Web 677 passed / 2 skipped, TypeScript web проходит. API TypeScript: те же 56 ошибок, что на нетронутом HEAD, включая устаревший локальный Prisma-клиент; новых диагностик нет. PostgreSQL-интеграция нового пути и физическая печать не проверены.
