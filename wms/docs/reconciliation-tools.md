# Очередь сверок и инструменты заявок

Опубликовано 15.10.2026 через PR620/621 от production PR618/619 (`2026-10-15-monitor-routing`).
Новая база: `2026-10-15-reconciliation-tools`. Проверены health, хеши файлов, флаги и опубликованный интерфейс.

## Область изменения

- `common/reconciliation/queue.ts`: постоянные уникальные случаи, пакетная регистрация,
  атомарная блокировка на пять минут, до 50 попыток за цикл клиента, повторы через 5 минут — 6 часов.
- `common/reconciliation/wb-background.ts`: те же существующие проверки физического
  списания WB, подтверждённой печати и остатка завершённой заявки. Изменившиеся данные
  возобновляют проверку; открытие экрана не ставит задания в очередь.
- `marketplace-connections.service.ts`: только подключение очереди под флагом.
  При выключенном флаге остаётся действующий путь. Исходный метод также приведён к
  опубликованной версии с readOnly/activeOnly; в runtime вставляется только вызов очереди.
- `operations-tools`: авторизованные чтения готовности, точного поиска и случаев сверки;
  назначение себя ответственным с аудитом. Готовность не запускает перерасчёт остатков.
- `OperationsTools.tsx`, `ClientRequestsPanel.tsx`: раскрываемая панель в заявках,
  загрузка по действию пользователя, переход в существующее онлайн-выполнение.
- Одна новая служебная таблица `WmsReconciliationCase`; количества и доказательства
  отгрузки остаются в прежних таблицах. `done-request-packing.ts` восстановлен в исходниках
  из опубликованного помощника; сам runtime-помощник не заменяется.

## Изоляция и ограничения

`WMS_RECONCILIATION_QUEUE_ENABLED` и `WMS_OPERATIONS_TOOLS_ENABLED` по умолчанию выключены.
Включаются только в образе нашей WMS. Проданная WMS, агент печати, APK и структура меню
не изменяются. Авторизация ограничивает чтения клиентом и действующим филиалом до LIMIT.
КИЗ в коробе определяется по текущему филиалу короба, а не по старому движению.

Очередь не разрешает принудительное списание или закрытие случая без доказательства.
Действующие фоновые сверки могут выполнить уже разрешённое физическое действие по
прежним правилам; это не выпуск с гарантией отсутствия обычных фоновых записей.

Готовность ФБО показывает сохранённые факты отбора, упаковки, подтверждения коробов
и передачи грузомест Ozon. Для ФБС детали доступны через существующее онлайн-выполнение;
неизвестное состояние не показывается как завершённое. Наличие начисления не означает
оплату. Доступность формирования документов не означает наличие готового документа.
Внешний API маркетплейса при просмотре этой панели не вызывается.

Точный поиск возвращает до 20 строк каждого типа, очередь внимания — первые 100 случаев.
История короба загружается отдельно (до 30 движений и заданий). Новые инструменты
не заменяют полные складские отчёты. Фоновая очередь относится к WB; отправки Ozon
продолжают использовать прежние защищённые механизмы.

## Проверки

- Регрессии лимита параметров и филиала КИЗа воспроизведены до исправления.
- 12 новых unit-тестов очереди, авторизации и существующего финализатора.
- 6 сценариев отдельной PostgreSQL: два подключения, блокировка, изменение данных,
  backoff, восстановление после сбоя, разделение клиентов и бюджет цикла.
- 7 браузерных проверок фактического графа JS: ленивые запросы, поиск, готовность,
  назначение, переход, четыре ширины экрана, смена пользователя, отсутствие опроса.
- 6 проверок кандидатного образа: DI, реальные чтения, изоляция временной таблицы,
  выключенный флаг; схема Prisma валидна.
- Общий API: 3487 успешно, 155 пропущено; включая новые проверки очереди и мониторинга WB. Старый `kiz-duplicate.integration.spec.ts` исключён
  из общего прогона: для него не задана отдельная тестовая БД.
- Web: 443 успешно, 2 пропущено. Проверки TypeScript API/web.

## Выпуск и откат

Скрипты `scripts/releases/reconciliation-tools-20261015/` используют текущие образы,
проверяют точные изменения и блокировки выпуска. Сначала применяется только новая
таблица и регистрируется миграция, затем переключаются API/web. При ошибке проверки
возвращаются прежние образы; добавленная служебная таблица сохраняется для разбора.
Физические операции не отменяются сменой образа. Повторный запуск миграции при уже
существующей таблице останавливается для проверки её состояния.

Исправление запуска миграции в PR621: NODE_PATH задан для скрипта в `/test`.
Первый запуск остановился до обращения к БД и переключения контейнеров.
Повторный запуск проверен на изолированной схеме PostgreSQL и успешно опубликован.
