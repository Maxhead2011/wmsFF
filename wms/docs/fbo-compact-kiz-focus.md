# Фокус КИЗа после ШК в компактной упаковке ФБО

Подготовлено 29.10.2026; не опубликовано. Ветка `fix/fbo-compact-kiz-focus`,
целевой PR — `feature/wb-print-check`. База — PR753 / LOGOFF ТСД241.

Пользователь сообщил о потере фокуса после ШК при упаковке ФБО Лукина.
В `FboTwoStageScreen.renderCompactPacking` поле сохраняется между обновлениями,
но фокус запрашивался только синхронно. Завершающий Enter сканера может перевести
фокус на кнопку уже после обработки ШК. Обычный экран использует защиту
`AssemblyAutoFocus`; компактный экран её пропускал.

Изменён только `renderCompactPacking`: после немедленного запроса используется
существующий помощник с отложенными запросами фокуса. Проверяется актуальность
поля, открытый экран, готовность к скану и отсутствие диалога количества.
Помощник дополнительно проверяет активность окна, видимость и доступность поля.
КИЗ не отправляется без сканирования, складская логика не меняется.
Компактный экран ограничен LOGOFF; проданные варианты не затронуты.

`FboCompactPackingScreenTest.barcodeRestoresKizFocusAfterScannerEnter` воспроизводит
ошибку до исправления и проходит после: реальный экран принимает ШК, имитируется
уход фокуса на кнопку после Enter, затем поле КИЗ возвращает фокус. Проверяются
сохранение введённого ШК, тот же экземпляр поля, пустой ввод КИЗ и отсутствие
дополнительной записи. Проверки `AssemblyAutoFocusTest` также прошли.
Код помечен `// FIX`, тест — `// TEST`.

Полные Android-проверки пройдены: по 280 тестов LOGOFF/Ffullhab/Platform,
840 всего, без ошибок и пропусков. LOGOFF release-сборка и diff check успешны.
Физическая проверка терминала после установки будущего обновления ещё не выполнена.
