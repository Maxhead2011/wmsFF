# Lamoda: полная этикетка 58 × 40 и форма переклейки

Для нашей WMS, клиент CL-000001. Источник: предоставленные Катериной
«шк Ламода 23.11.pdf» (136 разных этикеток) и «Отгрузка Ламода Логофф.xlsx»
(15 товаров, 144 единицы). ШК склада и ШК Lamoda различаются; сопоставление —
только по подтверждённой карточке того же клиента, с проверкой артикула Lamoda.

Полный шаблон содержит бренд, название, артикул Lamoda, цвет, размер, состав,
импортёра с адресом, изготовителя, страну/адрес производства, дату изготовления,
ШК, EAC и знаки ухода из образца. Это адаптация предоставленного образца,
а не автоматическая проверка требований площадки. Текст не обрезается:
если полные данные не помещаются, печать возвращает понятную ошибку.

В переклейке существующей заявки блок «Данные для переклейки Lamoda» запрашивает
четыре переменных поля: состав, изготовитель, «Сделано в», дата производства.
Размеры одной модели с одинаковыми исходными данными объединены; отличающиеся
партии показаны раздельно. Нулевые позиции исключены. Данные образца — подсказка,
пользователь подтверждает именно текущую партию. Любая правка снимает подтверждение.
Сервер повторно проверяет обязательные поля, дату и точный набор SKU внутри
транзакции сохранения переклейки. Данные сохраняются в `LamodaFboAssembly.relabelLabels[].fullLabel`.
Повторное сохранение тех же данных не создаёт дублей; новая заявка не меняет старую.
Создание заявок и резервов не изменяется. Для уже созданной №3405 проверены
15 SKU / 144 единицы, без отбора и печати; сведения взяты из предоставленного PDF.
В будущих переклейках оператор заполняет и подтверждает четыре поля перед печатью.

Переклейка использует сохранённые сведения заявки, тот же полный рендерер и прежние
проверки КИЗ/отобранной единицы/подтверждения печати. Сохранены две копии этикетки,
сканирование нового ШК и защита от повторного задания печати. До обновления созданные
заявки, в которых уже печатался прежний шаблон, продолжают прежний сценарий:
новая форма не блокирует их и не меняет старые этикетки. После начала печати
сохранённые данные нельзя менять; повторное сохранение идентичных данных допустимо.

В «Печать → SKU» доступен «Лукин · Lamoda · 58 × 40 мм». Все страницы готовятся
до отправки; тихий агент использует существующую атомарную серию и повторяемый UUID.
Через браузер — стандартный выбор принтера. Старый сетевой TSPL-путь для этого
шаблона отклоняется с просьбой выбрать агент/браузер. Данные партии задаются в
форме переклейки заявки; свободная SKU-печать использует данные исходного профиля.

Профиль `lamoda.label-profile.v1:<clientId>` импортируется проверяемым скриптом
`scripts/releases/lamoda-label/profile.cjs`; он пишет только SystemSetting и AuditLog,
не меняет товары, остатки, резервы, КИЗ или начисления. Отдельный режим
`install-3405` сохраняет сведения переклейки только существующей заявки №3405
после проверки её 15 SKU и всех количеств. Повторный импорт
того же файла идемпотентен, отличающиеся данные не перезаписываются молча.
Дата 01.10.2026 взята из исходного PDF, не является текущей датой или значением
по умолчанию для всех будущих партий. У новых моделей постоянные поля берутся
из подтверждённой карточки/SKU и профиля, четыре переменных поля нужно заполнить.

## Проверки и выпуск

- `lamoda-full-label.spec.ts`: полнота, календарная дата, scope, связь Lamoda,
  переполнение макета, снимки двух разных партий.
- `lamoda-relabel-data.spec.ts`: форма существующей заявки, сохранение без
  прихода/резерва/печати, повтор, блокировка изменений после печати и сохранение
  работоспособности старых заявок; проверка прав до чтения данных.
- `lamoda-fbo-relabel-flow.spec.ts`: КИЗ, печать и повторная отправка без дубля.
- `lamodaLabelPrint.spec.ts`, `LamodaBatchFields.spec.tsx`: правильный ШК,
  клиент, копии, отсутствие частичной отправки, группировка размеров.
- `scripts/releases/lamoda-label/runtime-test.cjs`: фактические собранные модули,
  PDF/PNG, контроллер, переклейка, повтор, отключённый флаг.
- `scripts/releases/lamoda-label/browser.cjs`: реальный опубликованный интерфейс
  с перехватом API; заполнение четырёх полей, сохранение данных переклейки,
  блокировка печати до сохранения и после правки. Создание заявок не вызывается.
- Все 136 PDF: размер 58×40, одна страница, декодирование ШК при 203 и 300 dpi;
  все монохромные PNG считываются. Физическая печать отдельно не проверялась.

Исходники и runtime пока расходятся (`sourceParityVerified=false`), поэтому выпуск
строится точным API11/web5 overlay от PR1091, не полной заменой сборки исходников.
`build.cjs` проверяет единственность всех якорей; `release.py` сверяет каждый файл,
использует блокировки и откат. Проданная WMS не обновляется, окружение не меняется.
