# КИЗ в клиентских выгрузках приёмок

Подготовлено 13.11.2026, ветка `feature/receipt-kiz-client-exports`, целевая ветка `feature/la_panthera`. Не опубликовано.

## Поведение

Существующие кнопки скачивания Excel сохраняются. При включённом `WMS_RECEIPT_KIZ_EXPORT_ENABLED=true` выгрузки по серии коробов, за период и отдельному документу прихода содержат дополнительный лист **КИЗ по товарам**:

- дата приёмки и документ;
- исходный короб, наименование, артикул / SKU клиента, размер и штрихкод товара;
- полный КИЗ отдельной строкой;
- основание связи, предупреждение о корректировках и ID движения.

Количества и итоги берутся из прежнего листа приёмки. Число строк листа КИЗ не является новым итогом приёмки. Остатки, резервы, статусы, списания и биллинг не меняются. Клиентская и складская авторизация выполняется до чтения истории КИЗ.

## Источники и ограничения

Используются ProductMark, всё ещё связанные с разрешённым движением, и принятые `receipt_scan` с точным совпадением ключа операции, клиента, короба и документа (также склада и SKU, когда они записаны в скане). Поиск истории выполняется пакетами по 500 ключей. Перемещённый товар не привязывается к приёмке по его сегодняшнему коробу.

Исторический скан явно подписан как история; текущее состояние товара может отличаться. При связанных корректировках лист предупреждает, что исторические коды не подтверждают состав после корректировки. Если доказательства не сохранились, поле КИЗ пустое и указано «КИЗ не зафиксирован»; коды не угадываются. Ручные старые операции без точной исторической связи восстановить таким способом нельзя.

ExcelJS удаляет управляющий GS из XML. Поэтому основной документ сначала формируется прежним способом, затем лист КИЗ добавляется через SheetJS с сохранением полного текста, GS и ведущих нулей штрихкода. Обратное чтение XLSX проверено тестами.

## Изоляция и действующий сервер

Флаг по умолчанию выключен, проданная WMS не меняется. Web/API маршруты и права скачивания остаются прежними. При публикации включать флаг только нашей WMS.

Проверенный действующий runtime отличается от исходников: имеет восстановленные приёмки `receipt-file-recovery` и клиентский сводный формат. Скрипт `scripts/releases/receipt-kiz-20261113/overlay.cjs` сохраняет их: восстановленные приёмки уже содержат КИЗ и остаются без изменений, в остальные выгрузки добавляется лист. Обновляются ровно три API-модуля. Полную исходную сборку вместо runtime публиковать нельзя; `sourceParityVerified=false`.

Проверенная база API: `sha256:c4e26f46b38f01e6e92c2608f89933feb3856cd8b2b3f9c221fe111283325440`. Перед публикацией обязательно повторно сверить базу и состав кандидата. Подготовленный кандидат не опубликован и флаг на сервере не включён.
