# Статистика обработки заказов

Раздел «Склад и операции → Статистика», workspace `operations-statistics`.

## Контракт показателя

- Единица учёта: один связанный с заявкой WMS заказ/отправление, ключ — маркетплейс, подключение, номер. Не количество вещей и не количество повторных сборок.
- Начало: WB `createdAt`; Ozon `in_process_at` (дата поступления отправления в обработку, не гарантированная дата оформления покупателем).
- Конец: электронная передача в доставку. WB — `FbsSupplyPlan.sentToWbAt` с точным совпадением `orderIds`; Ozon — доступное в исходных данных `delivering_date`.
- Дата завершения сборки, печати этикетки, загрузки заказа в WMS и плановая отгрузка не заменяют отсутствующие даты.
- Период определяется начальной датой, календарные дни включительно, Москва (UTC+3), максимум 93 дня.
- Интервалы: [0,14), [14,18), [18,24), [24,48), [48,+∞) часов. Процент = число заказов зоны / число отгруженных заказов с достоверной длительностью. Округление до десятых.
- Отменённые заказы исключены из зон; активные без передачи показываются в работе, в том числе 24+ часов. Противоречивые даты и завершённые заказы без даты передачи — «Нет данных».
- Заказы без начальной даты нельзя отнести к периоду. Их отдельный счётчик охватывает всю доступную историю выбранных клиентов/филиалов, а не только период.
- Филиал берётся из заявки WMS; внутри него — склады продавца, с разделением клиентских кабинетов. Старые записи могут иметь неизвестный склад продавца.

## История и обновление

Новые nullable-поля `FbsOrderRequestLink` заполняются существующей синхронизацией заказов из исходных данных маркетплейса. Отсутствующие поля не стирают ранее сохранённые даты. Для исторической даты WB используется подходящее событие `FbsStockMonitorEvent` типа SALE, если оно есть. Полнота старых дат не гарантируется и отображается явно.

Таблица перечитывает WMS раз в минуту при видимой вкладке; это не принудительная синхронизация WB/Ozon. Показывается время расчёта и самая поздняя синхронизация среди включённых заказов — не гарантия свежести всех кабинетов.

## Доступ и выпуск

Только сотрудники с `stock:read`; CLIENT/demo запрещены. Применяется область клиентов и филиалов пользователя. API отчёта только читает данные, не меняет остатки, сборку и статусы доставки.

Перед запуском новой версии API применить миграцию `20260912000000_order_processing_statistics` и сгенерировать Prisma Client. Миграция добавляет четыре nullable-поля без изменения старых записей. Проданное окружение не обновлять. В текущей локальной работе production-миграция и развёртывание не выполнялись.

Проверки: тесты границ интервалов, группировки, процентов, пагинации, дат и областей доступа; тесты таблицы и навигации; полный API/web Vitest, TypeScript и production-сборка.
