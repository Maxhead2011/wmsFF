# Черновик по сданным заявкам

Подготовлено в `feature/billing-done-requests-20261003`, база нашей WMS —
`publish/feature/wb-print-check` (`081dbc30`). Опубликовано PR463 / 03.10.2026; см. [паспорт](current-production.md).

В «Биллинг → Счета» появляется кнопка «Создать счёт по сданным заявкам».
Выбор клиента необязателен: при массовом формировании каждый клиент получает
свой единый черновик в активном филиале. В отличие от прежней кнопки
«Сформировать за период», услуги не делятся на отдельные счета по категориям.
ИП Лукин автоматически не исключается.

Период — **дата сдачи**, как подтвердил Константин: последняя запись
`ClientRequestEvent` с `STATUS_CHANGED`, `statusTo=DONE`, при текущем статусе
заявки `DONE`. Границы включены, часовой пояс Europe/Moscow (UTC+3).
Дата редактирования заявки и даты выполненных услуг не заменяют дату сдачи.
Если событие отсутствует, заявка показана в исключениях без предположения о дате.
Новые/упакованные/отменённые заявки и другой филиал не включаются.

Суммируются утверждённые положительные начисления, связанные с заявками через
`requestId`. Даты в новом окне изначально пустые: оператор выбирает обе границы. Все виды услуг
включаются вместе; оригинальные даты услуг, тарифы и суммы сохраняются.
Цена за единицу не пересчитывается из общей суммы и округлённого тарифа.
Начисления, включённые в действующий счёт, повторно не добавляются.
По уточнению Константина сохраняются **все существующие счета, включая черновики**: они не объединяются, не отменяются и не пересчитываются. Если действующий счёт охватывает заявку, она исключается даже при другой дате услуги. Если период счёта пересекает выбранный период клиента/филиала, этот клиент исключается из нового формирования с номером существующего счёта. Отменённые счета не закрывают период. Счета другого клиента или филиала не блокируют расчёт.

**Ограничение расчёта:** кнопка суммирует сохранённые расчёты и не восстанавливает
пропущенные начисления из движений склада или заказов маркетплейсов. Заявки без
начислений/сохранённого расчёта, неутверждённые суммы, нулевые/неподтверждённые
тарифы и спорные счета показаны отдельно. Наличие одного начисления не доказывает
полноту всех услуг заявки. Известные проблемы восстановления FBS из аудита
03.10 не исправляются этим выпуском. Перед подтверждением нужно проверить
исключения; складские остатки, статусы заявок и оплаты этот режим не меняет.

Предварительный расчёт работает в `RepeatableRead` / `READ ONLY`. Подтверждение
привязано к SHA-256 исходных заявок, событий сдачи, начислений и счетов.
Создание использует общий финансовый advisory lock и блокировки исходных строк;
изменения после предварительного расчёта отклоняются. Повторная отправка того же
подтверждения возвращает сохранённый результат с повторной проверкой прав.
Новый предварительный расчёт после создания показывает существующий счёт в исключениях и не создаёт его повторно.
Ограничения объёма дают явную ошибку, не усечённые финансовые суммы.

Серверный флаг `WMS_BILLING_DONE_REQUESTS_ENABLED=true` включать **только в нашей
WMS**. Без флага новый режим запрещён, кнопка скрыта. Предыдущий режим по датам
услуг не меняется. Миграций нет, проданная WMS не включается. Изменяемые общие
модули: `billing-period.service.ts`, DTO, контроллер, `writePeriodDraft` (только
опциональный текст с номерами реально включённых заявок), окно биллинга/API-клиент.
В описании API учтён дополнительный маршрут проверки доступности кнопки.

Тесты: `billing-done-requests.spec.ts` — отбор/границы, объединение, неизменность
снимков, доступ/флаг, исключения, устаревший расчёт, повтор подтверждения и лимит.
`BillingPeriodGenerationDialog.spec.tsx` — передача режима, видимость дат сдачи,
заявки и подтверждение; прежние сценарии периода сохранены.
Новые проверки падают на прежнем сервисе/окне и проходят с изменениями.
