# Физически найденный КИЗ при прежней продаже WB

Для нашей WMS флаг `WMS_KIZ_SOLD_PHYSICAL_REUSE_ENABLED` разрешает ADMIN/OWNER/SUPER_ADMIN подтвердить использование конкретной доступной единицы из действующего обращения сборщика. Только явное решение REUSE, подтверждение физического наличия и причина. Автоматического допуска по факту AVAILABLE нет.

Случай ограничен свежими подтверждёнными WB sold/complete с данным КИЗ; неизвестная или противоречивая история и подтверждённое погашение не допускаются. Проверяются клиент, филиал, SKU, короб, уникальность марки, доступный баланс, отсутствие активного FBO и другого разрешения. Незавершённые прежние FBS привязки не освобождаются. Полный снимок закрытой прежней привязки сохраняется в AuditLog перед освобождением её уникального текущего слота; ShippedKizHistory и заказы WB не переписываются.

Разрешение связано с контекстом задания, версией физической марки и состоянием доказательств WB. Изменение марки, заказа, доказательств или выключение флага отзывает допуск. UNIT/FOUND и независимая переклейка не расширены этим изменением. Проданная WMS сохраняет прежнее поведение.

Исходник: `apps/api/src/common/kiz-physical-reuse.ts`. Встроен точечным `scripts/kiz-physical-reuse-runtime.cjs` в текущий `common/kiz-review-queue.js`; полная замена API запрещена при sourceParityVerified=false. Карточка получает `physicalReuseAllowed` от сервера. Web overlay сохраняет текущий граф и единственный React.

Проверки: регрессия manager → approval → повторный scan до исправления падала. После исправления 24 runtime-теста; 33 связанных FBS runtime-теста; 3417 API, 427 web. 155/2 теста пропущены; специализированные KIZ DB suites исключены из общего запуска. Отдельно реальный PostgreSQL: решение по обращению 6028038996 и повторный scan в транзакции с обязательным откатом, состояние после отката совпало. Браузер проверяет готовый граф, причину, подтверждение и выключенную capability. Web TypeScript проверяется отдельно.

Публикация: отдельный PR `fix/kiz-physical-presence-override` → `feature/wb-print-check`, API/web поверх baseline 2026-10-13-ozon-picking-230. Флаг только в образе нашей WMS. APK и таблицы остатков не меняются. Разрешение конкретному обращению остаётся отдельным действием менеджера.
