# Группы магазинов: выпуск настройки без автоматической отправки

26.10.2026 пользователь повторно разрешил публикацию после явного сообщения о
неготовности отправки. В выпуск входит только редактор групп и назначений;
публикация остатков на маркетплейсах в этом выпуске не включается.

Клиент хранит общий физический остаток. Конкретный SKU (включая размер и цвет)
назначается ровно одной группе магазинов WB/Ozon. Группа может состоять из первой
пары, второй пары или другого набора кабинетов одного клиента и физического склада.

## Подготовленные модули

- `multishop-stock-plan.ts`: проверка групп/назначений, целочисленное распределение,
  приоритет малого остатка, план уменьшений перед увеличениями.
- `multishop-stock-groups.service.ts` и `.controller.ts`: настройки в SystemSetting,
  блокировка редактирования, UUID версии, аудит, проверка клиентских прав и товаров,
  поиск товаров с пагинацией. Секреты кабинетов не возвращаются.
- `multishop-stock-publication.ts`: алгоритм одного шага через интерфейс операций.
  Это НЕ подключённая постоянная очередь: хранилище, блокировки и транспорт ещё
  должны быть реализованы. Подтверждение запроса не считается проверкой остатка.
- `MultishopStockGroupsView.tsx` / `multishop-stock-groups.css`: редактор групп и
  массовое назначение товаров. Подключён через `MultishopStockGroupsEntry` к
  пункту «Между магазинами»; старый редактор пары сохранён в details.

Флаг `WMS_MULTISHOP_STOCK_ENABLED` выключен по умолчанию и включается только в
образе нашей ВМС. Контроллер и сервис зарегистрированы, worker отправки отсутствует.
Изменения не затрагивают проданную ВМС. Сохранение черновика не активирует управление
остатками и не меняет работу существующих отправителей WB/Ozon.

## Оставшаяся работа для автоматической отправки (не входит в текущий выпуск)

1. Общий расчёт доступного количества должен учитывать WB, многотоварные заказы
   Ozon и заявки FBO, исключая двойное резервирование. Существующая функция
   `wbReservationQuantities` явно выбирает задания marketplace=WILDBERRIES;
   её нельзя объявлять достаточной для нового режима без проверки состава Ozon.
2. Подтверждённые соответствия карточек должны работать по каждому кабинету.
   Read-only каталог не равнозначен operational product links; нельзя автоматически
   включать прежние связи для всех клиентов.
3. Постоянная очередь, наблюдения старых и новых назначений, защита от всех прежних
   отправителей WB, проверенный транспорт Ozon, таймауты, перезапуски и актуальность
   бюджета перед внешней записью.
4. Подключение экрана и API, предпросмотр по рабочему расчёту, интеграционные тесты
   очереди в отдельной PostgreSQL, проверка собранного интерфейса.
5. Повторная сверка production, проверенный runtime delta, PR и выпуск. Полную
   исходную сборку использовать нельзя: sourceParityVerified=false.
