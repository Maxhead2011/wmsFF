# Автообновление скрытых окон ФБС

Продолжение пункта 3 аудита эффективности: остановка ненужных чтений сохранённого
окна. В опубликованном графе четыре интервала и два коротких повтора проверяли
только видимость вкладки браузера, но не окна внутри ВМС.

`FbsPanel.tsx` привязывает четыре интервала к корневому элементу через существующий
`startVisiblePolling`. Исходный путь сохраняется при выключенном
`VITE_MENU_READS_ENABLED`. Скрытие через hidden, display:none и класс свёрнутого
окна останавливает опрос; раскрытие вызывает обновление. Первоначальное чтение,
ручные действия, сроки интервалов и обработка уже отправленных запросов сохранены.

Runtime изменён точечно: четыре интервала и два уже существующих коротких повтора
синхронизации. Последних нет в старом исходном фрагменте; они сохранены, добавлена
проверка видимости. Полная сборка FbsPanel не переносится. Общий helper не меняется.
Только наша веб-версия; API, данные, APK233, печатный агент и проданная ВМС не меняются.

Проверки: регрессия на фактическом старом графе, пять браузерных сценариев кандидата,
два новых теста, web445/2 skipped, API3487/155 skipped (отдельный KIZ DB suite исключён),
TypeScript web, baseline verify. Семь падений старого hook-harness после добавления
ref устранены сохранением прежнего порядка существующих hooks; общие тесты повторены.

Это устранение лишних обращений скрытого окна, а не измеренное ускорение сканирования.
Кандидат сохраняет остальные файлы текущего образа; 33 файла графа меняются из-за
cache-safe переименования зависимостей. Публикация проверяет PR, свежие image ID,
хеши, health, неизменность API/APK/окружения и остальных контейнеров, с откатом web.
