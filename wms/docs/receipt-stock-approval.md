# Согласование приёмки и доступ в остатках

Новые приёмки Лукина в ФФ Москва требуют подтверждения клиента или администратора.
Клиент видит собственные приёмки, скачивает исходный файл и подтверждает сверку.
Имя и время берутся из authenticated user и сервера, сохраняются в SystemSetting и AuditLog.
Отключение разрешено только ADMIN/OWNER и блокируется при активном резерве/отборе.
ФБС/ФБО направления независимы; старое исключение для защищённых заказов не обходит согласование.

Pending-короба исключены из остатков/выгрузки, публикации WB, выбора ФБО/ФБС,
повторной сборки и прямого списания. Физические StockBalance/StockMovement и хранение не меняются.
Переезд товара из pending-короба запрещён до согласования, чтобы не обойти ограничение.

Включение: WMS_RECEIPT_APPROVAL_ENABLED=true и receipt.approval.scope.v1:<client>:<warehouse>.
Снимок grandfatheredReceiptIds сохраняет доступность старых приёмок. Идентификатор
приёмки остаётся прежним: клиент, филиал, год и серия коробов. Общие модули затронуты,
но новая проверка выключена без флага и конфигурации; sold WMS не публикуется.
Схема БД не меняется. Подтверждение берёт эксклюзивную блокировку scope,
отбор — разделяемую; версия scope меняется при сохранении для обнаружения старых снимков.

Проверки: API suite, web suite, TypeScript; actual runtime tests; реальный браузер:
preview/cancel/confirm/подпись/запрет клиентского отключения. Текущая БД: проверка
pending→approved с обязательным rollback, неизменность физического количества.
Изолированный kiz-duplicate.integration не выполняется без отдельной тестовой БД.

Публикация: отдельный PR в feature/wb-print-check; точечный overlay свежего runtime,
sourceParityVerified=false. release_baseline check-candidate ограничен восемью JS-модулями.
Web заменяет только ReceiptDirectionsPanel и переименовывает достижимый JS-граф.
APK218 и приложение учёта рабочего времени сохраняются.

Скрипты выпуска в scripts/releases/receipt-approval-20261007 архивируют проверенную
процедуру; исполняются из подготовленного scratch-каталога с before.json и baseline.
Откат образов: logoff-api:before-receipt-approval-20261007 и аналогичный web.
После появления новых несогласованных приёмок откат на старый API отключит фильтр:
его нельзя применять без ограничения отбора до восстановления согласования.
