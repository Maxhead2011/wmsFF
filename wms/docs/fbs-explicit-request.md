# FBS: ручной выбор следующей заявки

Подготовлено 29.10.2026, ветка `fix/fbs-manual-request-scope`; ещё не опубликовано.
База: опубликованный PR765 / снимок PR766 `2026-10-29-kiz-client-guard`.

## Подтверждённый сбой

Журнал HTTP и назначения Элеоноры на одном ТСД подтвердили последовательность:
WB Королёв №2545 завершён в 20:13:11 МСК, Ozon Баландин №2537 назначен
в 20:13:13, после его завершения WB Лукин №2535 назначен в 20:13:44.
Первый запрос содержал выбранный `requestId`, два последующих — пустое значение.
Записи получены только чтением; сборки, резервы, остатки и КИЗ не исправлялись.

В Android восстановление сохранённой операции восстанавливало `fbsAssembly`,
но теряло `selectedFbsRequestId`. Автоматический переход после завершения заказа
отправлял пустой номер. Сервер разрешал выдачу из общей очереди WB и Ozon.
Этот путь воспроизведён тестами; состояние памяти конкретного ТСД не считывалось.

## Поведение после исправления

Сборщик выбирает заявку, собирает её товары, видит завершение отбора и сам
выходит к списку, чтобы выбрать другую заявку. Переход между товарами внутри
выбранной заявки сохраняется. Автоматический выбор следующей заявки запрещён.

- `MainActivity.restorePendingFbsAssembly`: восстанавливает заявку и маркетплейс
  вместе с сохранённой операцией текущего сотрудника; вызывается при показе и повторе.
- `MainActivity.loadNextFbsAssembly`: при потерянном выборе открывает список,
  не отправляя запрос общей очереди. Обычный экран завершения не меняется.
- `MarketplaceConnectionsService.getNextFbsTsdAssemblyUnlocked`: с флагом
  `WMS_FBS_EXPLICIT_REQUEST_ENABLED=true` пустой номер не назначает новые задания.
  Уже назначенный этому сотруднику и устройству заказ можно продолжить.
  Явно выбранные заявки сохраняют проверку доступа и блокировку чужой незавершённой сборки.

Общие модули затронуты, но Android-изменение ограничено LOGOFF, серверное —
новым флагом, выключенным по умолчанию. Проданную WMS и её настройки не менять.
APK245 `0.1.245-fbs-request-scope` сохраняет изменения приёмки244 и озвучку243.
Миграций и корректировок рабочих данных нет.

Новые тесты: `apps/api/test/fbs-explicit-request.spec.ts` и
`apps/android-tsd/app/src/test/java/pro/logoff/wms/tsd/FbsRequestScopeActivityTest.java`.
До исправления сервер: 3 ошибки / 7 успешных проверок; Android: 3 ошибки / 1 успешная.
Серверный тест проверяет реальную выдачу заданий разных клиентов и маркетплейсов,
повтор без выбора, продолжение начатой работы, завершённую выбранную заявку,
явный выбор, ограничения доступа и сохранение прежнего поведения без флага.
Android-тесты исполняют настоящий Activity с очередью фоновых задач без сетевых вызовов.

Результаты: API **4028 успешно / 155 пропущено**, веб **555 успешно / 2 пропущено**,
Android **299 на каждый из трёх вариантов / 897 всего**, без ошибок и пропусков.
