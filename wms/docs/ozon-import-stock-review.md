# Проверка остатков при создании ФБО Ozon

Опубликовано 30.10.2026 через PR776 в `feature/wb-print-check`. Baseline `2026-10-30-ozon-import-stock`; точные live image ID и хеши сохранены в манифесте. Публичный браузер повторно прошёл 10 сценариев с синтетическими API, health и хеши опубликованных файлов проверены. Схема, APK245, окружение и остальные контейнеры сохранены.

После чтения Excel либо состава по ссылкам Ozon проверяется общий спрос по SKU во всех направлениях. Используется существующий `/client-requests/availability-preview`, как при создании WB: выбранный клиент и филиал, свободный остаток после резервов, отдельно принятый неразмещённый товар. Непринятый ожидаемый приход не считается остатком. Ошибка проверки не трактуется как нулевой остаток и не оставляет кнопок со старым результатом.

В таблице: товар/ШК, нужно, на складе, в резервах, доступно, принято/не размещено, не хватает. Смена клиента, филиала, файла или ссылок сбрасывает предыдущий результат. Повторяющийся товар суммируется по всем направлениям, не получает один и тот же остаток несколько раз.

## Две операции

- **Сформировать как есть** сохраняет весь исходный состав, включая дефицит. Это осознанный заказ под будущий приход. Само создание не отправляет изменения количества в Ozon.
- **Скорректировать по фактическим остаткам** сохраняет одну исходную заявку WMS и открывает существующий механизм корректировки. Сначала новый расчёт и распределение по направлениям, затем явное подтверждение изменения WMS и Ozon. Для файла без внешней привязки здесь же требуется выбрать кабинет, добавить ссылку и сохранить соответствия направлений. Созданная заявка остаётся доступна при ошибке или закрытии экрана; повторно создавать её не нужно.

Перед отправкой применяется существующая серверная проверка актуальных остатков/резервов, состава, упаковки, грузомест и изменяемости поставки. Локальные количества меняются только после подтверждённого результата Ozon. UNKNOWN не приводит к повторной отправке. Пустые направления не отменяются автоматически: сохраняется существующее ограничение корректировки.

## Область изменения

- `OzonCustomerImport.tsx`, `OzonLinkImport.tsx`: чтение состава → проверка → выбор действия, защита от устаревших ответов/двойного нажатия.
- `OzonImportStockReview.tsx`: агрегация SKU, общий endpoint доступности, таблица и действия.
- `OzonImportCorrection.tsx`: созданная заявка, привязка файла, существующая корректировка.
- `OzonStockAdjustment.tsx`: необязательный `autoPreview`, только чтение до подтверждения.
- `OzonAssemblySupply.tsx`: необязательные `onBindingReady`/`bindingOnly`; обычная работа с грузоместами сохранена.
- `api.ts`: тип имён товаров в существующем ответе preview.
- `OzonStockAdjustmentService.load`, `OzonAssemblySupplyService.load`: CLIENT использует филиал собственной scoped-заявки без внутреннего переключателя; чужие/read-only клиенты запрещены. Требования активного филиала сотрудников сохранены.
- `OzonStockAdjustmentController`: клиенту достаточно `client-requests:write`; сервер сохраняет обязательное `stock:write`/`system:admin` для внутренних сотрудников.

Контур по-прежнему ограничен `WMS_OZON_FBO_IMPORT_ENABLED`. Новые флаги, схема, данные, остатки, реальные поставки маркетплейса и APK не меняются. Проданная WMS не публикуется. Общий калькулятор WB и отправка корректировки Ozon не переписываются.

## Проверка

- Новый API-тест воспроизвёл отказ клиента без activeWarehouseId до исправления; после исправления проверяет собственный доступ и запреты чужого/read-only/другого филиала/непривилегированного сотрудника.
- Unit-тесты UI: суммирование нескольких направлений, исключение собственной существующей заявки, полный заказ при дефиците, пояснение привязки файла.
- Source browser: 8 сценариев, включая ошибку чтения остатков и UNKNOWN после отправки.
- Candidate browser на опубликованном графе модулей: 10 сценариев, оба способа, три ширины, явная отправка, привязка файла. Только синтетические API.
- Actual-container runtime: 11 проверок доступа, метаданных контроллера и загрузки AppModule.
- Общие API: 4072 passed / 151 skipped, 396 файлов passed / 12 skipped; отдельные `kiz*.integration.spec.ts` исключены без выделенной БД. Web: 560 passed / 2 skipped, 130 файлов passed / 1 skipped. TypeScript API/web и 8 baseline-тестов прошли.

Точечный runtime: 3 API-файла, 2 web-файла (`index.html` и новый Ozon-модуль). Остальная часть Ozon-модуля до/после заменяемого блока проверена побайтово. База PR773: `2026-10-30-found-unit`; перед публикацией повторная проверка live image ID и точного состава overlay. `sourceParityVerified=false` сохраняется.
