# Перенос WB через браузер

Пилотное расширение Manifest V3 для нашей ВМС https://wms.logoff.pro.
Установка: [INSTALL.txt](INSTALL.txt). Код не требует npm-зависимостей.

## Протокол

Официальный frontend WB FBS v1.7.14 использует `PATCH` к **исходной** поставке:
`https://marketplace.wildberries.ru/ns/marketplace-app/marketplace-remote-wh/api/v3/portal/supplies/{source}/orders/transfer`,
тело `{orderIds: number[], newSupply: string}`. Ответ содержит
`transferredOrders: [{orderId, oldStickerId, newStickerId}]`.

Источник: [официальная сборка WB, chunk 558](https://static-basket-02.wbbasket.ru/vol20/marketplace-fbs-orders-front/v1.7.14/558.chunk.1e403d80297b869ef2b2.js).
Клиент RestRequest: [официальная сборка root-monorepo v1.113.3](https://static-basket-02.wbbasket.ru/vol20/root-monorepo/latest/main.1b45f8149289a03d.js).
Адаптер закреплён за проверенной сборкой: при изменении hash выполнение блокируется.
Код WB не поставляется внутри расширения и не скачивается расширением.

## Границы и восстановление

- Сервер ВМС проверяет доступ к клиенту и филиалу, неизменность физической сборки,
  `complete/waiting/isTransferable=true`, исходную поставку и прежние стикеры.
- Целевая поставка создаётся существующим журналируемым публичным API.
- PREPARE читает обе уникальные поставки в текущем кабинете WB; целевая должна быть пустой и иметь ожидаемое название.
- `/fbs/reshipment/portal/start` выдаёт команду единожды, сохранив `PORTAL_STARTED` до ответа.
  Срок отправки команды 120 секунд. Серверные lease и fingerprint остаются действующими.
- Одноразовый ticket расширения связан с вкладкой и документом ВМС, вкладкой WB и точным составом команды.
- Расширение сохраняет намерение в local storage **до** вызова WB. Запрос внутри вкладки
  использует существующий SDK и его авторизацию; одноразовая обёртка транспорта также
  блокирует повтор из interceptor/MFA самого кабинета.
- Сервер не доверяет успеху или номерам стикеров из браузера: сверяет точный состав новой
  поставки, отсутствие заказов в старой, `confirm/waiting` и смену каждого стикера по публичному API.
- При потере ответа — только сверка. Автоматической переотправки ранее выданной команды нет.
  Отклонённая/истёкшая команда требует разбора операции администратором.
- Изменение физической сборки останавливает локальное завершение, без отката операции WB.
  Не выполняйте сборку/отгрузку или ручной перенос параллельно незавершённой операции.
- Журнал показывает старые/новые стикеры и скачивает актуальные через существующий PDF API.
  Устаревшие кэши статусов, стикеров и fallback сбрасываются/обновляются после подтверждения.
- Расширение имеет только `scripting`, `storage` и доступ к странице продавца WB;
  content script доступен только верхней странице нашей ВМС. Общего proxy, доступа ко всем сайтам,
  cookies permission, чтения API-ключей и передачи браузерных credentials в ВМС нет.

## Включение и ветки

PR: `fix/wb-delivery-transfer` → `feature/billing-period-register-20260910`.
Только на нашей ВМС после проверки расширения включить `WMS_WB_PORTAL_TRANSFER_ENABLED=true`.
Также должны быть включены существующие `WMS_FBS_RESHIPMENT_ENABLED` и
`WMS_FBS_NO_STOCK_TRANSFER_ENABLED`. На проданной ВМС новая настройка остаётся false/не задана.
Миграций БД нет; поля расширения хранятся в существующем JSON-снимке журнала.
Новые операции используют прежний путь при выключенной настройке. Незавершённый перенос
через браузер при отключении настройки не переключается на старый PATCH.

## Проверки

Из корня репозитория:

```powershell
pnpm --dir wms/apps/api test
pnpm --dir wms/apps/web test
pnpm --dir wms/apps/api build
pnpm --dir wms/apps/web build
node --test wms/extensions/wb-transfer/test/*.test.js
python wms/extensions/wb-transfer/package.py
```

Для изолированного теста настоящего расширения укажите `WMS_PLAYWRIGHT_MODULE`
(путь к Playwright), `WMS_BROWSER_EXECUTABLE` и `WMS_BROWSER_TEST_DIR` (папку
внутри рабочего пространства), затем `node wms/extensions/wb-transfer/test/browser.cjs`.
Тест создаёт отдельный профиль и подменяет весь HTTP-трафик; реальный кабинет не используется.

Перед постоянным распространением потребуется публикация в магазине расширений.
[Яндекс может отключать внешние расширения после перезапуска](https://yandex.ru/support/browser/ru/security/check-extensions).
Работа с реальной сессией продавца и перенос реального нового заказа требуют проверки
в установленном расширении; автоматические тесты не являются такой проверкой.
