# WMSFF2207: исключение завершённых WB-заказов из сборки

## Область изменений

- `wms/apps/api/src/common/fbs-terminal-queue.ts`: единая opt-in политика статусов.
- `client-requests.service.ts`, `list`: счётчики только действующей сборки и сохранённых завершённых фактов.
- `marketplace-connections.service.ts`: маршруты, выбор заявок ТСД, загрузка очереди и проверка пяти операций уже открытого задания.
- `tsd-assembly.service.ts`, `loadFbsAssemblyFacts`: оставшееся количество из действующих заказов, отдельная история исключённых заказов, без повторной упаковки или замены КИЗ для них.
- Web `ClientRequestsPanel.tsx`, `FbsExcludedOrders.tsx`, `lib/api.ts`: сворачиваемый блок «Не требуется собирать», без действий повторной сборки.
- Тесты: `fbs-terminal-queue.spec.ts`, `fbs-terminal-queue.service.spec.ts`, `FbsExcludedOrders.test.tsx`.

## Границы безопасности

Новый флаг `WMS_FBS_TERMINAL_QUEUE_FILTER_ENABLED=true` включается только для нашей ВМС после согласованного релиза. По умолчанию выключен. Семантика WB не применяется к Ozon. APK не меняются.

Не изменяются StockBalance, StockMovement, ProductMark, история попыток, печати, КИЗ и физической отгрузки. Отмена WB не возвращает товар на склад. История RETURN_REQUIRED сохраняется: отсутствие заказа в сборке не означает автоматического решения его бухгалтерского/складского конфликта.

Используются сохранённые статусы последней синхронизации WB. Сам фильтр не выполняет полную свежую сверку WB; перед включением нужно завершить сверку штатным механизмом. Неизвестный статус не означает отмену. `complete/waiting` оставлен для явно разрешённой аварийной досборки.

Открытое задание с физическими сканами не сбрасывается автоматически: операции сборки блокируются с объяснением, отложить/разобрать товар должен сотрудник/менеджер.

## Проверка и публикация

Регрессионные тесты воспроизвели ошибки до исправления: старые количества, маршруты, не начатый отменённый заказ, уже открытое терминальное задание. Новые тесты проверяют также сохранение сканов, отсутствие складских записей и выключенный флаг.

Итог: API 871/871 (`vitest run --maxWorkers=2 --minWorkers=1`), Web 36/36, API/Web `tsc --noEmit`, Web `vite build` — успешно. В первом высокопараллельном прогоне один существующий PDF-тест превысил 5 секунд; отдельно и в повторном полном прогоне прошёл. Vite сообщил о крупных чанках и трёх существующих ресурсах, разрешаемых при запуске; эти ресурсы не изменялись. Визуальная проверка живого сервера не выполнена: исправление ещё не развёрнуто.

Ветка `fix/fbs-terminal-orders-queue`, создана от текущей рабочей ветки (347fa54). Предлагаемая база PR: действующая интеграционная ветка `fix/fbs-box-scan-route-consistency`. PR и развёртывание требуют подтверждения. Удалённая база уже продвинулась: не развёртывать весь старый worktree поверх сервера и не разрешать возможные конфликты автоматически.

Откат read-side поведения: выключить новый флаг. Миграций и отката складских данных нет. Сам код ещё не опубликован на рабочем сервере.
